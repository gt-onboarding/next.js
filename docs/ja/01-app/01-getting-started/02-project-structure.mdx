### ネストされたルート

フォルダはURLセグメントを定義します。フォルダをネストするとセグメントもネストされます。任意の階層のレイアウトは、その子セグメントをラップします。`page`または`route`ファイルが存在する場合、そのルートは公開されます。

| パス                        | URL パターン    | 備考                                           |
| --------------------------- | --------------- | ---------------------------------------------- |
| `app/layout.tsx`            | —               | ルートレイアウトはすべてのルートに適用されます |
| `app/blog/layout.tsx`       | —               | `/blog` 以下のルートをラップする               |
| `app/page.tsx`              | `/`             | 公開ルート                                     |
| `app/blog/page.tsx`         | `/blog`         | 公開ルート                                     |
| `app/blog/authors/page.tsx` | `/blog/authors` | 公開ルート                                     |

### 動的ルート

角括弧を使ってセグメントをパラメータ化します。単一のパラメータには `[segment]`、キャッチオールには `[...segment]`、オプションのキャッチオールには `[[...segment]]` を使用します。値には [`params`](/docs/app/api-reference/file-conventions/page#params-optional) prop 経由でアクセスします。

| パス                            | URL パターン                                                         |
| ------------------------------- | -------------------------------------------------------------------- |
| `app/blog/[slug]/page.tsx`      | `/blog/my-first-post`                                                |
| `app/shop/[...slug]/page.tsx`   | `/shop/clothing`, `/shop/clothing/shirts`                            |
| `app/docs/[[...slug]]/page.tsx` | `/docs`, `/docs/layouts-and-pages`, `/docs/api-reference/use-router` |

### ルートグループとプライベートフォルダ

ルートグループ [`(group)`](/docs/app/api-reference/file-conventions/route-groups#convention) を使用してURLを変更せずにコードを整理し、プライベートフォルダ [`_folder`](#private-folders) を使用してルーティング対象外のファイルをまとめて配置できます。

| パス                            | URL パターン | 備考                                                                |
| ------------------------------- | ------------ | ------------------------------------------------------------------- |
| `app/(marketing)/page.tsx`      | `/`          | グループは URL には現れない                                         |
| `app/(shop)/cart/page.tsx`      | `/cart`      | `(shop)` グループ内でレイアウトを共有                               |
| `app/blog/_components/Post.tsx` | —            | ルーティング対象外。UI 専用ユーティリティを配置するための安全な場所 |
| `app/blog/_lib/data.ts`         | —            | ルーティング対象外。ユーティリティを配置するための安全な場所        |

### 並列ルートとインターセプトルート

これらの機能は、スロットベースのレイアウトやモーダルルーティングなど、特定のUIパターン向けに用意されています。

`@slot` は親レイアウトによってレンダリングされる名前付きスロットに使用します。インターセプトパターンを使用すると、URLを変更せずに現在のレイアウト内で別のルートをレンダリングできます。たとえば、リスト上にモーダルとして詳細ビューを表示する場合などに使用します。

| パターン（ドキュメント）                                                                    | 概要                                   | 典型的な利用例                             |
| ------------------------------------------------------------------------------------------- | -------------------------------------- | ------------------------------------------ |
| [`@folder`](/docs/app/api-reference/file-conventions/parallel-routes#slots)                 | 名前付きスロット                       | サイドバーとメインコンテンツ               |
| [`(.)folder`](/docs/app/api-reference/file-conventions/intercepting-routes#convention)      | 同階層のルートをインターセプトする     | モーダル内で同階層のルートをプレビューする |
| [`(..)folder`](/docs/app/api-reference/file-conventions/intercepting-routes#convention)     | 親ルートをインターセプトする           | 親の子ルートをオーバーレイとして開く       |
| [`(..)(..)folder`](/docs/app/api-reference/file-conventions/intercepting-routes#convention) | 2階層上のルートをインターセプトする    | より深くネストされたオーバーレイを表示する |
| [`(...)folder`](/docs/app/api-reference/file-conventions/intercepting-routes#convention)    | ルート（最上位）からインターセプトする | 現在のビューに任意のルートを表示する       |

  ## プロジェクトの構成

Next.js はプロジェクトファイルの整理やコロケーションの方法について**特定の規約を設けていません**。ただし、プロジェクトを整理するためのいくつかの機能を提供しています。

### コンポーネント階層

特殊ファイルで定義されたコンポーネントは、特定の階層でレンダリングされます：

- `layout.js`
- `template.js`
- `error.js`（React のエラーバウンダリ）
- `loading.js`（React Suspense バウンダリ）
- `not-found.js`（「Not Found」UI のための React エラーバウンダリ）
- `page.js` またはネストされた `layout.js`

<Image
  alt="ファイル規約におけるコンポーネントの階層"
  srcLight="/docs/light/file-conventions-component-hierarchy.png"
  srcDark="/docs/dark/file-conventions-component-hierarchy.png"
  width="1600"

コンポーネントはネストされたルート内で再帰的にレンダリングされます。つまり、あるルートセグメントのコンポーネントは、親セグメントのコンポーネントの**内側**にネストされます。

### コロケーション

`app` ディレクトリでは、ネストされたフォルダがルート構造を定義します。各フォルダは、URLパスの対応するセグメントにマッピングされるルートセグメントを表します。

ただし、ルート構造はフォルダによって定義されますが、ルートセグメントに `page.js` または `route.js` ファイルが追加されるまで、そのルートは**一般公開されません**。

<Image
  alt="page.js または route.js ファイルがルートセグメントに追加されるまで、そのルートが公開されずアクセスできないことを示す図。"
  srcLight="/docs/light/project-organization-not-routable.png"
  srcDark="/docs/dark/project-organization-not-routable.png"
  width="1600"
  height="444"
/>

また、ルートが公開アクセス可能な場合でも、クライアントに送信されるのは `page.js` または `route.js` が**返すコンテンツ**のみです。

<Image
  alt="page.js と route.js ファイルによってルートがどのように公開され、外部からアクセス可能になるかを示す図。"
  srcLight="/docs/light/project-organization-routable.png"
  srcDark="/docs/dark/project-organization-routable.png"

つまり、**プロジェクトファイル**を `app` ディレクトリ内のルートセグメントに**安全に配置**しても、意図せずルーティング対象になることはありません。

<Image

  srcLight="/docs/light/project-organization-colocation.png"

> **補足**: プロジェクトのファイルを `app` 内に配置することも**できます**が、必ずしもそうする**必要はありません**。お好みで、[それらを `app` ディレクトリの外に置く](#store-project-files-outside-of-app)こともできます。

### プライベートフォルダ

フォルダ名の先頭にアンダースコアを付けることで、プライベートフォルダを作成できます: `_folderName`

これは、フォルダがプライベートな実装の詳細であり、ルーティングシステムの対象外とすべきであることを示します。これにより、**そのフォルダとすべてのサブフォルダ**がルーティングから除外されます。

<Image
  alt="プライベートフォルダーを含むフォルダー構成例"
  srcLight="/docs/light/project-organization-private-folders.png"
  srcDark="/docs/dark/project-organization-private-folders.png"
  width="1600"
  height="849"
/>

`app` ディレクトリ内のファイルは[デフォルトで安全にコロケーション可能](#colocation)なため、コロケーションにプライベートフォルダーは必須ではありません。ただし、次のような用途に活用できます：

- UI ロジックをルーティングロジックから分離する。
- プロジェクト全体および Next.js エコシステム全体で、内部ファイルの構成を一貫させる。
- コードエディターでのファイルの並び替えとグループ化。
- 将来の Next.js のファイル命名規則と名前が衝突する可能性を避ける。

> **補足**：
>
> - フレームワークの公式な規約ではありませんが、同じアンダースコアパターンを使って、プライベートフォルダ外のファイルも「プライベート」として扱うことを検討してもよいでしょう。
> - フォルダ名の前に `%5F`（アンダースコアを URL エンコードした形式）を付けることで、アンダースコアで始まる URL セグメントを作成できます: `%5FfolderName`。
> - プライベートフォルダを使用しない場合は、予期しない名前の競合を防ぐために、Next.js の[特殊なファイルの規約](/docs/app/getting-started/project-structure#routing-files)を把握しておくと役立ちます。

### ルートグループ

ルートグループは、フォルダー名を括弧で囲むことで作成できます: `(folderName)`

これは、フォルダが整理用であり、ルートのURLパスに**含まれない**ことを示します。

<Image
  alt="ルートグループを使用したフォルダ構造の例"
  srcLight="/docs/light/project-organization-route-groups.png"
  srcDark="/docs/dark/project-organization-route-groups.png"
  width="1600"
  height="849"
/>

ルートグループは以下の用途に役立ちます：

- サイトのセクション、用途、担当チームごとにルートを整理します。例: マーケティングページ、管理ページなど。
- 同じルートセグメント階層内でネストされたレイアウトを有効化する：
  - [同一セグメント内で複数のネストされたレイアウト（複数のルートレイアウトを含む）を作成する](#creating-multiple-root-layouts)
  - [共通のセグメント内の特定のルートにのみレイアウトを追加する](#opting-specific-segments-into-a-layout)

### `src` フォルダ

Next.js は、アプリケーションコード（`app` を含む）をオプションの [`src` フォルダ](/docs/app/api-reference/file-conventions/src-folder)内に配置することをサポートしています。これにより、アプリケーションコードと、主にプロジェクトのルートに存在するプロジェクト設定ファイルを分離できます。

### 複数のルートレイアウトを作成する

複数の[ルートレイアウト](/docs/app/api-reference/file-conventions/layout#root-layout)を作成するには、トップレベルの`layout.js`ファイルを削除し、各ルートグループ内に`layout.js`ファイルを追加します。これは、アプリケーションをまったく異なるUIやエクスペリエンスを持つセクションに分割する際に便利です。各ルートレイアウトには`<html>`タグと`<body>`タグを追加する必要があります。
