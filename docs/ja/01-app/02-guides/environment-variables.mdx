Next.js には環境変数の組み込みサポートがあり、次のことができます：

- [`.env` を使って環境変数を読み込む](#loading-environment-variables)
- [`NEXT_PUBLIC_` をプレフィックスとして付けることで、環境変数をブラウザ用にバンドルする](#bundling-environment-variables-for-the-browser)

> **警告:** デフォルトの `create-next-app` テンプレートでは、すべての `.env` ファイルが `.gitignore` に追加されます。ほとんどの場合、これらのファイルをリポジトリにコミットすべきではありません。

## 環境変数の読み込み

Next.js には、`.env*` ファイルから `process.env` へ環境変数を読み込むための機能が組み込まれています。

```txt filename=".env"
DB_HOST=localhost
DB_USER=myuser
DB_PASS=mypassword
```

<PagesOnly>
  これにより、`process.env.DB_HOST`、`process.env.DB_USER`、`process.env.DB_PASS` が自動的に Node.js の実行環境に読み込まれ、[Next.js のデータ取得メソッド](/docs/pages/building-your-application/data-fetching)や [API ルート](/docs/pages/building-your-application/routing/api-routes) で利用できるようになります。

たとえば、[`getStaticProps`](/docs/pages/building-your-application/data-fetching/get-static-props) を使う場合は次のようになります:

```js filename="pages/index.js"
export async function getStaticProps() {
  const db = await myDB.connect({
    host: process.env.DB_HOST,
    username: process.env.DB_USER,
    password: process.env.DB_PASS,
  })
  // ...
}
```

</PagesOnly>

<AppOnly>
  > **注意**: Next.js は `.env*` ファイル内での複数行の変数もサポートしています:
  >
  > ```bash
  > # .env
  >
  > # 改行を含めて記述できます
  > PRIVATE_KEY="-----BEGIN RSA PRIVATE KEY-----
  > ...
  > Kh9NV...
  > ...
  > -----END DSA PRIVATE KEY-----"
  >
  > # あるいはダブルクォート内で `\n` を使うこともできます
  > PRIVATE_KEY="-----BEGIN RSA PRIVATE KEY-----\nKh9NV...\n-----END DSA PRIVATE KEY-----\n"
  > ```

> **注意**: `/src` フォルダを使用している場合、Next.js は `.env` ファイルを `/src` フォルダからでは **なく** 親フォルダから **のみ** 読み込む点に注意してください。
> これにより、`process.env.DB_HOST`、`process.env.DB_USER`、`process.env.DB_PASS` が自動的に Node.js の実行環境に読み込まれ、[Route Handlers](/docs/app/api-reference/file-conventions/route) で利用できるようになります。

たとえば、次のようになります:

```js filename="app/api/route.js"
export async function GET() {
  const db = await myDB.connect({
    host: process.env.DB_HOST,
    username: process.env.DB_USER,
    password: process.env.DB_PASS,
  })
  // ...
}
```

</AppOnly>

### `@next/env` を使用して環境変数を読み込む

ORM やテストランナー用のプロジェクトルートの設定ファイルなど、Next.js のランタイム環境外で環境変数を読み込む必要がある場合は、`@next/env` パッケージを使用できます。

このパッケージは、`.env*` ファイルから環境変数を読み込むために Next.js 内部でも使用されています。

使用するには、パッケージをインストールし、`loadEnvConfig` 関数を使って環境変数を読み込みます:

```bash package="pnpm"
pnpm add @next/env
```

```bash package="npm"
npm install @next/env
```

```bash package="yarn"
yarn add @next/env
```

```bash package="bun"
bun add @next/env
```

```tsx filename="envConfig.ts" switcher
import { loadEnvConfig } from '@next/env'

const projectDir = process.cwd()
loadEnvConfig(projectDir)
```

```jsx filename="envConfig.js" switcher
import { loadEnvConfig } from '@next/env'

const projectDir = process.cwd()
loadEnvConfig(projectDir)
```

次に、必要な場所でその設定をインポートできます。たとえば、次のようにインポートします。

```tsx filename="orm.config.ts" switcher
import './envConfig.ts'

export default defineConfig({
  dbCredentials: {
    connectionString: process.env.DATABASE_URL!,
  },
})
```

```jsx filename="orm.config.js" switcher
import './envConfig.js'

export default defineConfig({
  dbCredentials: {
    connectionString: process.env.DATABASE_URL,
  },
})
```

### 他の変数を参照する

Next.js は、`.env*` ファイル内で `$VARIABLE` のように `$` を使って他の変数を参照している変数を自動的に展開します。これにより、他のシークレットを参照できます。例えば、次のようになります。

```txt filename=".env"
TWITTER_USER=nextjs
TWITTER_URL=https://x.com/$TWITTER_USER
```

上記の例では、`process.env.TWITTER_URL` は `https://x.com/nextjs` に設定されます。

> **補足**: 実際の値に `$` を含める必要がある場合は、`\$` のようにエスケープする必要があります。

## ブラウザ向けの環境変数のバンドル

`NEXT_PUBLIC_` 以外の環境変数は Node.js の環境でのみ利用可能であり、ブラウザからはアクセスできません（クライアントは別の _環境_ で実行されます）。

環境変数の値をブラウザから参照できるようにするために、Next.js はビルド時にその値をクライアントに配信される JavaScript バンドル内に「インライン展開」し、`process.env.[variable]` へのすべての参照をハードコードされた値に置き換えることができます。これを行うよう指示するには、変数名の先頭に `NEXT_PUBLIC_` を付けるだけです。例えば次のとおりです。

```txt filename=".env"
NEXT_PUBLIC_ANALYTICS_ID=abcdefghijk
```

これにより、Next.js は Node.js 環境内の `process.env.NEXT_PUBLIC_ANALYTICS_ID` へのすべての参照を、`next build` を実行した環境の値で置き換え、コード内のどこからでも使用できるようにします。この値は、ブラウザに送信される JavaScript にインライン展開されます。

> **注意:** ビルドが完了した後は、アプリはこれらの環境変数の変更を反映しなくなります。たとえば、ある環境でビルドされた slug を別の環境に昇格させるために Heroku パイプラインを使用している場合や、単一の Docker イメージをビルドして複数の環境にデプロイしている場合、すべての `NEXT_PUBLIC_` 変数はビルド時に評価された値のまま固定されます。そのため、これらの値はプロジェクトをビルドする時点で適切に設定しておく必要があります。実行時の環境変数の値にアクセスする必要がある場合は、それらをクライアントに提供するための独自の API（オンデマンドまたは初期化時）を用意する必要があります。

```js filename="pages/index.js"
import setupAnalyticsService from '../lib/my-analytics-service'

// 'NEXT_PUBLIC_ANALYTICS_ID' は 'NEXT_PUBLIC_' プレフィックスが付いているため、ここで使用できます。
// ビルド時に `setupAnalyticsService('abcdefghijk')` に変換されます。
setupAnalyticsService(process.env.NEXT_PUBLIC_ANALYTICS_ID)

function HomePage() {
  return <h1>Hello World</h1>
}

export default HomePage
```

次のような動的な参照はインライン化*されない*ことに注意してください:

```js
// 変数を使用しているため、インライン化されません
const varName = 'NEXT_PUBLIC_ANALYTICS_ID'
setupAnalyticsService(process.env[varName])

// 変数を使用しているため、インライン化されません
const env = process.env
setupAnalyticsService(env.NEXT_PUBLIC_ANALYTICS_ID)
```

### ランタイム環境変数

Next.js は、ビルド時とランタイムの両方で環境変数をサポートしています。

**デフォルトでは、環境変数はサーバー上でのみ利用可能です。** 環境変数をブラウザに公開するには、`NEXT_PUBLIC_` プレフィックスを付ける必要があります。ただし、これらの公開環境変数は、`next build` の実行時に JavaScript バンドルにインライン展開されます。

<PagesOnly>

ランタイム環境変数を読み取るには、`getServerSideProps` を使用するか、[App Router を段階的に採用する](/docs/app/guides/migrating/app-router-migration)ことを推奨します。

</PagesOnly>

<AppOnly>

動的レンダリング中にサーバー上で環境変数を安全に読み取ることができます:

```tsx filename="app/page.ts" switcher
import { connection } from 'next/server'

export default async function Component() {
  await connection()
  // cookies、headers、その他の Dynamic API も
  // 動的レンダリングにオプトインするため、
  // この環境変数は実行時に評価されます
  const value = process.env.MY_VALUE
  // ...
}
```

```jsx filename="app/page.js" switcher
import { connection } from 'next/server'

export default async function Component() {
  await connection()
  // cookies、headers、その他の Dynamic API も
  // 動的レンダリングにオプトインするため、
  // この環境変数は実行時に評価されます
  const value = process.env.MY_VALUE
  // ...
}
```

</AppOnly>

これにより、異なる値を持つ複数の環境間で、同一の Docker イメージをそのまま昇格させて利用できます。

**補足:**

- [`register` 関数](/docs/app/guides/instrumentation)を使用して、サーバー起動時にコードを実行できます。

## テスト用環境変数

`development` と `production` 環境とは別に、3 つ目のオプションとして `test` が利用できます。development や production 環境向けにデフォルト値を設定できるのと同様に、`test` 環境向けにも `.env.test` ファイルでデフォルト値を設定できます（ただし、これは前の 2 つほど一般的ではありません）。Next.js は `test` 環境では `.env.development` や `.env.production` から環境変数を読み込みません。

これは、`jest` や `cypress` のようなツールでテストを実行する際に、テスト専用の環境変数を設定する必要がある場合に便利です。`NODE_ENV` が `test` に設定されているとテスト用のデフォルト値が読み込まれますが、通常はテストツール側が処理してくれるため、これを手動で行う必要はあまりありません。

`test` 環境と `development` および `production` との間には、覚えておくべき小さな違いがあります。`.env.local` は読み込まれません。テストは誰に対しても同じ結果を出すことが期待されるためです。このようにして、`.env.local`（デフォルト設定を上書きすることを意図したもの）を無視することで、テストの各実行において、異なる実行間でも同じ環境変数のデフォルト値が使用されます。

> **補足**: Default Environment Variables と同様に、`.env.test` ファイルはリポジトリに含めるべきですが、`.env.test.local` は含めるべきではありません。`.env*.local` は `.gitignore` で無視されることを意図しているためです。

ユニットテストを実行する際には、`@next/env` パッケージの `loadEnvConfig` 関数を利用することで、Next.js と同じ方法で環境変数を読み込ませることができます。

```js
// 以下はJestのグローバルセットアップファイルや類似のテスト設定ファイルで使用できます
import { loadEnvConfig } from '@next/env'

export default async () => {
  const projectDir = process.cwd()
  loadEnvConfig(projectDir)
}
```

## 環境変数の読み込み順序

環境変数は以下の場所をこの順番で参照し、変数が見つかった時点で検索を終了します。

1. `process.env`
1. `.env.$(NODE_ENV).local`
1. `.env.local`（`NODE_ENV` が `test` の場合は参照されません）
1. `.env.$(NODE_ENV)`
1. `.env`

たとえば、`NODE_ENV` が `development` で、`.env.development.local` と `.env` の両方に同じ環境変数を定義している場合、`.env.development.local` の値が使用されます。

> **補足**: `NODE_ENV` に指定できる値は `production`、`development`、`test` です。

## 補足

- [`/src` ディレクトリ](/docs/app/api-reference/file-conventions/src-folder) を使用している場合でも、`.env.*` ファイルはプロジェクトのルートディレクトリに置いておく必要があります。
- 環境変数 `NODE_ENV` が設定されていない場合、Next.js は `next dev` コマンド実行時には自動的に `development` を、その他のすべてのコマンドでは `production` を割り当てます。
