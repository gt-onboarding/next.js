インストルメンテーションとは、コードによって監視やログ取得のツールをアプリケーションに組み込むプロセスのことです。これにより、アプリケーションのパフォーマンスや動作を追跡し、本番環境で発生する問題をデバッグできるようになります。

## 規約

インストルメンテーションをセットアップするには、プロジェクトの**ルートディレクトリ**（または使用している場合は [`src`](/docs/app/api-reference/file-conventions/src-folder) フォルダ）に `instrumentation.ts|js` ファイルを作成します。

次に、そのファイル内で `register` 関数をエクスポートします。この関数は、新しい Next.js サーバーインスタンスが起動されたタイミングで**一度だけ**呼び出され、サーバーがリクエストを処理できるようになる前に完了している必要があります。

たとえば、[OpenTelemetry](https://opentelemetry.io/) と [@vercel/otel](https://vercel.com/docs/observability/otel-overview) を使用して Next.js を計測するには、次のようにします。

```ts filename="instrumentation.ts" switcher
import { registerOTel } from '@vercel/otel'

export function register() {
  registerOTel('next-app')
}
```

```js filename="instrumentation.js" switcher
import { registerOTel } from '@vercel/otel'

export function register() {
  registerOTel('next-app')
}
```

完全な実装例については、[Next.js with OpenTelemetry の例](https://github.com/vercel/next.js/tree/canary/examples/with-opentelemetry)を参照してください。

> **補足**:
>
> - `instrumentation` ファイルはプロジェクトのルートに配置し、`app` や `pages` ディレクトリの中には置かないでください。`src` フォルダを使用している場合は、`pages` や `app` と同じ階層にある `src` 直下に配置してください。
> - 接尾辞を追加するために [`pageExtensions` 設定オプション](/docs/app/api-reference/config/next-config-js/pageExtensions)を使用する場合は、それに合わせて `instrumentation` のファイル名も更新する必要があります。

## 使用例

### 副作用を持つファイルのインポート

場合によっては、副作用を発生させることを目的としてファイルをインポートしたいことがあります。例えば、一連のグローバル変数を定義しているファイルをインポートするものの、コード内でそのインポートを明示的に参照しない場合です。この場合でも、そのパッケージによって宣言されたグローバル変数にはアクセスできます。

`register` 関数内では、JavaScript の `import` 構文を使ってファイルをインポートすることを推奨します。次の例は、`register` 関数内での `import` の基本的な使用方法を示しています。

```ts filename="instrumentation.ts" switcher
export async function register() {
  await import('package-with-side-effect')
}
```

```js filename="instrumentation.js" switcher
export async function register() {
  await import('package-with-side-effect')
}
```

> **補足:**
>
> ファイルの先頭ではなく、`register` 関数内からそのファイルをインポートすることを推奨しています。こうすることで、副作用を発生させるコードを 1 か所にまとめることができ、ファイル先頭でグローバルにインポートすることで生じうる意図しない影響を避けられます。

### ランタイム固有コードのインポート

Next.js はすべての環境で `register` を呼び出すため、特定のランタイム (例: [Edge または Node.js](/docs/app/api-reference/edge)) ではサポートされていないコードは、必ず条件付きでインポートする必要があります。現在の環境を取得するには、`NEXT_RUNTIME` 環境変数を使用できます。

```ts filename="instrumentation.ts" switcher
export async function register() {
  if (process.env.NEXT_RUNTIME === 'nodejs') {
    await import('./instrumentation-node')
  }

  if (process.env.NEXT_RUNTIME === 'edge') {
    await import('./instrumentation-edge')
  }
}
```

```js filename="instrumentation.js" switcher
export async function register() {
  if (process.env.NEXT_RUNTIME === 'nodejs') {
    await import('./instrumentation-node')
  }

  if (process.env.NEXT_RUNTIME === 'edge') {
    await import('./instrumentation-edge')
  }
}
```
