Progressive Web Application (PWA) は、ウェブアプリケーションの到達範囲やアクセスのしやすさに、ネイティブモバイルアプリの機能とユーザーエクスペリエンスを組み合わせたものです。Next.js を使うことで、複数のコードベースやアプリストアの審査を必要とせず、あらゆるプラットフォームでシームレスなアプリのような体験を提供する PWA を作成できます。

PWA によって、次のことが可能になります:

- アプリストアの審査を待たずに、更新を即座にデプロイする
- 単一のコードベースでクロスプラットフォームアプリケーションを作成する
- ホーム画面へのインストールやプッシュ通知など、ネイティブアプリに近い機能を提供する

## Next.js で PWA を構築する

### 1. Web App Manifest の作成

Next.js では、App Router を使って [web app manifest](/docs/app/api-reference/file-conventions/metadata/manifest) を作成するためのサポートが組み込まれています。静的または動的な manifest ファイルを作成できます。

たとえば、`app/manifest.ts` または `app/manifest.json` ファイルを作成します。

```tsx filename="app/manifest.ts" switcher
import type { MetadataRoute } from 'next'

export default function manifest(): MetadataRoute.Manifest {
  return {
    name: 'Next.js PWA',
    short_name: 'NextPWA',
    description: 'A Progressive Web App built with Next.js',
    start_url: '/',
    display: 'standalone',
    background_color: '#ffffff',
    theme_color: '#000000',
    icons: [
      {
        src: '/icon-192x192.png',
        sizes: '192x192',
        type: 'image/png',
      },
      {
        src: '/icon-512x512.png',
        sizes: '512x512',
        type: 'image/png',
      },
    ],
  }
}
```


このファイルには、名前やアイコン、ユーザーのデバイス上でアイコンとしてどのように表示されるかといった情報を含める必要があります。これにより、ユーザーは PWA をホーム画面にインストールできるようになり、ネイティブアプリのような体験を提供できます。

[ファビコンジェネレーター](https://realfavicongenerator.net/) などのツールを使ってさまざまなアイコンセットを作成し、生成されたファイルを `public/` フォルダに配置します。

### 2. Web Push 通知の実装

Web Push 通知は、次のようなモダンブラウザでサポートされています:

- ホーム画面にインストールされたアプリケーション向けの iOS 16.4 以降
- macOS 13 以降向けの Safari 16
- Chromium ベースのブラウザ
- Firefox

これにより、PWA はネイティブアプリの現実的な代替手段となります。特に、オフライン対応がなくてもインストールプロンプトをトリガーできます。

Web Push 通知を使用すると、ユーザーがアプリを積極的に使用していないときでも、ユーザーを再び呼び戻すことができます。ここでは、Next.js アプリケーションでの実装方法を説明します:

まず、`app/page.tsx` にメインのページコンポーネントを作成します。理解しやすくするために、小さなパーツに分割していきます。最初に、必要になるいくつかのインポートとユーティリティを追加します。参照している Server Actions はまだ存在していなくても問題ありません:

```tsx switcher
'use client'

import { useState, useEffect } from 'react'
import { subscribeUser, unsubscribeUser, sendNotification } from './actions'

function urlBase64ToUint8Array(base64String: string) {
  const padding = '='.repeat((4 - (base64String.length % 4)) % 4)
  const base64 = (base64String + padding).replace(/-/g, '+').replace(/_/g, '/')

  const rawData = window.atob(base64)
  const outputArray = new Uint8Array(rawData.length)

  for (let i = 0; i < rawData.length; ++i) {
    outputArray[i] = rawData.charCodeAt(i)
  }
  return outputArray
}
```

ここで、購読・購読解除・プッシュ通知の送信をまとめて管理するコンポーネントを追加しましょう。

```tsx switcher
function PushNotificationManager() {
  const [isSupported, setIsSupported] = useState(false)
  const [subscription, setSubscription] = useState<PushSubscription | null>(
    null
  )
  const [message, setMessage] = useState('')

  useEffect(() => {
    if ('serviceWorker' in navigator && 'PushManager' in window) {
      setIsSupported(true)
      registerServiceWorker()
    }
  }, [])

  async function registerServiceWorker() {
    const registration = await navigator.serviceWorker.register('/sw.js', {
      scope: '/',
      updateViaCache: 'none',
    })
    const sub = await registration.pushManager.getSubscription()
    setSubscription(sub)
  }

  async function subscribeToPush() {
    const registration = await navigator.serviceWorker.ready
    const sub = await registration.pushManager.subscribe({
      userVisibleOnly: true,
      applicationServerKey: urlBase64ToUint8Array(
        process.env.NEXT_PUBLIC_VAPID_PUBLIC_KEY!
      ),
    })
    setSubscription(sub)
    const serializedSub = JSON.parse(JSON.stringify(sub))
    await subscribeUser(serializedSub)
  }

  async function unsubscribeFromPush() {
    await subscription?.unsubscribe()
    setSubscription(null)
    await unsubscribeUser()
  }

  async function sendTestNotification() {
    if (subscription) {
      await sendNotification(message)
      setMessage('')
    }
  }

  if (!isSupported) {
    return <p>このブラウザはプッシュ通知をサポートしていません。</p>
  }

  return (
    <div>
      <h3>プッシュ通知</h3>
      {subscription ? (
        <>
          <p>プッシュ通知を購読しています。</p>
          <button onClick={unsubscribeFromPush}>購読解除</button>
          <input
            type="text"
            placeholder="通知メッセージを入力"
            value={message}
            onChange={(e) => setMessage(e.target.value)}
          />
          <button onClick={sendTestNotification}>テスト送信</button>
        </>
      ) : (
        <>
          <p>プッシュ通知を購読していません。</p>
          <button onClick={subscribeToPush}>購読する</button>
        </>
      )}
    </div>
  )
}
```

### 3. Server Actions の実装

`app/actions.ts` に Server Actions を定義するための新しいファイルを作成します。このファイルでは、サブスクリプションの作成と削除、および通知の送信を処理します。

```tsx filename="app/actions.ts" switcher
'use server'

import webpush from 'web-push'

webpush.setVapidDetails(
  '<mailto:your-email@example.com>',
  process.env.NEXT_PUBLIC_VAPID_PUBLIC_KEY!,
  process.env.VAPID_PRIVATE_KEY!
)

let subscription: PushSubscription | null = null

export async function subscribeUser(sub: PushSubscription) {
  subscription = sub
  // 本番環境では、サブスクリプションをデータベースに保存することをお勧めします
  // 例: await db.subscriptions.create({ data: sub })
  return { success: true }
}

export async function unsubscribeUser() {
  subscription = null
  // 本番環境では、サブスクリプションをデータベースから削除することをお勧めします
  // 例: await db.subscriptions.delete({ where: { ... } })
  return { success: true }
}

export async function sendNotification(message: string) {
  if (!subscription) {
    throw new Error('No subscription available')
  }

  try {
    await webpush.sendNotification(
      subscription,
      JSON.stringify({
        title: 'Test Notification',
        body: message,
        icon: '/icon.png',
      })
    )
    return { success: true }
  } catch (error) {
    console.error('Error sending push notification:', error)
    return { success: false, error: 'Failed to send notification' }

}
```

### 4. VAPID キーの生成

Web Push API を使用するには、[VAPID](https://vapidkeys.com/) キーを生成する必要があります。最も簡単なのは、`web-push` CLI を直接使用する方法です。

まず、`web-push` をグローバルインストールします。

```bash package="pnpm"
pnpm add -g web-push
```

```bash package="npm"
npm install -g web-push
```

```bash package="yarn"
yarn global add web-push
```

```bash package="bun"
bun add -g web-push
```

次のコマンドを実行して、VAPID キーを生成します：

```bash filename="Terminal"
web-push generate-vapid-keys
```

出力された内容をコピーし、そのキーを `.env` ファイルに貼り付けてください。

```
NEXT_PUBLIC_VAPID_PUBLIC_KEY=your_public_key_here
VAPID_PRIVATE_KEY=your_private_key_here
```

### 5. Service Worker の作成

Service Worker 用の `public/sw.js` ファイルを作成します。

```js filename="public/sw.js"
self.addEventListener('push', function (event) {
  if (event.data) {
    const data = event.data.json()
    const options = {
      body: data.body,
      icon: data.icon || '/icon.png',
      badge: '/badge.png',
      vibrate: [100, 50, 100],
      data: {
        dateOfArrival: Date.now(),
        primaryKey: '2',
      },
    }
    event.waitUntil(self.registration.showNotification(data.title, options))
  }
})

self.addEventListener('notificationclick', function (event) {
  console.log('Notification click received.')
  event.notification.close()
  event.waitUntil(clients.openWindow('<https://your-website.com>'))
})
```

この Service Worker はカスタム画像と通知をサポートします。受信した push イベントや通知のクリックを処理します。

- `icon` と `badge` プロパティを使って、通知にカスタムアイコンを設定できます。
- 対応デバイスでは、`vibrate` パターンを調整して、カスタムのバイブレーション通知を作成できます。
- `data` プロパティを使って、通知に追加のデータを付加できます。

Service Worker がさまざまなデバイスやブラウザで期待どおりに動作することを確認するために、十分にテストしてください。また、`notificationclick` イベントリスナー内の `'https://your-website.com'` リンクを、アプリケーションに適した URL に更新することも忘れないでください。

### 6. ホーム画面への追加

ステップ 2 で定義した `InstallPrompt` コンポーネントは、iOS デバイスに対してホーム画面に追加するよう促すメッセージを表示します。

アプリケーションをモバイル端末のホーム画面にインストール可能にするには、次の要件を満たす必要があります:

1. 有効な Web App Manifest（ステップ 1 で作成）
2. HTTPS 経由で配信されているウェブサイト

これらの条件が満たされている場合、最新のブラウザは自動的にユーザーにインストールプロンプトを表示します。[`beforeinstallprompt`](https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeinstallprompt_event) を使用してカスタムのインストールボタンを提供することもできますが、これはクロスブラウザかつクロスプラットフォームではなく（iOS の Safari では動作しないため）、推奨しません。

### 7. ローカルでのテスト

ローカルで通知を確認できるようにするには、次の点を確認してください。

- [HTTPS を使ってローカルで実行している](/docs/app/api-reference/cli/next#using-https-during-development) こと
  - テストには `next dev --experimental-https` を使用してください
- ブラウザ (Chrome、Safari、Firefox) で通知が有効になっていること
  - ローカルでプロンプトが表示されたら、通知の利用を許可してください
  - ブラウザ全体で通知が無効になっていないことを確認してください
  - それでも通知が表示されない場合は、別のブラウザを使ってデバッグしてみてください

### 8. アプリケーションのセキュリティ対策

セキュリティは、特に PWA において、あらゆる Web アプリケーションにとって重要な要素です。Next.js では、`next.config.js` ファイルを使用してセキュリティヘッダーを設定できます。例えば、次のように設定します。

```js filename="next.config.js"
module.exports = {
  async headers() {
    return [
      {
        source: '/(.*)',
        headers: [
          {
            key: 'X-Content-Type-Options',
            value: 'nosniff',
          },
          {
            key: 'X-Frame-Options',
            value: 'DENY',
          },
          {
            key: 'Referrer-Policy',
            value: 'strict-origin-when-cross-origin',
          },
        ],
      },
      {
        source: '/sw.js',
        headers: [
          {
            key: 'Content-Type',
            value: 'application/javascript; charset=utf-8',
          },
          {
            key: 'Cache-Control',
            value: 'no-cache, no-store, must-revalidate',
          },
          {
            key: 'Content-Security-Policy',
            value: "default-src 'self'; script-src 'self'",
          },
        ],
      },
    ]
  },
}
```

これらのオプションをそれぞれ見ていきましょう。

1. グローバルヘッダー（すべてのルートに適用）:
   1. `X-Content-Type-Options: nosniff`: MIME タイプスニッフィングを防ぎ、悪意のあるファイルのアップロードリスクを軽減します。
   2. `X-Frame-Options: DENY`: サイトが iframe に埋め込まれるのを防ぐことで、クリックジャッキング攻撃から保護します。
   3. `Referrer-Policy: strict-origin-when-cross-origin`: リクエストに含まれるリファラー情報の量を制御し、セキュリティと利便性のバランスを取ります。
2. Service Worker 固有のヘッダー:
   1. `Content-Type: application/javascript; charset=utf-8`: Service Worker が正しく JavaScript として解釈されるようにします。
   2. `Cache-Control: no-cache, no-store, must-revalidate`: Service Worker がキャッシュされるのを防ぎ、常に最新バージョンがユーザーに配信されるようにします。
   3. `Content-Security-Policy: default-src 'self'; script-src 'self'`: Service Worker に対して厳格な Content Security Policy を適用し、同一オリジンからのスクリプトのみを許可します。

Next.js における [Content Security Policies](/docs/app/guides/content-security-policy) の定義について、詳しくはドキュメントを参照してください。

## PWA の拡張

1. **PWA 機能の活用**: PWA はさまざまな Web API を活用して高度な機能を提供できます。アプリケーションを強化するために、Background Sync、Periodic Background Sync、File System Access API などの機能の利用を検討してください。PWA の機能に関する最新情報やアイデアについては、[What PWA Can Do Today](https://whatpwacando.today/) などのリソースを参照できます。
2. **静的エクスポート:** アプリケーションでサーバーを実行せず、ファイルの静的エクスポートを使用する必要がある場合は、そのような構成を有効化するように Next.js の設定を更新できます。詳しくは [Next.js Static Export ドキュメント](/docs/app/guides/static-exports) を参照してください。ただし、Server Actions から外部 API を呼び出す方式に移行し、定義したヘッダーをプロキシ側に移動する必要があります。
3. **オフライン対応**: オフライン機能を提供するための 1 つの選択肢は、Next.js と組み合わせた [Serwist](https://github.com/serwist/serwist) の利用です。Serwist を Next.js と統合する方法の例は、その [documentation](https://github.com/serwist/serwist/tree/main/examples/next-basic) で確認できます。**注:** 現在このプラグインには webpack の設定が必要です。
4. **セキュリティ上の考慮事項**: service worker が適切に保護されていることを確認してください。これには、HTTPS の使用、プッシュメッセージの送信元の検証、適切なエラー処理の実装などが含まれます。
5. **ユーザー体験**: 利用者のブラウザが特定の PWA 機能をサポートしていない場合でもアプリが適切に動作するよう、プログレッシブエンハンスメントの手法を実装することを検討してください。
