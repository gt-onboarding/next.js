React と Next.js では、目的やユースケースがそれぞれ異なる、いくつかの種類のテストを記述できます。このページでは、テストの種類と、アプリケーションをテストする際によく使われるツールの概要を説明します。

## テストの種類

- **Unit Testing（ユニットテスト）** は、個々のユニット（コードのブロック）を分離してテストすることです。React において、ユニットとは単一の関数、フック、またはコンポーネントを指します。
- **Component Testing（コンポーネントテスト）** は、ユニットテストの中でもとくに React コンポーネントを主な対象とする、より特化したテストです。コンポーネントのレンダリング結果、props とのやり取り、ユーザーイベントに対する振る舞いなどをテストする場合があります。
- **Integration Testing（統合テスト）** は、複数のユニットが一緒にどのように連携して動作するかをテストします。これは、コンポーネント、フック、関数の組み合わせになることがあります。
- **End-to-End (E2E) Testing（E2E テスト）** は、ブラウザのような、実際のユーザーシナリオをシミュレートした環境でユーザーフローをテストします。これは、本番環境に近い環境で特定のタスク（例: サインアップフロー）をテストすることを意味します。
- **Snapshot Testing（スナップショットテスト）** は、コンポーネントのレンダリング結果をキャプチャしてスナップショットファイルに保存する手法です。テスト実行時には、現在のコンポーネントのレンダリング結果が保存済みのスナップショットと比較されます。スナップショットの差分は、振る舞いの予期しない変更を示す手がかりとして使われます。
