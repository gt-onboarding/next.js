Next.js の Image コンポーネントは、HTML の `<img>` 要素を拡張し、画像を自動で最適化します。

```jsx filename="app/page.js"
import Image from 'next/image'

export default function Page() {
  return (
    <Image
      src="/profile.png"
      width={500}
      height={500}
      alt="Picture of the author"
    />
  )
}
```

<PagesOnly>
  > **補足**: Next.js 13
  より前のバージョンを使用している場合は、コンポーネントが名称変更されたため、[next/legacy/image](/docs/pages/api-reference/components/image-legacy)
  のドキュメントを参照してください。
</PagesOnly>

#### `src`

画像のソースとなる値。次のいずれかになります：

内部パスの文字列。

```jsx
<Image src="/profile.png" />
```

外部の絶対 URL（[remotePatterns](#remotepatterns) で設定されている必要があります）。

```jsx
<Image src="https://example.com/profile.png" />
```

静的インポート。

```jsx
import profile from './profile.png'

export default function Page() {
  return <Image src={profile} />
}
```

> **補足**: セキュリティ上の理由から、デフォルトの [loader](#loader) を使用する Image Optimization API は、`src` 画像を取得する際にリクエストヘッダーを転送し*ません*。
> `src` 画像の取得に認証が必要な場合は、Image Optimization を無効化するために [unoptimized](#unoptimized) プロパティの利用を検討してください。

#### `alt`

`alt` プロパティは、スクリーンリーダーや検索エンジン向けに画像を説明するために使われます。画像の表示が無効化されている場合や、画像の読み込み中にエラーが発生した場合の代替テキストとしても使用されます。

このプロパティには、[ページの意味を変えることなく](https://html.spec.whatwg.org/multipage/images.html#general-guidelines)画像の代わりになりうるテキストを指定します。画像を補足するためのものではなく、画像の上下のキャプションなどですでに提供されている情報を繰り返してはいけません。

画像が[純粋に装飾目的](https://html.spec.whatwg.org/multipage/images.html#a-purely-decorative-image-that-doesn't-add-any-information)である場合や、[ユーザーを対象としていない](https://html.spec.whatwg.org/multipage/images.html#an-image-not-intended-for-the-user)場合、`alt` プロパティは空文字列（`alt=""`）にします。

> [画像のアクセシビリティに関するガイドライン](https://html.spec.whatwg.org/multipage/images.html#alt)について詳しくは、こちらを参照してください。

#### `width` と `height`

`width` と `height` プロパティは、ピクセル単位の[固有](https://developer.mozilla.org/en-US/docs/Glossary/Intrinsic_Size)な画像サイズを表します。このプロパティは、ブラウザが画像のためにスペースを確保し、読み込み中のレイアウトシフトを防ぐために使用する正しい**アスペクト比**を推論するために使われます。これは、CSS によって制御される画像の*表示サイズ*を決定するものではありません。

```jsx
<Image src="/profile.png" width={500} height={500} />
```

`width` と `height` の両方のプロパティを **必ず** 設定する必要があります。ただし、次の場合は例外です:

- 画像が静的にインポートされている場合
- 画像に [`fill` プロパティ](#fill) が設定されている場合

高さと幅が不明な場合は、[`fill` プロパティ](#fill) の使用を推奨します。

#### `fill`

画像を親要素のサイズいっぱいに拡大して表示させるための真偽値です。

```js
<Image src="/profile.png" fill={true} />
```

**position の指定**:

- 親要素には必ず、`position` に `"relative"`、`"fixed"`、または `"absolute"` のいずれかを指定する **必要があります**。
- 既定では、`<img>` 要素は `position: "absolute"` を使用します。

**object-fit の指定**:

画像にスタイルが適用されていない場合、画像はコンテナに合わせて伸縮します。`objectFit` を使用して、トリミングとスケーリングを制御できます。

- `"contain"`: 画像はコンテナに収まるよう縮小され、アスペクト比が維持されます。
- `"cover"`: 画像はコンテナ全体を埋めるように表示され、はみ出た部分はトリミングされます。

> [`position`](https://developer.mozilla.org/en-US/docs/Web/CSS/position) と [`object-fit`](https://developer.mozilla.org/docs/Web/CSS/object-fit) について詳しくはドキュメントを参照してください。

#### `loader`

画像の URL を生成するために使用されるカスタム関数です。この関数は以下のパラメーターを受け取り、画像の URL 文字列を返します：

- [`src`](#src)
- [`width`](#width-and-height)
- [`quality`](#quality)

<AppOnly>

```js
'use client'

import Image from 'next/image'

const imageLoader = ({ src, width, quality }) => {
  return `https://example.com/${src}?w=${width}&q=${quality || 75}`
}

export default function Page() {
  return (
    <Image
      loader={imageLoader}
      src="me.png"
      alt="Picture of the author"
      width={500}
      height={500}
    />
  )
}
```

> **補足**: `onLoad` など、関数を受け取る props を使用する場合は、渡した関数をシリアライズするために [Client Components](https://react.dev/reference/rsc/use-client) を使用する必要があります。

</AppOnly>

<PagesOnly>

```js
import Image from 'next/image'

const imageLoader = ({ src, width, quality }) => {
  return `https://example.com/${src}?w=${width}&q=${quality || 75}`
}

export default function Page() {
  return (
    <Image
      loader={imageLoader}
      src="me.png"
      alt="Picture of the author"
      width={500}
      height={500}
    />
  )
}
```

</PagesOnly>

または、`next.config.js` 内の [loaderFile](#loaderfile) 設定を使用して、prop を渡さずにアプリケーション内のすべての `next/image` コンポーネントを設定することもできます。

#### `sizes`

各ブレークポイントでの画像サイズを定義します。ブラウザはこの情報を基に、生成された `srcset` から最も適切なサイズを選択します。

```jsx
import Image from 'next/image'

export default function Page() {
  return (
    <div className="grid-element">
      <Image
        fill
        src="/example.png"
        sizes="(max-width: 768px) 100vw, (max-width: 1200px) 50vw, 33vw"
      />
    </div>
  )
}
```

`sizes` は次のような場合に使用します:

- 画像で [`fill`](#fill) プロップを使用している場合
- CSS を使って画像をレスポンシブにしている場合

`sizes` が指定されていない場合、ブラウザは画像がビューポートと同じ幅（`100vw`）になると仮定します。その結果、必要以上に大きな画像がダウンロードされてしまう可能性があります。

さらに、`sizes` は `srcset` の生成方法にも影響します:

- `sizes` なし: Next.js は固定サイズの画像に適した、制限された `srcset`（例: 1x, 2x）を生成します。
- `sizes` あり: Next.js はレスポンシブレイアウト向けに最適化された、より幅広い `srcset`（例: 640w, 750w など）を生成します。

> `srcset` と `sizes` の詳細は [web.dev](https://web.dev/learn/design/responsive-images/#sizes) と [mdn](https://developer.mozilla.org/docs/Web/HTML/Element/img#sizes) を参照してください。

#### `quality`

最適化された画像の品質を指定する `1` から `100` までの整数値。値を大きくするとファイルサイズと視覚的な忠実度が上がります。値を小さくするとファイルサイズは小さくなりますが、鮮明さに影響する可能性があります。

```jsx
// デフォルトのqualityは75
<Image quality={75} />
```

`next.config.js` で [qualities](#qualities) を設定している場合、その値は許可されているいずれかの値と一致している必要があります。

> **補足**: 元の画像の画質がすでに低い場合、`quality` の値を高く設定しても見た目は改善されず、ファイルサイズだけが大きくなります。

#### `style`

内部の画像要素に CSS スタイルを渡せます。

```jsx
const imageStyle = {
  borderRadius: '50%',
  border: '1px solid #fff',
  width: '100px',
  height: 'auto',
}

export default function ProfileImage() {
  return <Image src="..." style={imageStyle} />
}
```

> **補足**: `style` プロップでカスタムの幅を指定する場合は、画像のアスペクト比を保つために `height: 'auto'` も必ず指定してください。

#### `preload`

画像を事前読み込みするかどうかを示すブール値です。

```jsx
// デフォルトのpreloadはfalse
<Image preload={false} />
```

- `true`: `<head>` 内に `<link>` を挿入して画像を[プリロード](https://web.dev/preload-responsive-images/)します。
- `false`: 画像をプリロードしません。

**使用すべき場合:**

- 画像が [Largest Contentful Paint (LCP)](https://nextjs.org/learn/seo/web-performance/lcp) 要素である場合。
- 画像がファーストビュー（折りたたみ線より上）にあり、一般的にヒーロー画像である場合。
- 画像が後で `<body>` 内で検出されるのを待たずに、`<head>` で読み込みを開始したい場合。

**使用すべきでない場合:**

- ビューポートによって、複数の画像が [Largest Contentful Paint (LCP)](https://nextjs.org/learn/seo/web-performance/lcp) 要素になり得る場合。
- `loading` プロパティを使用している場合。
- `fetchPriority` プロパティを使用している場合。

ほとんどの場合、`preload` の代わりに `loading="eager"` または `fetchPriority="high"` を使用するべきです。

#### `priority`

Next.js 16 以降では、挙動をより明確にするために、`priority` プロパティは非推奨となり、代わりに [`preload`](#preload) プロパティが推奨されます。

#### `loading`

画像の読み込みを開始するタイミングを制御します。

```jsx
// デフォルトは lazy
<Image loading="lazy" />
```

- `lazy`: 画像がビューポートから一定の距離に到達するまで、読み込みを遅延します。
- `eager`: ページ上での位置に関係なく、画像を即座に読み込みます。

画像を直ちに読み込ませたい場合にのみ `eager` を使用してください。

> [`loading` 属性](https://developer.mozilla.org/docs/Web/HTML/Element/img#loading)について詳しくは、こちらを参照してください。

#### `placeholder`

画像の読み込み中に表示するプレースホルダー画像を指定し、体感される読み込み速度を向上させます。

```jsx
// デフォルトは empty
<Image placeholder="empty" />
```

- `empty`: 画像の読み込み中にプレースホルダーを表示しません。
- `blur`: ぼかしをかけた画像をプレースホルダーとして使用します。[`blurDataURL`](#blurdataurl) プロパティと一緒に使用する必要があります。
- `data:image/...`: [Data URL](https://developer.mozilla.org/docs/Web/HTTP/Basics_of_HTTP/Data_URIs) をプレースホルダーとして使用します。

**例:**

- [`blur` プレースホルダー](https://image-component.nextjs.gallery/placeholder)
- [Data URL の `placeholder` プロップを使ったシマー効果](https://image-component.nextjs.gallery/shimmer)
- [`blurDataURL` プロップを使ったカラー効果](https://image-component.nextjs.gallery/color)

> [`placeholder` 属性](https://developer.mozilla.org/docs/Web/HTML/Element/img#placeholder)について詳しくは、こちらを参照してください。

#### `blurDataURL`

画像が正常に読み込まれるまでの間、プレースホルダー画像として使用するための [Data URL](https://developer.mozilla.org/docs/Web/HTTP/Basics_of_HTTP/Data_URIs) です。自動的に設定されたり、[`placeholder="blur"`](#placeholder) プロパティと併用したりできます。

```jsx
<Image placeholder="blur" blurDataURL="..." />
```

画像は自動的に拡大されてぼかされるため、極小サイズの画像（10px 以下）が推奨されます。

**自動**

`src` が `jpg`、`png`、`webp`、または `avif` ファイルの静的インポートである場合、画像がアニメーションでない限り、`blurDataURL` は自動的に追加されます。

**手動設定**

画像が動的またはリモートの場合は、自分で `blurDataURL` を指定する必要があります。生成するには、次のような方法が使えます:

- [png-pixel.com のようなオンラインツール](https://png-pixel.com)
- [Plaiceholder のようなライブラリ](https://github.com/joe-bell/plaiceholder)

`blurDataURL` のサイズが大きすぎるとパフォーマンスに悪影響を与える可能性があります。小さくシンプルに保ってください。

**例:**

- [デフォルトの `blurDataURL` prop](https://image-component.nextjs.gallery/placeholder)
- [`blurDataURL` prop を使ったカラーエフェクト](https://image-component.nextjs.gallery/color)

#### `onLoad`

画像の読み込みが完了し、[placeholder](#placeholder) が削除された後に呼び出されるコールバック関数です。

```jsx
<Image onLoad={(e) => console.log(e.target.naturalWidth)} />
```

コールバック関数は、1つの引数として、内部の `<img>` 要素を参照する `target` を持つイベントを受け取って呼び出されます。

<AppOnly>
  > **補足**: `onLoad` のように関数を受け取る props
  を使用する場合、渡した関数をシリアライズするために [Client
  Components](https://react.dev/reference/rsc/use-client)
  を使用する必要があります。
</AppOnly>

#### `onError`

画像の読み込みに失敗した場合に呼び出されるコールバック関数です。

```jsx
<Image onError={(e) => console.error(e.target.id)} />
```

<AppOnly>
  > **補足**: `onError` のように関数を受け取る props
  を使用する場合は、渡された関数をシリアライズするために [Client
  Components](https://react.dev/reference/rsc/use-client)
  を使用する必要があります。
</AppOnly>

#### `unoptimized`

画像を最適化しないかどうかを示す真偽値です。これは、1KB 未満の小さな画像、ベクター画像 (SVG)、アニメーション画像 (GIF) など、最適化による恩恵をほとんど受けない画像に有用です。

```js
import Image from 'next/image'

const UnoptimizedImage = (props) => {
  // デフォルトはfalse
  return <Image {...props} unoptimized />
}
```

- `true`: 画質・サイズ・フォーマットを変更せず、`src` で指定した元の画像がそのまま配信されます。
- `false`: 元の画像が最適化されます。

Next.js 12.3.0 以降、このプロパティは次の設定で `next.config.js` を更新することで、すべての画像に適用できます:

```js filename="next.config.js"
module.exports = {
  images: {
    unoptimized: true,
  },
}
```

#### `overrideSrc`

`<Image>` コンポーネントに `src` プロパティを指定すると、生成される `<img>` 要素には、`srcset` 属性と `src` 属性が自動的に設定されます。

```jsx filename="input.js"
<Image src="/profile.jpg" />
```

```html filename="output.html"
<img
  srcset="
    /_next/image?url=%2Fprofile.jpg&w=640&q=75 1x,
    /_next/image?url=%2Fprofile.jpg&w=828&q=75 2x
  "
  src="/_next/image?url=%2Fprofile.jpg&w=828&q=75"
/>
```

場合によっては、`src` 属性が自動的に設定されることが望ましくなく、`overrideSrc` プロパティを使ってその値を上書きしたい場合があります。

たとえば、既存のウェブサイトを `<img>` から `<Image>` に移行する際、画像ランキングや再クロールの回避などの SEO 上の理由から、同じ `src` 属性を維持したいことがあります。

```jsx filename="input.js"
<Image src="/profile.jpg" overrideSrc="/override.jpg" />
```

```html filename="output.html"
<img
  srcset="
    /_next/image?url=%2Fprofile.jpg&w=640&q=75 1x,
    /_next/image?url=%2Fprofile.jpg&w=828&q=75 2x
  "
  src="/override.jpg"
/>
```

#### `decoding`

ブラウザに対して、他のコンテンツ更新を表示する前に画像のデコード完了を待つべきかどうかを示すヒントです。

```jsx
// デフォルトは async
<Image decoding="async" />
```

- `async`: 画像を非同期でデコードし、デコードが完了する前に他のコンテンツをレンダリングできるようにします。
- `sync`: 画像を同期的にデコードし、他のコンテンツと同時に一体として表示されるようにします。
- `auto`: 優先度を指定しません。ブラウザーが最適な方法を選択します。

> [`decoding` 属性](https://developer.mozilla.org/docs/Web/HTML/Element/img#decoding)の詳細については、こちらを参照してください。

`<Image />` コンポーネントに指定されたその他のプロパティは、次のものを除き、基になる `img` 要素に渡されます:

このコールバック関数は、引数として 1 つだけ、基盤となる `<img>` 要素への参照を受け取ります。

<AppOnly>

```jsx
'use client'

```

</AppOnly>

<PagesOnly>

```jsx
<Image onLoadingComplete={(img) => console.log(img.naturalWidth)} />
```

</PagesOnly>

<AppOnly>

> **補足**: 提供された関数をシリアライズするために、`onLoadingComplete` のような関数を受け取る props を使用する場合は、[Client Components](https://react.dev/reference/rsc/use-client) を使用する必要があります。

### 設定オプション

Image コンポーネントは `next.config.js` で設定できます。利用可能なオプションは次のとおりです。

#### `localPatterns`

`next.config.js` ファイルで `localPatterns` を使用して、特定のローカルパス配下の画像のみを最適化できるようにし、それ以外はすべてブロックします。

```js filename="next.config.js"
module.exports = {
  images: {
    localPatterns: [
      {
        pathname: '/assets/images/**',
        search: '',
      },
    ],
  },
}
```

上記の例では、`next/image` の `src` プロパティは必ず `/assets/images/` で始まり、かつクエリ文字列を含まない必要があります。その他のパスを最適化しようとすると、`400` Bad Request エラーが返されます。

> **補足**: `search` プロパティを省略すると、すべての検索パラメータが許可されてしまい、意図していない URL を悪意ある第三者に最適化される可能性があります。`search: '?v=2'` のように特定の値を指定して、完全一致のみ許可するようにしましょう。

#### `remotePatterns`

`next.config.js` ファイルで `remotePatterns` を使用して、特定の外部パスからの画像のみを許可し、それ以外はすべてブロックします。これにより、自分のアカウント由来の外部画像だけが配信されるようにできます。

```js filename="next.config.js"
module.exports = {
  images: {
    remotePatterns: [new URL('https://example.com/account123/**')],
  },
}
```

このオブジェクトを使用して `remotePatterns` を設定することもできます。

```js filename="next.config.js"
module.exports = {
  images: {
    remotePatterns: [
      {
        protocol: 'https',
        hostname: 'example.com',
        port: '',
        pathname: '/account123/**',
        search: '',
      },
    ],
  },
}
```

上記の例では、`next/image` の `src` プロパティは必ず `https://example.com/account123/` で始まり、クエリ文字列を含まない必要があります。その他のプロトコル、ホスト名、ポート、または一致しないパスが指定された場合は、`400` Bad Request が返されます。

**ワイルドカードパターン:**

ワイルドカードパターンは `pathname` と `hostname` の両方で使用でき、次の構文があります:

- `*` は 1 つのパスセグメントまたはサブドメインにマッチします
- `**` は末尾の任意個数のパスセグメント、または先頭のサブドメインにマッチします。この構文はパターンの途中では機能しません。

```js filename="next.config.js"
module.exports = {
  images: {
    remotePatterns: [
      {
        protocol: 'https',
        hostname: '**.example.com',
        port: '',
        search: '',
      },
    ],
  },
}
```

これにより、`image.example.com` のようなサブドメインが許可されます。クエリ文字列やカスタムポートは引き続きブロックされます。

> **補足**: `protocol`、`port`、`pathname`、`search` を省略した場合、ワイルドカードの `**` が暗黙的に指定されます。意図していない URL を悪意ある第三者に最適化の対象として利用される可能性があるため、これは推奨されません。

**クエリ文字列**:

`search` プロパティを使用して、クエリ文字列を制限することもできます。

```js filename="next.config.js"
module.exports = {
  images: {
    remotePatterns: [
      {
        protocol: 'https',
        hostname: 'assets.example.com',
        search: '?v=1727111025337',
      },
    ],
  },
}
```

上記の例では、`next/image` の `src` プロパティは必ず `https://assets.example.com` で始まり、クエリ文字列も `?v=1727111025337` と完全に一致している必要があります。これ以外のプロトコルやクエリ文字列が指定された場合は、`400` Bad Request が返されます。

#### `loaderFile`

`loaderFiles` を使用すると、Next.js の代わりに独自の画像最適化サービスを利用できます。

```js filename="next.config.js"
module.exports = {
  images: {
    loader: 'custom',
    loaderFile: './my/image/loader.js',
  },
}
```

パスはプロジェクトルートからの相対パスである必要があります。ファイルは、URL 文字列を返すデフォルト関数をエクスポートしなければなりません。

<AppOnly>
  ```js filename="my/image/loader.js"
  'use client'

export default function myImageLoader({ src, width, quality }) {
return `https://example.com/${src}?w=${width}&q=${quality || 75}`
}

````
</AppOnly>

<PagesOnly>
```js filename="my/image/loader.js"
export default function myImageLoader({ src, width, quality }) {
````

- [カスタム Image Loader の設定](/docs/app/api-reference/config/next-config-js/images#example-loader-configuration)

#### `path`

Image Optimization API のデフォルトパスを変更したりプレフィックスを付けたい場合は、`path` プロパティで設定できます。`path` のデフォルト値は `/_next/image` です。

```js filename="next.config.js"
module.exports = {
  images: {
    path: '/my-prefix/_next/image',
  },
}
```

#### `deviceSizes`

`deviceSizes` を使用すると、デバイス幅のブレークポイントのリストを指定できます。これらの幅は、ユーザーのデバイスに適した画像が配信されるよう、`next/image` コンポーネントが [`sizes`](#sizes) プロップを使用する際に参照されます。

設定が行われていない場合は、以下のデフォルト値が使用されます。

```js filename="next.config.js"
module.exports = {
  images: {
    deviceSizes: [640, 750, 828, 1080, 1200, 1920, 2048, 3840],
  },
}
```

#### `imageSizes`

`imageSizes` では、画像の幅のリストを指定できます。これらの幅は [device sizes](#devicesizes) の配列と結合され、画像の [srcset](https://developer.mozilla.org/docs/Web/API/HTMLImageElement/srcset) を生成するために使用されるサイズ配列の完全なリストを構成します。

設定を行わなかった場合は、以下のデフォルト設定が使用されます。

```js filename="next.config.js"
module.exports = {
  images: {
    imageSizes: [32, 48, 64, 96, 128, 256, 384],
  },
}
```

`imageSizes` は、画像が画面の全幅より小さいことを示す [`sizes`](#sizes) プロップが指定されている画像に対してのみ使用されます。したがって、`imageSizes` 内のサイズはすべて、`deviceSizes` の中で最も小さいサイズより小さく設定する必要があります。

#### `qualities`

`qualities` では、画像の画質の値のリストを指定できます。

設定を行わない場合は、以下のデフォルト値が使用されます。

```js filename="next.config.js"
module.exports = {
  images: {
    qualities: [75],
  },
}
```

> **参考**: このフィールドは Next.js 16 以降必須です。制限のないアクセスを許可すると、悪意のある第三者が、想定していた以上の画像品質まで最適化できてしまう可能性があります。

次のように、許可リストに追加の画像品質を追加できます:

```js filename="next.config.js"
module.exports = {
  images: {
    qualities: [25, 50, 75, 100],
  },
}
```

上記の例では、25、50、75、100 の 4 つの品質のみが許可されています。

[`quality`](#quality) プロパティがこの配列内の値と一致しない場合は、最も近い許可された値が使用されます。

REST API に、この配列内の値と一致しない品質で直接アクセスした場合、サーバーは 400 Bad Request レスポンスを返します。

#### `formats`

`formats` を使用すると、使用される画像形式のリストを指定できます。

```js filename="next.config.js"
module.exports = {
  images: {
    // デフォルト
    formats: ['image/webp'],
  },
}
```

Next.js は、リクエストの `Accept` ヘッダーからブラウザがサポートしている画像形式を自動検出し、最適な出力形式を決定します。

`Accept` ヘッダーが設定されている形式の複数にマッチする場合、配列内で最初にマッチしたものが使用されます。そのため、配列の順序は重要です。マッチするものがない場合（または元の画像がアニメーション画像である場合）、元の画像の形式が使用されます。

ブラウザが [AVIF をサポートしていない場合](https://caniuse.com/avif)、src 画像の元の形式にフォールバックする AVIF サポートを有効にできます。

```js filename="next.config.js"
module.exports = {
  images: {
    formats: ['image/avif'],
  },
}
```

AVIF と WebP の両方のフォーマットを同時に有効にすることもできます。対応しているブラウザでは AVIF が優先され、WebP がフォールバックとして使用されます。

```js filename="next.config.js"
module.exports = {
  images: {
    formats: ['image/avif', 'image/webp'],
  },
}
```

> **補足**:
>
> - ほとんどのユースケースでは、引き続き WebP の使用を推奨します。
> - AVIF は一般的にエンコードに 50% 長く時間がかかりますが、WebP と比較して 20% 小さく圧縮できます。これは、画像の初回リクエスト時は通常より遅くなりますが、キャッシュされたあとのリクエストは高速になることを意味します。
> - 複数のフォーマットを使用する場合、Next.js はフォーマットごとに個別にキャッシュします。これは、単一フォーマットのみを使用する場合と比べてストレージ要件が増加することを意味します。異なるブラウザサポートに対応するために、画像の AVIF と WebP の両方のバージョンが保存されるためです。
> - Next.js の前段にプロキシ/CDN を置いてセルフホストする場合は、プロキシ側で `Accept` ヘッダーを転送するように設定する必要があります。

#### `minimumCacheTTL`

`minimumCacheTTL` を使用すると、最適化された画像キャッシュの TTL（Time to Live、生存時間）を秒単位で設定できます。多くの場合は、[Static Image Import](/docs/app/getting-started/images#local-images) を使用するほうが適切です。こちらはファイル内容を自動的にハッシュ化し、`immutable` な `Cache-Control` ヘッダーとともに画像を永久にキャッシュします。

設定を行わなかった場合は、以下のデフォルト値が使用されます。

```js filename="next.config.js"
module.exports = {
  images: {
    minimumCacheTTL: 14400, // 4時間
  },
}
```

TTL を長く設定することで、再検証の回数を減らし、コスト削減につながる可能性があります。

```js filename="next.config.js"
module.exports = {
  images: {
    minimumCacheTTL: 2678400, // 31日
  },
}
```

最適化された画像の有効期限（正確には Max-Age）は、`minimumCacheTTL` とアップストリーム画像の `Cache-Control` ヘッダーの値のうち、大きい方で決まります。

画像ごとにキャッシュ動作を変更する必要がある場合は、[`headers`](/docs/app/api-reference/config/next-config-js/headers) を設定して、アップストリーム画像（例: `/some-asset.jpg`。`/_next/image` 自体ではありません）に対して `Cache-Control` ヘッダーを指定できます。

現時点ではキャッシュを無効化する仕組みはないため、`minimumCacheTTL` は低めに設定しておくことを推奨します。そうしない場合、[`src`](#src) プロパティを手動で変更するか、キャッシュされたファイル `<distDir>/cache/images` を削除する必要が出てくるかもしれません。

#### `disableStaticImages`

`disableStaticImages` を使用すると、静的画像のインポートを無効にできます。

デフォルトの挙動では、`import icon from './icon.png'` のように静的ファイルをインポートし、それを `src` プロパティに渡すことができます。場合によっては、このインポートの挙動が異なることを前提としている他のプラグインと競合するため、この機能を無効にしたいことがあります。

`next.config.js` 内で静的画像のインポートを無効にできます:

```js filename="next.config.js"
module.exports = {
  images: {
    disableStaticImages: true,
  },
}
```

#### `maximumRedirects`

デフォルトの画像最適化ローダーは、リモート画像を取得する際に、HTTP リダイレクトを最大 3 回までフォローします。

```js filename="next.config.js"
module.exports = {
  images: {
    maximumRedirects: 3,
  },
}
```

リモート画像の取得時に、何回までリダイレクトをたどるかを設定できます。値を `0` に設定すると、リダイレクトの追跡が無効になります。

```js filename="next.config.js"
module.exports = {
  images: {
    maximumRedirects: 0,
  },
}
```

#### `maximumDiskCacheSize`

デフォルトの画像最適化ローダーは、最適化済み画像をディスクに書き込み、以降のリクエストをディスクキャッシュからより高速に配信できるようにします。

ディスクキャッシュの最大サイズをバイト単位で設定できます。たとえば 500 MB のように指定します。

```js filename="next.config.js"
module.exports = {
  images: {
    maximumDiskCacheSize: 500_000_000,
  },
}
```

値を `0` に設定すると、ディスク キャッシュを完全に無効にできます。

```js filename="next.config.js"
module.exports = {
  images: {
    maximumDiskCacheSize: 0,
  },
}
```

値が設定されていない場合、デフォルトでは、起動時に一度だけ現在利用可能なディスク容量を確認し、その 50% を上限として使用します。

ディスクキャッシュが設定されたサイズを超えた場合、キャッシュが再び上限未満になるまで、最も最近使用されていない最適化済み画像から順に削除されます。

または、[`cacheHandler`](/docs/app/api-reference/config/next-config-js/incrementalCacheHandlerPath) を使用して独自のキャッシュハンドラーを実装することもでき、その場合は `maximumDiskCacheSize` 設定は無視されます。

#### `maximumResponseBody`

デフォルトの画像最適化ローダーは、サイズが最大 50 MB のソース画像を取得します。

```js filename="next.config.js"
module.exports = {
  images: {
    maximumResponseBody: 50_000_000,
  },
}
```

すべてのソース画像が小さいことを把握している場合は、この値を 5 MB などのより小さな値に下げることで、メモリ制約のあるサーバーを保護できます。

```js filename="next.config.js"
module.exports = {
  images: {
    maximumResponseBody: 5_000_000,
  },
}
```

#### `dangerouslyAllowLocalIP`

プライベートネットワーク上で Next.js をセルフホストしているなどのまれなケースでは、同一ネットワーク上のローカル IP アドレスからの画像最適化を許可したい場合があります。これは、悪意のあるユーザーが内部ネットワーク上のコンテンツにアクセスできてしまう可能性があるため、ほとんどのユーザーには推奨されません。

デフォルトでは、この値は false です。

```js filename="next.config.js"
module.exports = {
  images: {
    dangerouslyAllowLocalIP: false,
  },
}
```

ローカルネットワーク内の別のホストで配信されているリモート画像を最適化する必要がある場合は、この値を true に設定します。

```js filename="next.config.js"
module.exports = {
  images: {
    dangerouslyAllowLocalIP: true,
  },
}
```

#### `dangerouslyAllowSVG`

`dangerouslyAllowSVG` は、SVG 画像の配信を許可します。

```js filename="next.config.js"
module.exports = {
  images: {
    dangerouslyAllowSVG: true,
  },
}
```

デフォルトでは、Next.js はいくつかの理由から SVG 画像を最適化しません:

- SVG はベクター形式であり、劣化なくリサイズできます。
- SVG は HTML/CSS と共通する機能が多く、適切な [Content Security Policy (CSP) ヘッダー](/docs/app/api-reference/config/next-config-js/headers#content-security-policy) がないと脆弱性につながる可能性があります。

[`src`](#src) プロップが SVG であることがわかっている場合は、[`unoptimized`](#unoptimized) プロップを使用することを推奨します。これは、`src` が `".svg"` で終わる場合には自動的に判断されます。

```jsx
<Image src="/my-image.svg" unoptimized />
```

さらに、ブラウザに画像のダウンロードを強制するために `contentDispositionType` を、画像に埋め込まれたスクリプトが実行されないようにするために `contentSecurityPolicy` も設定しておくことを強く推奨します。

```js filename="next.config.js"
module.exports = {
  images: {
    dangerouslyAllowSVG: true,
    contentDispositionType: 'attachment',
    contentSecurityPolicy: "default-src 'self'; script-src 'none'; sandbox;",
  },
}
```

#### `contentDispositionType`

`contentDispositionType` を使用すると、[`Content-Disposition`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/Content-Disposition#as_a_response_header_for_the_main_body) ヘッダーを設定できます。

```js filename="next.config.js"
module.exports = {
  images: {
    contentDispositionType: 'inline',
  },
}
```

#### `contentSecurityPolicy`

`contentSecurityPolicy` を使用すると、画像用の [`Content-Security-Policy`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CSP) ヘッダーを設定できます。これは、画像内に埋め込まれたスクリプトの実行を防ぐために [`dangerouslyAllowSVG`](#dangerouslyallowsvg) を使用する場合に特に重要です。

```js filename="next.config.js"
module.exports = {
  images: {
    contentSecurityPolicy: "default-src 'self'; script-src 'none'; sandbox;",
  },
}
```

デフォルトでは、[loader](#loader) は API が任意のリモート画像を配信できるため、追加の保護として [`Content-Disposition`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/Content-Disposition#as_a_response_header_for_the_main_body) ヘッダーを `attachment` に設定します。

デフォルト値は `attachment` であり、画像に直接アクセスした際にブラウザに画像のダウンロードを強制します。これは特に [`dangerouslyAllowSVG`](#dangerouslyallowsvg) が true の場合に重要です。

任意で `inline` を設定すると、画像に直接アクセスした際にブラウザがダウンロードせずに画像を表示できるようになります。

### 非推奨となった設定オプション

#### `domains`

> **警告**: 悪意のあるユーザーからアプリケーションを保護するため、Next.js 14 以降ではより厳密な [`remotePatterns`](#remotepatterns) の使用が推奨されており、このオプションは非推奨になりました。

[`remotePatterns`](#remotepatterns) と同様に、`domains` 設定は外部画像に対して許可するホスト名のリストを指定するために使用できます。ただし、`domains` 設定はワイルドカードによるパターンマッチングをサポートせず、プロトコル、ポート、またはパス名を制限することもできません。

ほとんどのリモート画像サーバーは複数のテナント間で共有されるため、意図した画像のみが最適化されるようにするには `remotePatterns` を使用する方が安全です。

以下は、`next.config.js` ファイル内の `domains` プロパティの例です：

```js filename="next.config.js"
module.exports = {
  images: {
    domains: ['assets.acme.com'],
  },
}
```

## 関数

### `getImageProps`

`getImageProps` 関数は、基盤となる `<img>` 要素に渡される props を取得し、それらを別のコンポーネントやスタイル、canvas などに渡すために使用できます。

```jsx
import { getImageProps } from 'next/image'

const { props } = getImageProps({
  src: 'https://example.com/image.jpg',
  alt: 'A scenic mountain view',
  width: 1200,
  height: 800,
})

function ImageWithCaption() {
  return (
    <figure>
      <img {...props} />
      <figcaption>A scenic mountain view</figcaption>
    </figure>
  )
}
```

これにより React の `useState()` を呼び出さずに済むため、パフォーマンスの向上につながる可能性もありますが、プレースホルダーが決して削除されないため、[`placeholder`](#placeholder) プロパティとは併用できません。

## 既知のブラウザバグ

この `next/image` コンポーネントはブラウザのネイティブな[遅延読み込み](https://caniuse.com/loading-lazy-attr)を使用しており、Safari 15.4 より前の古いブラウザでは eager loading にフォールバックする場合があります。ぼかしプレースホルダーを使用している場合、Safari 12 より前の古いブラウザでは空のプレースホルダーにフォールバックします。`width`/`height` に `auto` を指定したスタイルを使用している場合、アスペクト比を[保持しない](https://caniuse.com/mdn-html_elements_img_aspect_ratio_computed_from_attributes) Safari 15 より前の古いブラウザでは[レイアウトシフト](https://web.dev/cls/)を引き起こす可能性があります。詳細は[この MDN の動画](https://www.youtube.com/watch?v=4-d_SoCHeWE)を参照してください。

- [Safari 15 - 16.3](https://bugs.webkit.org/show_bug.cgi?id=243601) は読み込み中に灰色のボーダーを表示します。Safari 16.4 で[この問題は修正されました](https://webkit.org/blog/13966/webkit-features-in-safari-16-4/#:~:text=Now%20in%20Safari%2016.4%2C%20a%20gray%20line%20no%20longer%20appears%20to%20mark%20the%20space%20where%20a%20lazy%2Dloaded%20image%20will%20appear%20once%20it%E2%80%99s%20been%20loaded.)。考えられる対処方法:
  - 次の CSS を使用する: `@supports (font: -apple-system-body) and (-webkit-appearance: none) { img[loading="lazy"] { clip-path: inset(0.6px) } }`
  - 画像がファーストビュー内にある場合は [`loading="eager"`](#loading) を使用する
- [Firefox 67+](https://bugzilla.mozilla.org/show_bug.cgi?id=1556156) は読み込み中に白い背景を表示します。考えられる対処方法:
  - [AVIF `formats`](#formats) を有効にする
  - [`placeholder`](#placeholder) を使用する

## 例

### 画像のスタイリング

Image コンポーネントのスタイリングは、通常の `<img>` 要素のスタイリングとほぼ同じですが、いくつか守るべきガイドラインがあります。

`styled-jsx` ではなく、`className` か `style` を使用してください。ほとんどの場合は、`className` プロパティを使うことを推奨します。ここには、インポートした [CSS Module](/docs/app/getting-started/css) や [グローバルスタイルシート](/docs/app/getting-started/css#global-css) などを指定できます。

```jsx
import styles from './styles.module.css'

export default function MyImage() {
  return <Image className={styles.image} src="/my-image.png" alt="My Image" />
}
```

`style` props を使用してインラインスタイルを適用することもできます。

```jsx
export default function MyImage() {
  return (
    <Image style={{ borderRadius: '8px' }} src="/my-image.png" alt="My Image" />
  )
}
```

`fill` を使用する場合、親要素には `position: relative` または `display: block` のいずれかを指定する必要があります。これは、このレイアウトモードで画像要素が正しくレンダリングされるために必要です。

```jsx
<div style={{ position: 'relative' }}>
  <Image fill src="/my-image.png" alt="My Image" />
</div>
```

[styled-jsx](/docs/app/guides/css-in-js) は、スタイルを `global` としてマークしない限り、そのコンポーネントにのみスコープされるため使用できません。

### 静的エクスポートでのレスポンシブ画像

静的画像をインポートすると、Next.js はファイルに基づいて自動的に幅と高さを設定します。`style` を設定することで、画像をレスポンシブにできます:

<Image
  alt="親コンテナの幅と高さいっぱいに表示されるレスポンシブ画像"
  srcLight="/docs/light/responsive-image.png"
  srcDark="/docs/dark/responsive-image.png"
  width="1600"
  height="629"
/>

```jsx
import Image from 'next/image'
import mountains from '../public/mountains.jpg'

export default function Responsive() {
  return (
    <div style={{ display: 'flex', flexDirection: 'column' }}>
      <Image
        alt="Mountains"
        // 画像をインポートすると
        // 自動的に幅と高さが設定される
        src={mountains}
        sizes="100vw"
        // 画像を全幅で表示し
        // アスペクト比を維持する
        style={{
          width: '100%',
          height: 'auto',
        }}
      />
    </div>
  )
}
```

### リモート URL を使ったレスポンシブ画像

ソース画像が動的またはリモートの URL の場合、Next.js がアスペクト比を計算できるようにするため、`width` と `height` の props を必ず指定する必要があります。

```jsx filename="components/page.js"
import Image from 'next/image'

export default function Page({ photoUrl }) {
  return (
    <Image
      src={photoUrl}
      alt="Picture of the author"
      sizes="100vw"
      style={{
        width: '100%',
        height: 'auto',
      }}
      width={500}
      height={300}
    />
  )
}
```

### `fill` を使ったレスポンシブ画像

画像のアスペクト比が不明な場合は、[`fill` prop](#fill) を追加し、`objectFit` prop を `cover` に設定します。これにより、画像が親コンテナの幅いっぱいに表示されます。

<Image
  alt="親コンテナの幅いっぱいに表示された画像グリッド"
  srcLight="/docs/light/fill-container.png"
  srcDark="/docs/dark/fill-container.png"
  width="1600"
  height="529"
/>

```jsx
import Image from 'next/image'
import mountains from '../public/mountains.jpg'

export default function Fill() {
  return (
    <div
      style={{
        display: 'grid',
        gridGap: '8px',
        gridTemplateColumns: 'repeat(auto-fit, minmax(400px, auto))',
      }}
    >
      <div style={{ position: 'relative', width: '400px' }}>
        <Image
          alt="Mountains"
          src={mountains}
          fill
          sizes="(min-width: 808px) 50vw, 100vw"
          style={{
            objectFit: 'cover', // cover, contain, none
          }}
        />
      </div>
      {/* グリッド内のその他の画像... */}
    </div>
  )
}
```

### リモート画像

リモート画像を使用するには、`src` プロパティに URL 文字列を指定します。

```jsx filename="app/page.js"
import Image from 'next/image'

export default function Page() {
  return (
    <Image
      src="https://s3.amazonaws.com/my-bucket/profile.png"
      alt="Picture of the author"
      width={500}
      height={500}
    />
  )
}
```

Next.js はビルド処理中にリモートファイルへアクセスできないため、[`width`](/docs/app/api-reference/components/image#width-and-height)、[`height`](/docs/app/api-reference/components/image#width-and-height)、およびオプションの [`blurDataURL`](/docs/app/api-reference/components/image#blurdataurl) props を手動で指定する必要があります。

`width` と `height` 属性は、画像の正しいアスペクト比を推定し、画像の読み込みによるレイアウトシフトを防ぐために使用されます。`width` と `height` は、画像ファイルの実際の表示サイズを決定するものでは _ありません_。

画像を安全に最適化できるようにするには、`next.config.js` 内でサポートする URL パターンのリストを定義します。悪用を防ぐため、可能な限り具体的に指定してください。たとえば、次の設定では、特定の AWS S3 バケットからの画像のみが許可されます。

```js filename="next.config.js"
module.exports = {
  images: {
    remotePatterns: [
      {
        protocol: 'https',
        hostname: 's3.amazonaws.com',
        port: '',
        pathname: '/my-bucket/**',
        search: '',
      },
    ],
  },
}
```

### テーマ検出

ライトモードとダークモードで異なる画像を表示したい場合は、2つの `<Image>` コンポーネントをラップする新しいコンポーネントを作成し、CSS メディアクエリに基づいて適切な方を表示できるようにします。

```css filename="components/theme-image.module.css"
.imgDark {
  display: none;
}

@media (prefers-color-scheme: dark) {
  .imgLight {
    display: none;
  }
  .imgDark {
    display: unset;
  }
}
```

```tsx filename="components/theme-image.tsx" switcher
import styles from './theme-image.module.css'
import Image, { ImageProps } from 'next/image'

type Props = Omit<ImageProps, 'src' | 'preload' | 'loading'> & {
  srcLight: string
  srcDark: string
}

const ThemeImage = (props: Props) => {
  const { srcLight, srcDark, ...rest } = props

  return (
    <>
      <Image {...rest} src={srcLight} className={styles.imgLight} />
      <Image {...rest} src={srcDark} className={styles.imgDark} />
    </>
  )
}
```

```jsx filename="components/theme-image.js" switcher
import styles from './theme-image.module.css'
import Image from 'next/image'

const ThemeImage = (props) => {
  const { srcLight, srcDark, ...rest } = props

  return (
    <>
      <Image {...rest} src={srcLight} className={styles.imgLight} />
      <Image {...rest} src={srcDark} className={styles.imgDark} />
    </>
  )
}
```

> **補足**: `loading="lazy"` のデフォルトの挙動により、表示対象の画像のみが読み込まれます。両方の画像が読み込まれてしまうため、`preload` や `loading="eager"` は使用できません。代わりに [`fetchPriority="high"`](https://developer.mozilla.org/docs/Web/API/HTMLImageElement/fetchPriority) を使用できます。

### アートディレクション

モバイルとデスクトップで異なる画像を表示したい場合（[Art Direction](https://developer.mozilla.org/en-US/docs/Learn/HTML/Multimedia_and_embedding/Responsive_images#art_direction) と呼ばれることもあります）、`getImageProps()` に `src`、`width`、`height`、`quality` それぞれに異なる props を渡すことができます。

```jsx filename="app/page.js"
import { getImageProps } from 'next/image'

export default function Home() {
  const common = { alt: 'Art Direction Example', sizes: '100vw' }
  const {
    props: { srcSet: desktop },
  } = getImageProps({
    ...common,
    width: 1440,
    height: 875,
    quality: 80,
    src: '/desktop.jpg',
  })
  const {
    props: { srcSet: mobile, ...rest },
  } = getImageProps({
    ...common,
    width: 750,
    height: 1334,
    quality: 70,
    src: '/mobile.jpg',
  })

  return (
    <picture>
      <source media="(min-width: 1000px)" srcSet={desktop} />
      <source media="(min-width: 500px)" srcSet={mobile} />
      <img {...rest} style={{ width: '100%', height: 'auto' }} />
    </picture>
  )
}
```

### 背景の CSS

`srcSet` 文字列を [`image-set()`](https://developer.mozilla.org/en-US/docs/Web/CSS/image/image-set) CSS 関数に変換して、背景画像を最適化することもできます。

```jsx filename="app/page.js"
import { getImageProps } from 'next/image'

function getBackgroundImage(srcSet = '') {
  const imageSet = srcSet
    .split(', ')
    .map((str) => {
      const [url, dpi] = str.split(' ')
      return `url("${url}") ${dpi}`
    })
    .join(', ')
  return `image-set(${imageSet})`
}

export default function Home() {
  const {
    props: { srcSet },
  } = getImageProps({ alt: '', width: 128, height: 128, src: '/img.png' })
  const backgroundImage = getBackgroundImage(srcSet)
  const style = { height: '100vh', width: '100vw', backgroundImage }

  return (
    <main style={style}>
      <h1>Hello World</h1>
    </main>
  )
}
```
