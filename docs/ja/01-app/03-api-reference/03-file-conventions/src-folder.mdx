プロジェクトのルートに Next.js 固有の `app` または `pages` ディレクトリを置く代わりに、アプリケーションコードを `src` フォルダ配下に配置するという一般的なパターンも Next.js ではサポートされています。

これにより、プロジェクトのルートに置かれることが多い設定ファイルとアプリケーションコードを分離できます。この構成を好む開発者やチームもいます。

`src` フォルダを使用するには、`app` ルーター用フォルダまたは `pages` ルーター用フォルダを、それぞれ `src/app` もしくは `src/pages` に移動します。

> **補足**:
>
> - `/public` ディレクトリはプロジェクトのルートに残しておく必要があります。
> - `package.json`、`next.config.js`、`tsconfig.json` などの設定ファイルはプロジェクトのルートに残しておく必要があります。
> - `.env.*` ファイルはプロジェクトのルートに残しておく必要があります。
> - ルートディレクトリに `app` または `pages` が存在する場合、`src/app` または `src/pages` は無視されます。
> - `src` を使用している場合、`/components` や `/lib` などの他のアプリケーション用フォルダも同様に移動することが多いでしょう。
> - Proxy を使用している場合は、`src` フォルダ内に配置されていることを確認してください。
> - Tailwind CSS を使用している場合は、[content セクション](https://tailwindcss.com/docs/content-configuration)内の `tailwind.config.js` ファイルでパスに `/src` プレフィックスを追加する必要があります。
> - `@/*` のような TypeScript のパスインポートを使用している場合は、`tsconfig.json` 内の `paths` オブジェクトを更新し、`src/` を含める必要があります。
