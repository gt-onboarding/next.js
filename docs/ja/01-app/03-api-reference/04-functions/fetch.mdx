Next.js は [Web `fetch()` API](https://developer.mozilla.org/docs/Web/API/Fetch_API) を拡張し、サーバー上の各リクエストが永続キャッシュと再検証のポリシーをそれぞれ設定できるようにします。

ブラウザでは、`cache` オプションは fetch リクエストが _ブラウザ_ の HTTP キャッシュとどのようにやり取りするかを示します。この拡張により、`cache` は _サーバー側_ の fetch リクエストがフレームワークの永続的な [Data Cache](/docs/app/guides/caching#data-cache) とどのようにやり取りするかを示します。

サーバーコンポーネント内では、`async` と `await` を使って `fetch` を直接呼び出すことができます。

```tsx filename="app/page.tsx" switcher
export default async function Page() {
  let data = await fetch('https://api.vercel.app/blog')
  let posts = await data.json()
  return (
    <ul>
      {posts.map((post) => (
        <li key={post.id}>{post.title}</li>
      ))}
    </ul>
  )
}
```

```jsx filename="app/page.js" switcher
export default async function Page() {
  let data = await fetch('https://api.vercel.app/blog')
  let posts = await data.json()
  return (
    <ul>
      {posts.map((post) => (
        <li key={post.id}>{post.title}</li>
      ))}
    </ul>
  )
}
```

## `fetch(url, options)`

Next.js は [Web `fetch()` API](https://developer.mozilla.org/docs/Web/API/Fetch_API) を拡張しているため、[用意されている標準のオプション](https://developer.mozilla.org/docs/Web/API/fetch#parameters)をそのまま利用できます。

### `options.cache`

リクエストが Next.js の [Data Cache](/docs/app/guides/caching#data-cache) とどのようにやり取りするかを設定します。

```ts
fetch(`https://...`, { cache: 'force-cache' | 'no-store' })
```

- **`auto no cache`** (デフォルト): 開発環境では、Next.js はリクエストごとにリモートサーバーからリソースを取得しますが、ルートが静的に事前レンダリングされるため、`next build` 時には 1 回だけ取得します。ルートで [Dynamic APIs](/docs/app/guides/caching#dynamic-rendering) が検出された場合、Next.js はリクエストごとにリソースを取得します。
- **`no-store`**: ルートで Dynamic APIs が検出されていない場合でも、Next.js はリクエストごとにリモートサーバーからリソースを取得します。
- **`force-cache`**: Next.js は Data Cache 内で一致するリクエストを探します。
  - 一致があり、かつまだ有効な場合は、そのキャッシュが返されます。
  - 一致がない、またはキャッシュが古い場合、Next.js はリモートサーバーからリソースを取得し、ダウンロードしたリソースでキャッシュを更新します。

### `options.next.revalidate`

```ts
fetch(`https://...`, { next: { revalidate: false | 0 | number } })
```

リソースのキャッシュ有効期間（秒）を設定します。[データキャッシュ](/docs/app/guides/caching#data-cache)。

- **`false`** - リソースを無期限にキャッシュします。意味的には `revalidate: Infinity` と同等です。HTTP キャッシュは時間の経過とともに古いリソースを破棄する可能性があります。
- **`0`** - リソースがキャッシュされないようにします。
- **`number`** - （秒）リソースのキャッシュ有効期間が最大で `n` 秒になるように指定します。

> **補足**:
>
> - 個々の `fetch()` リクエストで、ルートの[デフォルトの `revalidate`](/docs/app/api-reference/file-conventions/route-segment-config#revalidate) より小さい `revalidate` 値を設定した場合、ルート全体の再検証間隔は短くなります。
> - 同じルート内で同じ URL を持つ 2 つの `fetch()` リクエストに異なる `revalidate` 値が指定されている場合、小さい方の値が使用されます。
> - `{ revalidate: 3600, cache: 'no-store' }` のような矛盾するオプションは許可されず、両方とも無視されます。開発モードでは、警告がターミナルに出力されます。

### `options.next.tags`

```ts
fetch(`https://...`, { next: { tags: ['collection'] } })
```

リソースのキャッシュタグを設定します。データは [`revalidateTag`](/docs/app/api-reference/functions/revalidateTag) を使用してオンデマンドで再検証できます。カスタムタグの最大長は 256 文字、タグの最大数は 128 です。

## トラブルシューティング

### デフォルトの `auto no store` および `cache: 'no-store'` を使った `fetch` が開発環境で最新データを表示しない

Next.js はローカル開発環境において、高速なレスポンスを実現し、従量課金の API コールにかかるコストを削減するために、サーバーコンポーネント内の `fetch` レスポンスをホットモジュールリプレースメント (HMR) をまたいでキャッシュします。

デフォルトでは、[HMR キャッシュ](/docs/app/api-reference/config/next-config-js/serverComponentsHmrCache) は、デフォルトの `auto no cache` および `cache: 'no-store'` オプションを含む、すべての fetch リクエストに適用されます。これは、キャッシュされていないリクエストであっても、HMR によるリフレッシュの間は最新データが表示されないことを意味します。ただし、ナビゲーションやページ全体の再読み込みを行うと、キャッシュはクリアされます。

詳しくは、[`serverComponentsHmrCache`](/docs/app/api-reference/config/next-config-js/serverComponentsHmrCache) のドキュメントを参照してください。

### 開発環境でのハードリフレッシュとキャッシュ

開発モードでは、リクエストに `cache-control: no-cache` ヘッダーが含まれている場合、`options.cache`、`options.next.revalidate`、`options.next.tags` は無視され、`fetch` リクエストはソースから直接返されます。

ブラウザは、開発者ツールでキャッシュを無効化している場合やハードリフレッシュ時に、通常 `cache-control: no-cache` を送信します。
