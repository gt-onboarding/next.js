`metadata` オブジェクトまたは `generateMetadata` 関数を使用してメタデータを定義できます。

## `metadata` オブジェクト

静的メタデータを定義するには、`layout.js` または `page.js` ファイルから [`Metadata` オブジェクト](#metadata-fields) をエクスポートします。

```tsx filename="layout.tsx | page.tsx" switcher
import type { Metadata } from 'next'

export const metadata: Metadata = {
  title: '...',
  description: '...',
}

export default function Page() {}
```

```jsx filename="layout.js | page.js" switcher
export const metadata = {
  title: '...',
  description: '...',
}

export default function Page() {}
```

> サポートされているオプションの一覧については、[Metadata Fields](#metadata-fields) を参照してください。

## `generateMetadata` 関数

動的メタデータは、現在のルートパラメータ、外部データ、または親セグメントの `metadata` などの**動的な情報**に依存します。これらは、[`Metadata` オブジェクト](#metadata-fields)を返す `generateMetadata` 関数をエクスポートすることで設定できます。

`generateMetadata` の評価はページのレンダリング処理の一部です。ページをプリレンダリングでき、かつ `generateMetadata` が動的な挙動を追加しない場合、生成されたメタデータはページの初期 HTML に含まれます。

それ以外の場合、`generateMetadata` から解決されたメタデータは、初期 UI の送信後に[ストリーミングすることができます](/docs/app/api-reference/functions/generate-metadata#streaming-metadata)。

```tsx filename="app/products/[id]/page.tsx" switcher
import type { Metadata, ResolvingMetadata } from 'next'

type Props = {
  params: Promise<{ id: string }>
  searchParams: Promise<{ [key: string]: string | string[] | undefined }>
}

export async function generateMetadata(
  { params, searchParams }: Props,
  parent: ResolvingMetadata
): Promise<Metadata> {
  // ルートパラメータを読み取る
  const { id } = await params

  // データを取得する
  const product = await fetch(`https://.../${id}`).then((res) => res.json())

  // 親メタデータに（上書きではなく）任意でアクセスして拡張する
  const previousImages = (await parent).openGraph?.images || []

  return {
    title: product.title,
    openGraph: {
      images: ['/some-specific-page-image.jpg', ...previousImages],
    },
  }
}

export default function Page({ params, searchParams }: Props) {}
```

```jsx filename="app/products/[id]/page.js" switcher
export async function generateMetadata({ params, searchParams }, parent) {
  // ルートパラメータを読み取る
  const { id } = await params

  // データを取得する
  const product = await fetch(`https://.../${id}`).then((res) => res.json())

  // 親メタデータに任意でアクセスして拡張する（置き換えではなく）
  const previousImages = (await parent).openGraph?.images || []

  return {
    title: product.title,
    openGraph: {
      images: ['/some-specific-page-image.jpg', ...previousImages],
    },
  }
}

export default function Page({ params, searchParams }) {}
```

`params` と `searchParams` の型補完を行うには、最初の引数に対して、ページには [`PageProps<'/route'>`](/docs/app/api-reference/file-conventions/page#page-props-helper)、レイアウトには [`LayoutProps<'/route'>`](/docs/app/api-reference/file-conventions/layout#layout-props-helper) を指定できます。

> **補足**:
>
> - メタデータは `layout.js` および `page.js` ファイルに追加できます。
> - Next.js はメタデータを自動的に解決し、ページに対応する `<head>` タグを作成します。
> - `metadata` オブジェクトと `generateMetadata` 関数のエクスポートは、**サーバーコンポーネントでのみサポート**されます。
> - 同じルートセグメントから `metadata` オブジェクトと `generateMetadata` 関数の両方をエクスポートすることはできません。
> - `generateMetadata` 内の `fetch` リクエストは、`generateMetadata`、`generateStaticParams`、レイアウト、ページ、およびサーバーコンポーネント間で同じデータに対して自動的に[メモ化](/docs/app/guides/caching#request-memoization)されます。
> - `fetch` が利用できない場合は、React の [`cache` を使用](/docs/app/guides/caching#react-cache-function)できます。
> - [ファイルベースのメタデータ](/docs/app/api-reference/file-conventions/metadata)の優先順位が高く、`metadata` オブジェクトと `generateMetadata` 関数を上書きします。

## なぜ `generateMetadata` はサーバーコンポーネント専用なのか

`generateMetadata` と `metadata` エクスポートは、メタデータをページコンポーネントのレンダリング前にサーバー上で解決する必要があるため、サーバーコンポーネントでのみサポートされています。これにより、Next.js は初期 HTML レスポンスにメタデータを含めることができます。

クライアントコンポーネントの機能を利用する必要がある場合は、`page.tsx` はサーバーコンポーネントのままにし、クライアントコンポーネントのロジックを別ファイルに分離してください。

```tsx filename="app/page.tsx" switcher
import type { Metadata } from 'next'
import { InteractiveComponent } from './interactive-component'

export const metadata: Metadata = {
  title: 'My Page',
}

export default function Page() {
  return <InteractiveComponent />
}
```

```jsx filename="app/page.js" switcher
import { InteractiveComponent } from './interactive-component'

export const metadata = {
  title: 'My Page',
}

export default function Page() {
  return <InteractiveComponent />
}
```

```tsx filename="app/interactive-component.tsx" switcher
'use client'

export function InteractiveComponent() {
  // クライアントサイドのインタラクティブ機能（フック、イベントハンドラーなど）
}
```

```jsx filename="app/interactive-component.js" switcher
'use client'

export function InteractiveComponent() {
  // クライアントサイドのインタラクティブ機能（フック、イベントハンドラーなど）
}
```

## リファレンス

### パラメーター

`generateMetadata` 関数は次のパラメーターを受け取ります:

- `props` - 現在のルートのパラメーターを含むオブジェクト:
  - `params` - ルートの先頭セグメントから、`generateMetadata` が呼び出されるセグメントまでの[動的ルートパラメーター](/docs/app/api-reference/file-conventions/dynamic-routes)オブジェクトを含むオブジェクト。例:

    | Route                           | URL         | `params`                  |
    | ------------------------------- | ----------- | ------------------------- |
    | `app/shop/[slug]/page.js`       | `/shop/1`   | `{ slug: '1' }`           |
    | `app/shop/[tag]/[item]/page.js` | `/shop/1/2` | `{ tag: '1', item: '2' }` |
    | `app/shop/[...slug]/page.js`    | `/shop/1/2` | `{ slug: ['1', '2'] }`    |

  - `searchParams` - 現在の URL の[検索パラメーター](https://developer.mozilla.org/docs/Learn/Common_questions/What_is_a_URL#parameters)を含むオブジェクト。例:

    | URL             | `searchParams`       |
    | --------------- | -------------------- |
    | `/shop?a=1`     | `{ a: '1' }`         |
    | `/shop?a=1&b=2` | `{ a: '1', b: '2' }` |
    | `/shop?a=1&a=2` | `{ a: ['1', '2'] }`  |

- `parent` - 親ルートセグメントから解決されたメタデータを表す Promise。

### 戻り値

`generateMetadata` は、1 つ以上のメタデータフィールドを含む [`Metadata` オブジェクト](#metadata-fields) を返す必要があります。

> **補足**:
>
> - メタデータが実行時情報に依存しない場合は、`generateMetadata` ではなく静的な [`metadata` オブジェクト](#the-metadata-object) で定義してください。
> - 同じデータに対する `generateMetadata`、`generateStaticParams`、レイアウト、ページ、およびサーバーコンポーネント間で行われる `fetch` リクエストは、自動的に[メモ化](/docs/app/guides/caching#request-memoization)されます。`fetch` が使用できない場合は、React の [`cache` を使用](/docs/app/guides/caching#react-cache-function)できます。
> - `searchParams` は `page.js` セグメントでのみ利用可能です。
> - Next.js の [`redirect()`](/docs/app/api-reference/functions/redirect) と [`notFound()`](/docs/app/api-reference/functions/not-found) メソッドも `generateMetadata` 内で使用できます。

### メタデータフィールド

以下のフィールドがサポートされています:

#### `title`

`title` 属性はドキュメントのタイトルを設定するために使用されます。シンプルな [string](#string) またはオプションの [template object](#template) として定義できます。

##### 文字列

```jsx filename="layout.js | page.js"
export const metadata = {
  title: 'Next.js',
}
```

```html filename="<head> output" hideLineNumbers
<title>Next.js</title>
```

##### `default`

`title.default` は、`title` が定義されていない子ルートセグメントに対して使用できる **フォールバック用のタイトル** です。

```tsx filename="app/layout.tsx"
import type { Metadata } from 'next'

export const metadata: Metadata = {
  title: {
    default: 'Acme',
  },
}
```

```tsx filename="app/about/page.tsx"
import type { Metadata } from 'next'

export const metadata: Metadata = {}

// 出力: <title>Acme</title>
```

##### `template`

`title.template` は、**子**ルートセグメントで定義された `titles` に接頭辞や接尾辞を追加できます。

```tsx filename="app/layout.tsx" switcher
import type { Metadata } from 'next'

export const metadata: Metadata = {
  title: {
    template: '%s | Acme',
    default: 'Acme', // テンプレートを使用する場合、defaultは必須です
  },
}
```

```jsx filename="app/layout.js" switcher
export const metadata = {
  title: {
    template: '%s | Acme',
    default: 'Acme', // テンプレートを作成する際はデフォルト値が必要
  },
}
```

```tsx filename="app/about/page.tsx" switcher
import type { Metadata } from 'next'

export const metadata: Metadata = {
  title: 'About',
}

// 出力: <title>About | Acme</title>
```

```jsx filename="app/about/page.js" switcher
export const metadata = {
  title: 'About',
}

// Output: <title>About | Acme</title>
```

> **補足**:
>
> - `title.template` は、そのプロパティが定義されているルートセグメント **自身ではなく、その子** ルートセグメントに適用されます。つまり、次のとおりです。
>   - `title.template` を追加する場合は、`title.default` が **必須** です。
>   - `layout.js` で定義された `title.template` は、同じルートセグメント内の `page.js` で定義された `title` には適用されません。
>   - `page.js` で定義された `title.template` は、ページが常に終端のセグメント（子ルートセグメントを持たない）であるため、効果がありません。
> - ルートで `title` または `title.default` が定義されていない場合、`title.template` は **何の効果もありません**。

##### `absolute`

`title.absolute` は、親セグメントで設定された `title.template` を**無視して**タイトルを指定するために使用できます。

```tsx filename="app/layout.tsx" switcher
import type { Metadata } from 'next'

export const metadata: Metadata = {
  title: {
    template: '%s | Acme',
  },
}
```

```jsx filename="app/layout.js" switcher
export const metadata = {
  title: {
    template: '%s | Acme',
  },
}
```

```tsx filename="app/about/page.tsx" switcher
import type { Metadata } from 'next'

export const metadata: Metadata = {
  title: {
    absolute: 'About',
  },
}

// 出力: <title>About</title>
```

```jsx filename="app/about/page.js" switcher
export const metadata = {
  title: {
    absolute: 'About',
  },
}

// Output: <title>About</title>
```

> **補足**:
>
> - `layout.js`
>   - `title` (string) と `title.default` は、独自の `title` を定義していない子セグメントのデフォルトタイトルを定義します。存在する場合は、最も近い親セグメントの `title.template` と組み合わされます。
>   - `title.absolute` は子セグメントのデフォルトタイトルを定義します。親セグメントの `title.template` は無視されます。
>   - `title.template` は子セグメント用の新しいタイトルテンプレートを定義します。
> - `page.js`
>   - ページが自身のタイトルを定義していない場合、最も近い親の解決済みタイトルが使用されます。
>   - `title` (string) はルートのタイトルを定義します。存在する場合は、最も近い親セグメントの `title.template` と組み合わされます。
>   - `title.absolute` はルートタイトルを定義します。親セグメントの `title.template` は無視されます。
>   - ページは常にルートの終端セグメントであるため、`page.js` では `title.template` は使用されません。

#### `metadataBase`

`metadataBase` は、完全修飾 URL が必要な `metadata` フィールドに対して、ベースとなる URL プレフィックスを設定するための補助的なオプションです。

- `metadataBase` を使うと、**現在のルートセグメントおよびその配下** で定義される URL ベースの `metadata` フィールドに、本来必要となる絶対 URL の代わりに **相対パス** を使用できます。
- フィールドの相対パスは `metadataBase` と組み合わされ、完全修飾 URL が生成されます。

```jsx filename="layout.js | page.js"
export const metadata = {
  metadataBase: new URL('https://acme.com'),
  alternates: {
    canonical: '/',
    languages: {
      'en-US': '/en-US',
      'de-DE': '/de-DE',
    },
  },
  openGraph: {
    images: '/og-image.png',
  },
}
```

```html filename="<head> output" hideLineNumbers
<link rel="canonical" href="https://acme.com" />
<link rel="alternate" hreflang="en-US" href="https://acme.com/en-US" />
<link rel="alternate" hreflang="de-DE" href="https://acme.com/de-DE" />
<meta property="og:image" content="https://acme.com/og-image.png" />
```

> **補足**:
>
> - `metadataBase` は、通常ルートレイアウトの `app/layout.js` に設定し、全ルートで使われる URL ベースの `metadata` フィールドに適用します。
> - 絶対 URL を必要とするすべての URL ベースの `metadata` フィールドは、`metadataBase` オプションで設定できます。
> - `metadataBase` には、サブドメイン（例: `https://app.acme.com`）やベースパス（例: `https://acme.com/start/from/here`）を含めることができます。
> - 特定の `metadata` フィールドで絶対 URL が指定されている場合、そのフィールドに対しては `metadataBase` は無視されます。
> - `metadataBase` を設定せずに、URL ベースの `metadata` フィールドで相対パスを使うと、ビルドエラーになります。
> - Next.js は、`metadataBase`（例: `https://acme.com/`）と相対パスのフィールド（例: `/path`）の間に重複するスラッシュがあっても、それらを単一のスラッシュ（例: `https://acme.com/path`）に正規化します。

#### URL の構成

URL の構成は、デフォルトのディレクトリ走査の挙動よりも、開発者の意図を優先します。

- `metadataBase` と `metadata` フィールドの間にある末尾スラッシュの有無は正規化されます。
- `metadata` フィールド内の、本来であれば URL パス全体を置き換えるような「絶対」パスは、`metadataBase` の末尾から始まる「相対」パスとして扱われます。

たとえば、次のような `metadataBase` があるとします:

```tsx filename="app/layout.tsx" switcher
import type { Metadata } from 'next'

export const metadata: Metadata = {
  metadataBase: new URL('https://acme.com'),
}
```

```jsx filename="app/layout.js" switcher
export const metadata = {
  metadataBase: new URL('https://acme.com'),
}
```

上記の `metadataBase` を継承しつつ固有の値を設定した任意の `metadata` フィールドは、次のように解決されます:

| `metadata` field                 | Resolved URL                     |
| -------------------------------- | -------------------------------- |
| `/`                              | `https://acme.com`               |
| `./`                             | `https://acme.com`               |
| `payments`                       | `https://acme.com/payments`      |
| `/payments`                      | `https://acme.com/payments`      |
| `./payments`                     | `https://acme.com/payments`      |
| `../payments`                    | `https://acme.com/payments`      |
| `https://beta.acme.com/payments` | `https://beta.acme.com/payments` |

### リソースヒント

`<link>` 要素には、外部リソースが必要になる可能性が高いことをブラウザに示すために使用できる、いくつかの `rel` キーワードがあります。ブラウザはこの情報を使って、キーワードに応じたプリロードの最適化を適用します。

Metadata API はこれらのヒントを直接サポートしていませんが、新しい [`ReactDOM` メソッド](https://github.com/facebook/react/pull/26237) を使用して、ドキュメントの `<head>` 内に安全に挿入できます。

```tsx filename="app/preload-resources.tsx" switcher
'use client'

import ReactDOM from 'react-dom'

export function PreloadResources() {
  ReactDOM.preload('...', { as: '...' })
  ReactDOM.preconnect('...', { crossOrigin: '...' })
  ReactDOM.prefetchDNS('...')

  return '...'
}
```

```jsx filename="app/preload-resources.js" switcher

}
```

>
> - これらのメソッドは現在、初回ページロード時には引き続きサーバーサイドレンダリングされる Client Components でのみサポートされています。
> - `next/font`、`next/image`、`next/script` などの Next.js の組み込み機能は、関連するリソースヒントを自動的に処理します。

## 挙動

### デフォルトフィールド

ルートでメタデータを定義していない場合でも、常に追加される `meta` タグが 2 つあります：

- [meta charset タグ](https://developer.mozilla.org/docs/Web/HTML/Element/meta#attr-charset) は、Webサイトの文字エンコーディングを設定します。
- [meta viewport タグ](https://developer.mozilla.org/docs/Web/HTML/Viewport_meta_tag) は、さまざまなデバイスに対応できるように、Webサイトのビューポートの幅や拡大率を設定します。

```html
<meta charset="utf-8" />
<meta name="viewport" content="width=device-width, initial-scale=1" />
```

> **補足**: デフォルトの [`viewport`](/docs/app/api-reference/functions/generate-metadata#viewport) メタタグは上書きできます。

### ストリーミングメタデータ

ストリーミングメタデータを使用すると、Next.js は `generateMetadata` の完了を待たずに初期UIをレンダーしてブラウザへ送信できます。

`generateMetadata` の処理が完了すると、その結果のメタデータタグは `<body>` タグに追加されます。JavaScript を実行して完全な DOM を検査するボット（例: `Googlebot`）に対して、メタデータが正しく解釈されることを検証済みです。

JavaScript を実行できない **HTML-limited bots**（例: `facebookexternalhit`）向けには、メタデータは引き続きページのレンダリングをブロックします。生成されたメタデータは `<head>` タグ内で利用可能になります。

Next.js は User-Agent ヘッダーを確認することで、自動的に **HTML-limited bots** を検出します。Next.js の設定ファイル内の [`htmlLimitedBots`](/docs/app/api-reference/config/next-config-js/htmlLimitedBots) オプションを使用して、デフォルトの [User Agent リスト](https://github.com/vercel/next.js/blob/canary/packages/next/src/shared/lib/router/utils/html-bots.ts) を上書きできます。

ストリーミングメタデータを完全に無効化するには、次のようにします:

```ts filename="next.config.ts" switcher
import type { NextConfig } from 'next'

const config: NextConfig = {
  htmlLimitedBots: /.*/,
}

export default config
```

```js filename="next.config.js" switcher
module.exports = {
  htmlLimitedBots: /.*/,
}
```

ストリーミングメタデータは、[TTFB](https://developer.mozilla.org/docs/Glossary/Time_to_first_byte) を短縮することで体感パフォーマンスを向上させ、[LCP](https://developer.mozilla.org/docs/Glossary/Largest_contentful_paint) の時間短縮にも役立ちます。

`htmlLimitedBots` を上書きすると、レスポンス時間が長くなる可能性があります。ストリーミングメタデータは高度な機能ですが、デフォルト設定でほとんどのケースに十分対応できます。

### Cache Components を使用する場合

[Cache Components](/docs/app/getting-started/cache-components) が有効な場合、`generateMetadata` は他のコンポーネントと同じルールに従います。メタデータがランタイムデータ（`cookies()`, `headers()`, `params`, `searchParams`）にアクセスしたり、キャッシュされていないデータフェッチを行う場合、その処理はリクエスト時にフォールバックされます。

Next.js がこれをどのように扱うかは、ページの残りの構成によって異なります:

- **他の部分もリクエスト時にフォールバックする場合**: プリレンダリングによって静的シェルが生成され、メタデータは他のフォールバックコンテンツと一緒にストリーミングされます。
- **ページまたはレイアウトが、それ以外は完全にプリレンダリング可能な場合**: Next.js は明示的な選択を要求します。可能であればデータをキャッシュするか、フォールバックレンダリングが意図的であることを示す必要があります。

ページの残りが完全にプリレンダリング可能であるにもかかわらず、メタデータだけをランタイムにストリーミングすることは一般的ではありません。この挙動が意図的であることを保証するため、どのページまたはレイアウトに対応が必要かを示すエラーが発生します。

これを解決するには 2 つの選択肢があります。メタデータがランタイムデータではなく外部データに依存する場合は、`use cache` を使用します:

```tsx filename="app/page.tsx" highlight={2}
export async function generateMetadata() {
  'use cache'
  const { title, description } = await db.query('site-metadata')
  return { title, description }
}
```

メタデータで実行時のデータが本当に必要な場合は、ページに動的マーカーコンポーネントを追加してください。

```tsx filename="app/page.tsx" highlight={11-14,19,31}
import { Suspense } from 'react'
import { cookies } from 'next/headers'
import { connection } from 'next/server'

export async function generateMetadata() {
  const token = (await cookies()).get('token')?.value
  // ... トークンを使用してパーソナライズされたメタデータを取得する
  return { title: 'Personalized Title' }
}

const Connection = async () => {
  await connection()
  return null
}

async function DynamicMarker() {
  return (
    <Suspense>
      <Connection />
    </Suspense>
  )
}

export default function Page() {
  // ここに await connection() を置かないこと
  // 置くと article タグのコンテンツが
  // 静的シェルに含まれなくなる
  return (
    <>
      <article>Static content</article>
      <DynamicMarker />
    </>
  )
}
```

`DynamicMarker` コンポーネントは何も描画しませんが、そのページに意図的に動的なコンテンツが含まれていることを Next.js に伝えます。これを Suspense でラップすることで、静的なコンテンツは引き続き通常どおりに事前レンダーされます。

### 順序

メタデータは、ルートセグメントから最終的な `page.js` セグメントに最も近いセグメントまで、順に評価されます。例：

1. `app/layout.tsx` (ルートレイアウト)
2. `app/blog/layout.tsx` (ネストされたブログレイアウト)
3. `app/blog/[slug]/page.tsx` (ブログページ)

### マージ

[評価順序](#ordering)に従って、同じルート内の複数のセグメントからエクスポートされた Metadata オブジェクトは、ルートの最終的なメタデータ出力を構成するために**浅く**マージされます。重複するキーは、その順序に基づいて**置き換え**られます。

つまり、[`openGraph`](/docs/app/api-reference/functions/generate-metadata#opengraph) や [`robots`](/docs/app/api-reference/functions/generate-metadata#robots) のようなネストされたフィールドを持つメタデータは、前のセグメントで定義されている場合でも、同じフィールドを最後に定義したセグメントによって**上書き**されます。

#### フィールドの上書き

```jsx filename="app/layout.js"
export const metadata = {
  title: 'Acme',
  openGraph: {
    title: 'Acme',
    description: 'Acme is a...',
  },
}
```

```jsx filename="app/blog/page.js"
export const metadata = {
  title: 'Blog',
  openGraph: {
    title: 'Blog',
  },
}

// 出力:
// <title>Blog</title>
// <meta property="og:title" content="Blog" />
```

上記の例では:

- `app/layout.js` の `title` は、`app/blog/page.js` の `title` によって**置き換えられ**ます。
- `app/layout.js` のすべての `openGraph` フィールドは、`app/blog/page.js` で `openGraph` メタデータを設定しているため、`app/blog/page.js` で**置き換えられ**ます。`openGraph.description` が含まれていないことに注意してください。

一部のネストされたフィールドをセグメント間で共有しつつ、他のフィールドを上書きしたい場合は、それらを別の変数として切り出すことができます:

```jsx filename="app/shared-metadata.js"
export const openGraphImage = { images: ['http://...'] }
```

```jsx filename="app/page.js"
import { openGraphImage } from './shared-metadata'

export const metadata = {
  openGraph: {
    ...openGraphImage,
    title: 'Home',
  },
}
```

```jsx filename="app/about/page.js"
import { openGraphImage } from '../shared-metadata'

export const metadata = {
  openGraph: {
    ...openGraphImage,
    title: 'About',
  },
}
```

上記の例では、OG画像は `app/layout.js` と `app/about/page.js` の間で共有されていますが、タイトルは異なります。

#### フィールドの継承

```jsx filename="app/layout.js"
export const metadata = {
  title: 'Acme',
  openGraph: {
    title: 'Acme',
    description: 'Acme is a...',
  },
}
```

```jsx filename="app/about/page.js"
export const metadata = {
  title: 'About',
}

// 出力:
// <title>About</title>
// <meta property="og:title" content="Acme" />
// <meta property="og:description" content="Acme is a..." />
```

**注意**

- `app/layout.js` の `title` は、`app/about/page.js` の `title` によって**上書きされ**ます。
- `app/about/page.js` が `openGraph` メタデータを設定していないため、`app/layout.js` のすべての `openGraph` フィールドは `app/about/page.js` に**引き継がれ**ます。
