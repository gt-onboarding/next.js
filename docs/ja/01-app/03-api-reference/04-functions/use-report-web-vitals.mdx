`useReportWebVitals` フックを使うと、[Core Web Vitals](https://web.dev/vitals/) をレポートでき、使用しているアナリティクスサービスと組み合わせて利用できます。

`useReportWebVitals` に渡された新しい関数は、その時点までに利用可能なメトリクスを引数に呼び出されます。重複したデータをレポートしないようにするには（以下のコード例にあるように）、コールバック関数の参照が変わらないようにしてください。

<PagesOnly>
  ```jsx filename="pages/_app.js"
  import { useReportWebVitals } from 'next/web-vitals'

const logWebVitals = (metric) => {
console.log(metric)
}

function MyApp({ Component, pageProps }) {
useReportWebVitals(logWebVitals)

    return <Component {...pageProps} />

}

````
</PagesOnly>

<AppOnly>
```jsx filename="app/_components/web-vitals.js"
'use client'

import { useReportWebVitals } from 'next/web-vitals'

const logWebVitals = (metric) => {
  console.log(metric)
}

export function WebVitals() {
  useReportWebVitals(logWebVitals)

  return null
}
````

```jsx filename="app/layout.js"
import { WebVitals } from './_components/web-vitals'

export default function Layout({ children }) {
  return (
    <html>
      <body>
        <WebVitals />
        {children}
      </body>
    </html>
  )
}
```

> `useReportWebVitals` フックは `'use client'` ディレクティブを必要とするため、最もパフォーマンスに優れた方法は、ルートレイアウトからインポートされる専用コンポーネントを作成することです。これにより、クライアント境界は `WebVitals` コンポーネントのみに限定されます。

</AppOnly>

## useReportWebVitals

フックの引数として渡される `metric` オブジェクトは、次のような複数のプロパティで構成されています：

- `id`：現在のページロードのコンテキスト内における、このメトリクスの一意の識別子
- `name`：パフォーマンスメトリクスの名前。取りうる値には、Web アプリケーション固有の [Web Vitals](#web-vitals) メトリクス（TTFB, FCP, LCP, FID, CLS）の名前が含まれます。
- `delta`：現在の値と前回のメトリクス値との差分。値は通常ミリ秒単位で、時間経過に伴うメトリクス値の変化量を表します。
- `entries`：メトリクスに関連付けられた [PerformanceEntry](https://developer.mozilla.org/docs/Web/API/PerformanceEntry) の配列。これらのエントリは、そのメトリクスに関連するパフォーマンスイベントに関する詳細情報を提供します。
- `navigationType`：メトリクス収集をトリガーした[ナビゲーションの種類](https://developer.mozilla.org/docs/Web/API/PerformanceNavigationTiming/type) を示します。取りうる値には `"navigate"`、`"reload"`、`"back_forward"`、`"prerender"` があります。
- `rating`：メトリクス値に対する定性的な評価で、パフォーマンスの状態を表します。取りうる値は `"good"`、`"needs-improvement"`、`"poor"` です。評価は通常、メトリクス値を、許容できるパフォーマンスか最適とはいえないパフォーマンスかを示す事前定義されたしきい値と比較することで決定されます。
- `value`：パフォーマンスエントリの実際の値または所要時間で、一般的にミリ秒単位です。この値は、そのメトリクスが追跡しているパフォーマンス面を定量的に測定したものです。値の出どころは測定される特定のメトリクスに依存し、さまざまな [Performance API](https://developer.mozilla.org/docs/Web/API/Performance_API) から取得される場合があります。

## Web Vitals

[Web Vitals](https://web.dev/vitals/) は、ウェブページにおけるユーザー体験を把握するための有用な指標群です。次の Web Vitals が含まれます。

- [Time to First Byte](https://developer.mozilla.org/docs/Glossary/Time_to_first_byte) (TTFB)
- [First Contentful Paint](https://developer.mozilla.org/docs/Glossary/First_contentful_paint) (FCP)
- [Largest Contentful Paint](https://web.dev/lcp/) (LCP)
- [First Input Delay](https://web.dev/fid/) (FID)
- [Cumulative Layout Shift](https://web.dev/cls/) (CLS)
- [Interaction to Next Paint](https://web.dev/inp/) (INP)

これらの指標の結果はすべて、`name` プロパティを使って処理できます。

<PagesOnly>

```jsx filename="pages/_app.js"
import { useReportWebVitals } from 'next/web-vitals'

const handleWebVitals = (metric) => {
  switch (metric.name) {
    case 'FCP': {
      // FCP の結果を処理
    }
    case 'LCP': {
      // LCP の結果を処理
    }
    // ...
  }
}

function MyApp({ Component, pageProps }) {
  useReportWebVitals(handleWebVitals)

  return <Component {...pageProps} />
}
```

</PagesOnly>

## カスタムメトリクス

上記のコア指標に加えて、ページのハイドレーションおよびレンダーにかかる時間を計測する、いくつかの追加のカスタム指標があります。

- `Next.js-hydration`: ページがハイドレーションを開始してから完了するまでの時間（ミリ秒）
- `Next.js-route-change-to-render`: ルート変更後、ページのレンダーが開始されるまでの時間（ミリ秒）
- `Next.js-render`: ルート変更後、ページのレンダーが完了するまでの時間（ミリ秒）

これらの指標の結果はすべて個別に処理できます。

```jsx filename="pages/_app.js"
import { useReportWebVitals } from 'next/web-vitals'

function handleCustomMetrics(metrics) {
  switch (metric.name) {
    case 'Next.js-hydration':
      // hydration の結果を処理
      break
    case 'Next.js-route-change-to-render':
      // route-change から render までの結果を処理
      break
    case 'Next.js-render':
      // render の結果を処理
      break
    default:
      break
  }
}

function MyApp({ Component, pageProps }) {
  useReportWebVitals(handleCustomMetrics)

  return <Component {...pageProps} />
}
```

これらの指標は、[User Timing API](https://caniuse.com/#feat=user-timing) をサポートしているすべてのブラウザで動作します。

</PagesOnly>

## 結果を外部システムに送信する

任意のエンドポイントに結果を送信して、サイト上の実ユーザーのパフォーマンスを計測・追跡できます。たとえば、次のようにします。

```js
function postWebVitals(metrics) {
  const body = JSON.stringify(metric)
  const url = 'https://example.com/analytics'

  // 利用可能であれば `navigator.sendBeacon()` を使用し、そうでなければ `fetch()` にフォールバックします。
  if (navigator.sendBeacon) {
    navigator.sendBeacon(url, body)
  } else {
    fetch(url, { body, method: 'POST', keepalive: true })
  }
}

useReportWebVitals(postWebVitals)
```

> **参考**: [Google Analytics](https://analytics.google.com/analytics/web/) を使用している場合、
> `id` の値を使うことでメトリクスの分布を手動で構築できます（パーセンタイルを計算する
> など）。

> ```js
> useReportWebVitals(metric => {
>   // 次の例のように Google Analytics を初期化している場合は `window.gtag` を使用してください:
>   // https://github.com/vercel/next.js/blob/canary/examples/with-google-analytics
>   window.gtag('event', metric.name, {
>     value: Math.round(metric.name === 'CLS' ? metric.value * 1000 : metric.value), // 値は整数である必要があります
>     event_label: metric.id, // 現在のページロードに固有の id
>     non_interaction: true, // 直帰率に影響しないようにします。
>   });
> }
> ```
>
> [Google Analytics に結果を送信する方法](https://github.com/GoogleChrome/web-vitals#send-the-results-to-google-analytics)の詳細については、こちらを参照してください。
