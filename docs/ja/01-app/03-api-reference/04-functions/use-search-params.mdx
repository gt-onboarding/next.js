`useSearchParams` は、現在の URL の **クエリ文字列** を読み取るための **Client Component** 用フックです。

`useSearchParams` は、[`URLSearchParams`](https://developer.mozilla.org/docs/Web/API/URLSearchParams) インターフェイスの **読み取り専用** バージョンを返します。

```tsx filename="app/dashboard/search-bar.tsx" switcher
'use client'

import { useSearchParams } from 'next/navigation'

export default function SearchBar() {
  const searchParams = useSearchParams()

  const search = searchParams.get('search')

  // URL -> `/dashboard?search=my-project`
  // `search` -> 'my-project'
  return <>Search: {search}</>
}
```

```jsx filename="app/dashboard/search-bar.js" switcher
'use client'

import { useSearchParams } from 'next/navigation'

export default function SearchBar() {
  const searchParams = useSearchParams()

  const search = searchParams.get('search')

  // URL -> `/dashboard?search=my-project`
  // `search` -> 'my-project'
  return <>Search: {search}</>
}
```

## パラメータ

```tsx
const searchParams = useSearchParams()
```

`useSearchParams` は引数を一切受け取りません。

## 戻り値

`useSearchParams` は、[`URLSearchParams`](https://developer.mozilla.org/docs/Web/API/URLSearchParams) インターフェースの **読み取り専用** バージョンを返します。これには、URL のクエリ文字列を読み取るためのユーティリティメソッドが含まれます：

- [`URLSearchParams.get()`](https://developer.mozilla.org/docs/Web/API/URLSearchParams/get): 検索パラメーターに関連付けられた最初の値を返します。例：

  | URL                  | `searchParams.get("a")`                                                                                                         |
  | -------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
  | `/dashboard?a=1`     | `'1'`                                                                                                                           |
  | `/dashboard?a=`      | `''`                                                                                                                            |
  | `/dashboard?b=3`     | `null`                                                                                                                          |
  | `/dashboard?a=1&a=2` | `'1'` _- すべての値を取得するには [`getAll()`](https://developer.mozilla.org/docs/Web/API/URLSearchParams/getAll) を使用します_ |

- [`URLSearchParams.has()`](https://developer.mozilla.org/docs/Web/API/URLSearchParams/has): 指定されたパラメーターが存在するかどうかを示す真偽値を返します。例：

  | URL              | `searchParams.has("a")` |
  | ---------------- | ----------------------- |
  | `/dashboard?a=1` | `true`                  |
  | `/dashboard?b=3` | `false`                 |

- [`getAll()`](https://developer.mozilla.org/docs/Web/API/URLSearchParams/getAll)、[`keys()`](https://developer.mozilla.org/docs/Web/API/URLSearchParams/keys)、[`values()`](https://developer.mozilla.org/docs/Web/API/URLSearchParams/values)、[`entries()`](https://developer.mozilla.org/docs/Web/API/URLSearchParams/entries)、[`forEach()`](https://developer.mozilla.org/docs/Web/API/URLSearchParams/forEach)、[`toString()`](https://developer.mozilla.org/docs/Web/API/URLSearchParams/toString) など、[`URLSearchParams`](https://developer.mozilla.org/docs/Web/API/URLSearchParams) のその他の **読み取り専用** メソッドについてはリンク先を参照してください。

> **補足**:
>
> - `useSearchParams` は [Client Component](/docs/app/getting-started/server-and-client-components) 用のフックであり、[partial rendering](/docs/app/getting-started/linking-and-navigating#client-side-transitions) 中に古い値が発生するのを防ぐため、[Server Components](/docs/app/getting-started/server-and-client-components) では **サポートされていません**。
> - 検索パラメーターに基づいて Server Component でデータをフェッチしたい場合は、対応する Page の [`searchParams` prop](/docs/app/api-reference/file-conventions/page#searchparams-optional) を参照する方がよい場合が多いです。その後、その Page 内の任意のコンポーネント（Server / Client）に props として渡せます。
> - アプリケーションに `/pages` ディレクトリが含まれている場合、`useSearchParams` は `ReadonlyURLSearchParams | null` を返します。`null` の値は移行中の互換性のためのものであり、`getServerSideProps` を使用していないページのプリレンダリング時には検索パラメーターを知ることができないためです。

## 挙動

### 静的レンダリング

ルートが[静的にレンダリング](/docs/app/guides/caching#static-rendering)されている場合、`useSearchParams` を呼び出すと、最も近い [`Suspense` 境界](/docs/app/api-reference/file-conventions/loading#examples)までの Client Component ツリーがクライアント側でレンダリングされます。

これにより、ルートの一部を静的にレンダリングしつつ、`useSearchParams` を使用する動的な部分だけをクライアント側でレンダリングできます。

`useSearchParams` を使用する Client Component を `<Suspense/>` 境界でラップすることを推奨します。こうすることで、それより上位の Client Component は静的にレンダリングされ、初期 HTML の一部として送信されます。[例](/docs/app/api-reference/functions/use-search-params#static-rendering)。

例えば、次のようになります:

```tsx filename="app/dashboard/search-bar.tsx" switcher
'use client'

import { useSearchParams } from 'next/navigation'

export default function SearchBar() {
  const searchParams = useSearchParams()

  const search = searchParams.get('search')

  // 静的レンダリングを使用する場合、これはサーバー側にログ出力されません
  console.log(search)

  return <>Search: {search}</>
}
```

```jsx filename="app/dashboard/search-bar.js" switcher
'use client'

import { useSearchParams } from 'next/navigation'

export default function SearchBar() {
  const searchParams = useSearchParams()

  const search = searchParams.get('search')

  // 静的レンダリングを使用する場合、これはサーバー側にログ出力されません
  console.log(search)

  return <>Search: {search}</>
}
```

```tsx filename="app/dashboard/page.tsx" switcher
import { Suspense } from 'react'
import SearchBar from './search-bar'

// このコンポーネントは Suspense バウンダリのフォールバックとして渡され、
// 初期 HTML ではサーチバーの代わりにレンダリングされます。
// React のハイドレーション中に値が利用可能になると、フォールバックは
// `<SearchBar>` コンポーネントに置き換えられます。
function SearchBarFallback() {
  return <>placeholder</>
}

export default function Page() {
  return (
    <>
      <nav>
        <Suspense fallback={<SearchBarFallback />}>
          <SearchBar />
        </Suspense>
      </nav>
      <h1>Dashboard</h1>
    </>
  )
}
```

> **補足**:
>
> - 開発環境ではルートはオンデマンドでレンダリングされるため、`useSearchParams` はサスペンドせず、`Suspense` を使わなくても動作しているように見える場合があります。
> - 本番ビルド時には、Client Component から `useSearchParams` を呼び出す[静的ページ](/docs/app/guides/caching#static-rendering)は必ず `Suspense` 境界でラップする必要があります。そうしない場合、ビルドは [Missing Suspense boundary with useSearchParams](/docs/messages/missing-suspense-with-csr-bailout) エラーで失敗します。
> - そのルートを動的レンダリングしたい場合は、まず Server Component 内で [`connection`](/docs/app/api-reference/functions/connection) 関数を使って受信リクエストを待機することを推奨します。これにより、それ以降のすべてがプリレンダリングから除外されます。ルートが動的になる条件については、[Dynamic Rendering ガイド](/docs/app/guides/caching#dynamic-rendering)を参照してください。
> - すでに Server Component の Page 内にいる場合は、[`searchParams` prop](/docs/app/api-reference/file-conventions/page#searchparams-optional) を使用し、その値を Client Component に渡すことを検討してください。
> - Page の [`searchParams` prop](/docs/app/api-reference/file-conventions/page#searchparams-optional) をそのまま Client Component に渡し、React の `use()` でアンラップすることもできます。ただし、この場合はサスペンドされるため、その Client Component は `Suspense` 境界でラップする必要があります。

### 動的レンダリング

ルートが[動的にレンダリング](/docs/app/guides/caching#dynamic-rendering)される場合、`useSearchParams` はクライアントコンポーネントの初回サーバーレンダリング時にサーバー上で利用可能になります。

例えば、次のようになります：

```tsx filename="app/dashboard/search-bar.tsx" switcher
'use client'

import { useSearchParams } from 'next/navigation'

export default function SearchBar() {
  const searchParams = useSearchParams()

  const search = searchParams.get('search')

  // これは初回レンダリング時にサーバーで、
  // その後のナビゲーション時にクライアントでログに記録されます。
  console.log(search)

  return <>Search: {search}</>
}
```

```jsx filename="app/dashboard/search-bar.js" switcher
'use client'

import { useSearchParams } from 'next/navigation'

  // その後のナビゲーション時にクライアントでログに記録されます。
  console.log(search)

  return <>Search: {search}</>
}
```

> **補足**:
>
> - 以前は、ページで `export const dynamic = 'force-dynamic'` を設定することで動的レンダリングを強制していました。代わりに [`connection()`](/docs/app/api-reference/functions/connection) の使用を推奨します。こちらの方が、動的レンダリングを受信したリクエストに意味的に結び付けられるためです。

### サーバーコンポーネント

#### ページ

[Pages](/docs/app/api-reference/file-conventions/page)（サーバーコンポーネント）で検索パラメータにアクセスするには、[`searchParams`](/docs/app/api-reference/file-conventions/page#searchparams-optional) プロパティを使用します。

#### レイアウト

Pages とは異なり、[Layouts](/docs/app/api-reference/file-conventions/layout)（サーバーコンポーネント）は `searchParams` prop を**受け取りません**。これは、共有レイアウトは[ナビゲーション中に再レンダーされない](/docs/app/getting-started/linking-and-navigating#client-side-transitions)ため、ナビゲーション間で `searchParams` が古い状態のままになる可能性があるためです。[詳細な説明](/docs/app/api-reference/file-conventions/layout#query-params)を参照してください。

代わりに、Page の [`searchParams`](/docs/app/api-reference/file-conventions/page) prop、またはクライアントコンポーネント内で [`useSearchParams`](/docs/app/api-reference/functions/use-search-params) フックを使用してください。クライアントコンポーネントは、最新の `searchParams` を使ってクライアント側で再レンダーされます。

## 例

### `searchParams` の更新

新しい `searchParams` を設定するには、[`useRouter`](/docs/app/api-reference/functions/use-router) または [`Link`](/docs/app/api-reference/components/link) を使用できます。ナビゲーションが行われると、現在の [`page.js`](/docs/app/api-reference/file-conventions/page) は更新された [`searchParams` プロパティ](/docs/app/api-reference/file-conventions/page#searchparams-optional) を受け取ります。

```tsx filename="app/example-client-component.tsx" switcher
'use client'

export default function ExampleClientComponent() {
  const router = useRouter()
  const pathname = usePathname()
  const searchParams = useSearchParams()

  // 現在のsearchParamsと指定されたキー/値のペアをマージして
  // 新しいsearchParams文字列を取得する
  const createQueryString = useCallback(
    (name: string, value: string) => {
      const params = new URLSearchParams(searchParams.toString())
      params.set(name, value)

      return params.toString()
    },
    [searchParams]
  )

  return (
    <>
      <p>並び替え</p>

      {/* useRouterを使用 */}
      <button
        onClick={() => {
          // <pathname>?sort=asc
          router.push(pathname + '?' + createQueryString('sort', 'asc'))
        }}
      >
        ASC
      </button>

      {/* <Link>を使用 */}
      <Link
        href={
          // <pathname>?sort=desc
          pathname + '?' + createQueryString('sort', 'desc')
        }
      >
        DESC
      </Link>
    </>
  )
}
```
