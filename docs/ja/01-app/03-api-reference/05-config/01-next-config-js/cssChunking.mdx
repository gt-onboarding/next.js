title: cssChunking

---

CSS Chunking は、CSS ファイルをチャンクに分割して再配置することで、ウェブアプリケーションのパフォーマンスを向上させるための手法です。これにより、アプリケーション全体の CSS を一度に読み込むのではなく、特定のルートに必要な CSS だけを読み込むことができます。

`next.config.js` ファイルの `experimental.cssChunking` オプションを使用して、CSS ファイルの分割方法を制御できます。

```tsx filename="next.config.ts" switcher
import type { NextConfig } from 'next'

const nextConfig = {
  experimental: {
    cssChunking: true, // デフォルト
  },
} satisfies NextConfig

export default nextConfig
```

```js filename="next.config.js" switcher
/** @type {import('next').NextConfig} */
const nextConfig = {
  experimental: {
    cssChunking: true, // デフォルト
  },
}

module.exports = nextConfig
```

## オプション

- **`true` (デフォルト)**: Next.js は可能な限り CSS ファイルをマージしようとし、インポート順からファイル間の明示的および暗黙的な依存関係を判定して、チャンク数とそれに伴うリクエスト数を削減します。
- **`false`**: Next.js は CSS ファイルのマージや並び替えを行いません。
- **`'strict'`**: Next.js は CSS ファイルを、コード内でインポートされた順序どおりに読み込みます。その結果、チャンク数とリクエスト数が増える可能性があります。

予期しない CSS の挙動に遭遇した場合は、`'strict'` の使用を検討してください。たとえば、`a.css` と `b.css` を別々のファイルで異なる `import` 順序（`a` を先にしてから `b`、または `b` を先にしてから `a`）でインポートしている場合、`true` では両ファイルを任意の順序でマージし、それらの間に依存関係がないと仮定します。しかし、`b.css` が `a.css` に依存している場合は、ファイルがマージされないようにし、代わりにインポートされた順序どおりに読み込むために `'strict'` を使用したほうがよいでしょう。この場合、チャンク数とリクエスト数が増える可能性があります。

ほとんどのアプリケーションでは、リクエストが少なくなりパフォーマンスが向上するため、`true` を推奨します。
