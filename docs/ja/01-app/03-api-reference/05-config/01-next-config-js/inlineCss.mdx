## 使用方法

`<head>` 内への CSS のインライン挿入を実験的にサポートします。このフラグを有効にすると、通常は `<link>` タグを生成するすべての箇所が、代わりに生成された `<style>` タグになります。

```ts filename="next.config.ts" switcher
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  experimental: {
    inlineCss: true,
  },
}

export default nextConfig
```

```js filename="next.config.js" switcher
/** @type {import('next').NextConfig} */
const nextConfig = {
  experimental: {
    inlineCss: true,
  },
}

module.exports = nextConfig
```

## トレードオフ

- Tailwind のようなアトミック CSS を使用していて、新規訪問者向けの初回ロードパフォーマンスを最適化したい場合は **有効にする**
- 再訪問ユーザーが多く、キャッシュされたスタイルシートの恩恵を受けさせたい場合は **スキップ** する

### インライン CSS が役立つとき

通常、ブラウザは HTML をダウンロードしてパースし、CSS の `<link>` タグを見つけてスタイルシートをリクエストしてから、ようやくレンダリングできます。インライン化すると、スタイルが HTML と一緒に届くため、[このようなリクエストの連鎖を解消](https://web.dev/learn/performance/optimize-resource-loading#inline_critical_css)でき、ブラウザはすぐにレンダリングを開始できます。

このメリットが最も大きいのは次のケースです:

- **初回訪問ユーザー**: CSS ファイルはレンダリングをブロックするため、インライン化により初回訪問時に発生するダウンロード待ちを排除できます。スタイルシートがキャッシュされている再訪問ユーザーにはこの効果はありません。

- **パフォーマンス指標**: CSS ファイルのための追加のネットワークリクエストを削減することで、インライン化は [First Contentful Paint (FCP)](https://web.dev/articles/fcp) や [Largest Contentful Paint (LCP)](https://web.dev/articles/lcp) を大きく改善できます。

- **低速な回線**: レイテンシの高いネットワークでは、リクエストが 1 つ増えるごとに遅延が増えます。インライン化は往復回数を減らすため、接続が遅いほど効果が大きくなります。

- **Atomic CSS (Tailwind)**: Utility-first なフレームワークは、使用したクラスだけを生成するため CSS を小さく保てます。ページのスタイルはページの複雑さに比例して増えず、多くの場合 UI をどれだけ構築してもコンパクトに収まります。そのため、HTML を大きく膨らませることなくパフォーマンス上のメリットを得られ、インライン化が現実的になります。

### 外部 CSS の方が適している場合

インラインスタイルは HTML とは別にキャッシュできません。ページを読み込むたびに同じ CSS が再ダウンロードされます。

このトレードオフの影響が特に大きくなるのは次のような場合です:

- **再訪問ユーザー**: サイトを繰り返し訪れるユーザーは、キャッシュされた外部スタイルシートの恩恵を受けられます。インライン化している場合、訪問のたびにスタイルを再ダウンロードする必要があります。

- **大きな CSS バンドル**: 外部スタイルシートは独立してキャッシュされ、モダンなインフラストラクチャ上で効率的に読み込まれます。インライン CSS はすべての HTML レスポンスと一緒に送信されるため、[Time to First Byte (TTFB)](https://web.dev/articles/ttfb) を増加させ、ブラウザがスタイルだけを別途キャッシュすることを妨げます。このトレードオフは、小さな CSS（Tailwind のようなアトミックフレームワーク）には有効ですが、大きなバンドル（Bootstrap や Material UI のようなコンポーネントライブラリ）の場合はオーバーヘッドが増えます。

- **多くのページでスタイルを共有している場合**: あるページでキャッシュされた外部スタイルシートは、他のページへのナビゲーションを高速化します。インラインスタイルには、ページ間でのキャッシュによるメリットはありません。

> **補足**:
>
> この機能は現在実験的であり、いくつかの既知の制限があります:
>
> - CSS のインライン化はグローバルに適用され、ページ単位で設定することはできません
> - 初回ページロード時にはスタイルが重複します。SSR 用の `<style>` タグ内と、RSC ペイロード内の 2 か所に含まれます
> - 静的にレンダリングされたページに遷移する場合、重複を避けるためにスタイルはインライン CSS ではなく `<link>` タグを使用します
> - この機能は開発モードでは利用できず、本番ビルドでのみ動作します
