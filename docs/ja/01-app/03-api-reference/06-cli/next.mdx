Next.js CLI を使用すると、アプリケーションの開発・ビルド・起動などを行えます。

基本的な使い方:

```bash package="pnpm"
pnpm next [command] [options]
```

```bash package="npm"
npx next [command] [options]
```

```bash package="yarn"
yarn next [command] [options]
```

```bash package="bun"
bunx next [command] [options]
```

> **補足**: `npm run` を使う場合は、CLI フラグの前に `--` を付ける必要があります。そうすることで、npm がフラグを `next` に渡します。`pnpm`、`yarn`、`bun` ではこの指定は不要です。

## リファレンス

使用可能なオプションは次のとおりです。

| オプション              | 説明                                     |
| ----------------------- | ---------------------------------------- |
| `-h` または `--help`    | 利用可能なすべてのオプションを表示します |
| `-v` または `--version` | Next.js のバージョン番号を表示します     |

### コマンド

使用できるコマンドは次のとおりです:

| コマンド                                                     | 説明                                                                                                    |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------- |
| [`dev`](#next-dev-options)                                   | Hot Module Reloading、エラー報告などを有効にした開発モードで Next.js を起動します。                     |
| [`build`](#next-build-options)                               | アプリケーションの最適化された本番ビルドを作成します。各ルートに関する情報を表示します。                |
| [`start`](#next-start-options)                               | 本番モードで Next.js を起動します。事前に `next build` でコンパイルしておく必要があります。             |
| [`info`](#next-info-options)                                 | 現在のシステムに関する、Next.js のバグ報告に利用できる関連情報を出力します。                            |
| [`telemetry`](#next-telemetry-options)                       | 完全に匿名の Next.js のテレメトリー収集を有効化または無効化します。                                     |
| [`typegen`](#next-typegen-options)                           | 完全なビルドを実行せずに、routes、pages、layouts、route handlers 向けの TypeScript 型定義を生成します。 |
| [`upgrade`](#next-upgrade-options)                           | Next.js アプリケーションを最新バージョンにアップグレードします。                                        |
| [`experimental-analyze`](#next-experimental-analyze-options) | Turbopack を使用してバンドル出力を解析します。ビルド成果物は生成しません。                              |

> **補足**: コマンドを指定せずに `next` を実行すると、`next dev` のエイリアスとして動作します。

### `next dev` のオプション

`next dev` は、Hot Module Reloading (HMR)、エラー報告などを有効にした開発モードでアプリケーションを起動します。

> **補足**: 開発ビルドの出力先は `.next` ではなく `.next/dev` です。これにより、`next dev` と `next build` を競合なく同時に実行できます。

`next dev` 実行時に利用可能なオプションは次のとおりです:

| オプション                               | 説明                                                                                                                                                  |
| ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `-h, --help`                             | 利用可能なすべてのオプションを表示します。                                                                                                            |
| `[directory]`                            | アプリケーションをビルドするディレクトリ。指定しない場合はカレントディレクトリが使用されます。                                                        |
| `--turbopack`                            | [Turbopack](/docs/app/api-reference/turbopack) を強制的に有効にします（デフォルトで有効）。`--turbo` としても利用可能です。                           |
| `--webpack`                              | 開発用バンドラとして、デフォルトの [Turbopack](/docs/app/api-reference/turbopack) の代わりに Webpack を使用します。                                   |
| `-p` or `--port <port>`                  | アプリケーションを起動するポート番号を指定します。デフォルト: 3000、環境変数: PORT                                                                    |
| `-H`or `--hostname <hostname>`           | アプリケーションを起動するホスト名を指定します。ネットワーク上の他のデバイスからアプリケーションにアクセス可能にする際に便利です。デフォルト: 0.0.0.0 |
| `--experimental-https`                   | HTTPS でサーバーを起動し、自己署名証明書を生成します。                                                                                                |
| `--experimental-https-key <path>`        | HTTPS キーファイルへのパス。                                                                                                                          |
| `--experimental-https-cert <path>`       | HTTPS 証明書ファイルへのパス。                                                                                                                        |
| `--experimental-https-ca <path>`         | HTTPS 認証局 (CA) 証明書ファイルへのパス。                                                                                                            |
| `--experimental-upload-trace <traceUrl>` | デバッグトレースの一部をリモートの HTTP URL に送信します。                                                                                            |
| `--experimental-cpu-prof`                | V8 の Inspector を使用した CPU プロファイリングを有効にします。プロファイルは終了時に `.next/cpu-profiles/` に保存されます。                          |

### `next build` のオプション

`next build` は、アプリケーションの最適化済み本番ビルドを作成します。ビルド結果には、各ルートに関する情報が表示されます。例えば、次のように表示されます：

```bash filename="Terminal"
Route (app)
┌ ○ /_not-found
└ ƒ /products/[id]

○  (Static)   prerendered as static content
ƒ  (Dynamic)  server-rendered on demand
```

`next build` コマンドでは、次のオプションが利用できます:

| オプション                         | 説明                                                                                                                                                                           |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `-h, --help`                       | 利用可能なすべてのオプションを表示します。                                                                                                                                     |
| `[directory]`                      | アプリケーションをビルドするディレクトリです。指定しない場合は、現在のディレクトリが使用されます。                                                                             |
| `--turbopack`                      | [Turbopack](/docs/app/api-reference/turbopack) を強制的に有効化します（デフォルトで有効）。`--turbo` としても利用できます。                                                    |
| `--webpack`                        | Webpack を使用してビルドします。                                                                                                                                               |
| `-d` or `--debug`                  | より詳細なビルド出力を有効化します。このフラグを有効にすると、rewrites、redirects、headers などの追加のビルド出力が表示されます。                                              |
|                                    |                                                                                                                                                                                |
| `--profile`                        | 本番環境での [React のプロファイリング](https://react.dev/reference/react/Profiler) を有効化します。                                                                           |
| `--no-lint`                        | lint を無効化します。_注: lint は Next 16 で `next build` から削除される予定です。Next 15.5+ で `eslint` 以外の linter を使用している場合、ビルド時の lint は実行されません。_ |
| `--no-mangling`                    | [名前マングリング](https://en.wikipedia.org/wiki/Name_mangling) を無効化します。これはパフォーマンスに影響する可能性があり、デバッグ目的でのみ使用すべきです。                 |
| `--experimental-app-only`          | App Router のルートのみをビルドします。                                                                                                                                        |
| `--experimental-build-mode [mode]` | 実験的なビルドモードを使用します。（選択肢: "compile", "generate", デフォルト: "default"）                                                                                     |
| `--debug-prerender`                | 開発環境での prerender のエラーをデバッグします。                                                                                                                              |
| `--debug-build-paths=<patterns>`   | デバッグのために、指定したパターンに一致する特定のルートのみをビルドします。                                                                                                   |
| `--experimental-cpu-prof`          | V8 の inspector を使用した CPU プロファイリングを有効化します。プロファイルは終了時に `.next/cpu-profiles/` に保存されます。                                                   |

### `next start` のオプション

`next start` はアプリケーションを本番モードで起動します。事前にアプリケーションを [`next build`](#next-build-options) でコンパイルしておく必要があります。

`next start` コマンドでは、次のオプションが利用できます:

| オプション                              | 説明                                                                                                                         |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `-h` or `--help`                        | 利用可能なすべてのオプションを表示します。                                                                                   |
| `[directory]`                           | アプリケーションを起動するディレクトリを指定します。ディレクトリを指定しない場合は、カレントディレクトリが使用されます。     |
| `-p` or `--port <port>`                 | アプリケーションを起動するポート番号を指定します。(デフォルト: 3000, 環境変数: PORT)                                         |
| `-H` or `--hostname <hostname>`         | アプリケーションを起動するホスト名を指定します (デフォルト: 0.0.0.0)。                                                       |
| `--keepAliveTimeout <keepAliveTimeout>` | アイドル状態の接続を閉じるまでの最大待機時間（ミリ秒）を指定します。                                                         |
| `--experimental-cpu-prof`               | V8 の inspector を使用した CPU プロファイリングを有効にします。プロファイルは終了時に `.next/cpu-profiles/` に保存されます。 |

### `next info` のオプション

`next info` は、[GitHub issue](https://github.com/vercel/next.js/issues) を作成して Next.js のバグを報告する際に利用できる、現在のシステムに関する関連情報を出力します。出力される情報には、オペレーティングシステムのプラットフォーム／アーキテクチャ／バージョン、バイナリ（Node.js、npm、Yarn、pnpm）、パッケージのバージョン（`next`、`react`、`react-dom`）などがあります。

出力結果は次のようになります:

```bash filename="Terminal"
Operating System:
  Platform: darwin
  Arch: arm64
  Version: Darwin Kernel Version 23.6.0
  Available memory (MB): 65536
  Available CPU cores: 10
Binaries:
  Node: 20.12.0
  npm: 10.5.0
  Yarn: 1.22.19
  pnpm: 9.6.0
Relevant Packages:
  next: 15.0.0-canary.115 // 利用可能な最新バージョンが検出されました (15.0.0-canary.115).
  eslint-config-next: 14.2.5
  react: 19.0.0-rc
  react-dom: 19.0.0
  typescript: 5.5.4
Next.js Config:
  output: N/A
```

`next info` コマンドでは、次のオプションが利用できます。

| オプション           | 説明                                     |
| -------------------- | ---------------------------------------- |
| `-h` または `--help` | 利用可能なすべてのオプションを表示します |
| `--verbose`          | デバッグのための追加情報を収集します。   |

### `next telemetry` オプション

Next.js は一般的な利用状況に関する**完全に匿名化された**テレメトリデータを収集します。この匿名プログラムへの参加は任意であり、情報を共有したくない場合はオプトアウトできます。

`next telemetry` コマンドでは、次のオプションが利用できます。

| オプション   | 説明                                       |
| ------------ | ------------------------------------------ |
| `-h, --help` | 使用可能なすべてのオプションを表示します。 |
| `--enable`   | Next.js のテレメトリ収集を有効にします。   |
| `--disable`  | Next.js のテレメトリ収集を無効にします。   |

詳しくは [Telemetry](/telemetry) を参照してください。

### `next typegen` のオプション

`next typegen` は、アプリケーションのルートに対する TypeScript 型定義を、完全なビルドを行わずに生成します。これは、IDE の補完機能や、ルートの利用箇所に対する CI での型チェックに役立ちます。

以前は、ルート型は `next dev` または `next build` の実行時にのみ生成されていました。そのため、`tsc --noEmit` を直接実行してもルート型は検証されませんでした。今では、型を個別に生成し、外部ツールなどで検証できるようになっています。

```bash filename="Terminal"
# まずルート型を生成し、TypeScriptで検証する
next typegen && tsc --noEmit

# またはビルドせずに型チェックを行うCIワークフローで使用する
next typegen && npm run type-check
```

`next typegen` コマンドでは、次のオプションが使用できます:

| オプション    | 説明                                                                               |
| ------------- | ---------------------------------------------------------------------------------- |
| `-h, --help`  | 利用可能なオプションをすべて表示します。                                           |
| `[directory]` | 型定義を生成するディレクトリ。指定しない場合は、現在のディレクトリが使用されます。 |

出力ファイルは `<distDir>/types` に出力されます（通常: 開発環境では `.next/dev/types`、本番環境では `.next/types`）:

```bash filename="Terminal"
next typegen
# または特定のアプリの場合
next typegen ./apps/web
```

また、`next typegen` は `next-env.d.ts` ファイルを生成します。`next-env.d.ts` を `.gitignore` ファイルに追加することを推奨します。

`next-env.d.ts` ファイルは `tsconfig.json` に含まれ、Next.js の型をプロジェクト内で利用できるようにします。

型チェックを実行する前に `next-env.d.ts` が存在することを保証するには、`next typegen` を実行してください。`next dev` と `next build` コマンドも `next-env.d.ts` ファイルを生成しますが、特に CI/CD 環境などでは、単に型チェックのためだけにこれらを実行するのは望ましくない場合がよくあります。

> **補足**: `next typegen` は、本番ビルドフェーズを使って Next.js の設定ファイル（`next.config.js`、`next.config.mjs`、または `next.config.ts`）を読み込みます。設定ファイルを正しく読み込めるように、必要な環境変数と依存関係が利用可能になっていることを確認してください。

### `next upgrade` オプション

`next upgrade` は、Next.js アプリケーションを最新バージョンにアップグレードします。

`next upgrade` コマンドでは、次のオプションが使用できます。

| オプション              | 説明                                                                                                                                                                                        |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `-h, --help`            | 利用可能なすべてのオプションを表示します。                                                                                                                                                  |
| `[directory]`           | アップグレード対象の Next.js アプリケーションがあるディレクトリ。指定しない場合は、カレントディレクトリが使用されます。                                                                     |
| `--revision <revision>` | アップグレード先の Next.js のバージョンまたはタグを指定します（例: `latest`、`canary`、`15.0.0`）。指定しない場合は、現在インストールされているリリースチャネルが既定値として使用されます。 |
| `--verbose`             | アップグレード処理の詳細な出力を表示します。                                                                                                                                                |

### `next experimental-analyze` のオプション

`next experimental-analyze` は、[Turbopack](/docs/app/api-reference/turbopack) を使用してアプリケーションのバンドル出力を分析します。このコマンドは、JavaScript、CSS、その他のアセットを含むバンドルのサイズと構成を把握するのに役立ちます。このコマンドは、アプリケーションのビルドは作成しません。

```bash package="pnpm"
pnpm next experimental-analyze
```

```bash package="npm"
npx next experimental-analyze
```

```bash package="yarn"
yarn next experimental-analyze
```

```bash package="bun"
bunx next experimental-analyze
```

デフォルトでは、コマンドは解析完了後にローカルサーバーを起動し、ブラウザでバンドル構成を確認できるようにします。アナライザーでは次のことができます:

- ルートごとにバンドルをフィルタし、クライアントビューとサーバービューを切り替える
- モジュールが含まれている理由を示す完全なインポートチェーンを表示する
- サーバーからクライアントへのコンポーネント境界や動的インポートをまたいでインポートをトレースする

最適化戦略については、[Package Bundling](/docs/app/guides/package-bundling#optimizing-large-bundles) を参照してください。

サーバーを起動せずに解析結果をディスクに書き出すには、`--output` フラグを使用します。出力は `.next/diagnostics/analyze` に書き込まれ、他の場所にコピーしたり、他者と共有したりできる静的ファイルとして生成されます:

```bash filename="Terminal"
# 出力を .next/diagnostics/analyze に書き込む
npx next experimental-analyze --output

# 今後の分析と比較するために出力をコピーする
cp -r .next/diagnostics/analyze ./analyze-before-refactor
```

`next experimental-analyze` コマンドには、次のオプションが使用できます:

| オプション      | 説明                                                                                                                                                     |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `-h, --help`    | 利用可能なすべてのオプションを表示します。                                                                                                               |
| `[directory]`   | アプリケーションを分析するディレクトリ。指定しない場合、現在のディレクトリが使用されます。                                                               |
| `--no-mangling` | [mangling](https://en.wikipedia.org/wiki/Name_mangling) を無効にします。これはパフォーマンスに影響する可能性があり、デバッグ目的でのみ使用してください。 |
| `--profile`     | 本番環境での React の[プロファイリング](https://react.dev/reference/react/Profiler)を有効にします。これはパフォーマンスに影響する可能性があります。      |
| `-o, --output`  | サーバーを起動せずに分析ファイルをディスクに書き出します。出力は `.next/diagnostics/analyze` に書き出されます。                                          |
| `--port <port>` | アナライザーを提供するポート番号を指定します。(デフォルト: 4000, 環境変数: PORT)                                                                         |

## 例

### プリレンダリングエラーのデバッグ

`next build` の実行中にプリレンダリングエラーが発生した場合は、より詳細な出力を得るために `--debug-prerender` フラグを指定できます。

```bash filename="Terminal"
next build --debug-prerender
```

これはデバッグを容易にするために、いくつかの実験的オプションを有効にします：

- サーバーコードの minify を無効化:
  - `experimental.serverMinification = false`
  - `experimental.turbopackMinify = false`
- サーバーバンドル用のソースマップを生成:
  - `experimental.serverSourceMaps = true`
- プリレンダリングに使用される子プロセスでソースマップの利用を有効化:
  - `enablePrerenderSourceMaps = true`
- 最初のプリレンダリングエラー発生後もビルドを継続し、すべての問題を一度に確認できるようにする:
  - `experimental.prerenderEarlyExit = false`

これにより、ビルド出力内のスタックトレースやコードフレームがより読みやすく表示されるようになります。

> **警告**: `--debug-prerender` は開発時のデバッグ専用です。`--debug-prerender` で生成されたビルドは、本番環境にはデプロイしないでください。パフォーマンスに影響を与える可能性があります。

### 特定のルートをビルドする

`--debug-build-paths` オプションを使用すると、App Router と Pages Router で特定のルートのみをビルドできます。これは、大規模なアプリケーションを扱う際のデバッグを高速化するのに役立ちます。`--debug-build-paths` オプションはカンマ区切りのファイルパスを受け付け、glob パターンをサポートします。

```bash filename="Terminal"
# 特定のルートをビルドする
next build --debug-build-paths="app/page.tsx"

# 複数のルートをビルドする
next build --debug-build-paths="app/page.tsx,pages/index.tsx"

# globパターンを使用する
next build --debug-build-paths="app/**/page.tsx"
next build --debug-build-paths="pages/*.tsx"
```

### デフォルトポートの変更

デフォルトでは、Next.js は開発中および `next start` 実行時に `http://localhost:3000` を使用します。デフォルトのポート番号は、次のように `-p` オプションで変更できます：

```bash filename="Terminal"
next dev -p 4000
```

または、`PORT` 環境変数を指定します:

```bash filename="Terminal"
PORT=4000 next dev
```

> **補足**: HTTP サーバーの起動は他のコードが初期化される前に行われるため、`.env` 内で `PORT` を設定しても有効になりません。

### 開発中に HTTPS を使用する

Webhook や認証など特定のユースケースでは、`localhost` 上に安全な環境を構築するために [HTTPS](https://developer.mozilla.org/en-US/docs/Glossary/HTTPS) を使用できます。Next.js は、`--experimental-https` フラグを付けて `next dev` を実行することで、自己署名証明書を生成できます。

```bash filename="Terminal"
next dev --experimental-https
```

生成された証明書を使用すると、Next.js の開発サーバーは `https://localhost:3000` で利用できます。`-p`、`--port`、または `PORT` でポートを指定しない限り、デフォルトのポート `3000` が使用されます。

`--experimental-https-key` および `--experimental-https-cert` を使って、カスタムの証明書と鍵を指定することもできます。必要に応じて、`--experimental-https-ca` を使ってカスタム CA 証明書を指定することもできます。

```bash filename="Terminal"
next dev --experimental-https --experimental-https-key ./certificates/localhost-key.pem --experimental-https-cert ./certificates/localhost.pem
```

`next dev --experimental-https` は開発用途専用であり、[`mkcert`](https://github.com/FiloSottile/mkcert) を使ってローカルで信頼される証明書を作成します。本番環境では、信頼できる認証局が正規に発行した証明書を使用してください。

### 下流プロキシ用のタイムアウトを設定する

Next.js を下流プロキシ（例: AWS ELB/ALB のようなロードバランサー）の背後にデプロイする場合、Next.js の基盤となる HTTP サーバーの [keep-alive タイムアウト](https://nodejs.org/api/http.html#http_server_keepalivetimeout) を、下流プロキシのタイムアウトよりも _長く_ 設定することが重要です。そうしないと、特定の TCP 接続で keep-alive タイムアウトに達した時点で、Node.js は下流プロキシに通知せずにその接続を即座に切断します。その結果、Node.js がすでに切断した接続をプロキシが再利用しようとするたびに、プロキシエラーが発生します。

本番環境の Next.js サーバーのタイムアウト値を設定するには、`next start` に `--keepAliveTimeout`（ミリ秒単位）を次のように指定します:

```bash filename="Terminal"
next start --keepAliveTimeout 70000
```

### Node.js 引数の指定

`next` コマンドには、任意の [Node.js の引数](https://nodejs.org/api/cli.html#cli_node_options_options) を渡すことができます。例えば、次のように指定します。

```bash filename="Terminal"
NODE_OPTIONS='--throw-deprecation' next
NODE_OPTIONS='-r esm' next
NODE_OPTIONS='--inspect' next
```

### CPU プロファイリング

Next.js アプリケーションのパフォーマンスのボトルネックを分析するために、CPU プロファイルを取得できます。`--experimental-cpu-prof` フラグは V8 の組み込み CPU プロファイラを有効にし、プロセス終了時に `.next/cpu-profiles/` にプロファイルを保存します。

```bash filename="Terminal"
# ビルドプロセスをプロファイリング
next build --experimental-cpu-prof

# 開発サーバーをプロファイリング（Ctrl+C または SIGTERM でプロファイルが保存される）
next dev --experimental-cpu-prof

# 本番サーバーをプロファイリング
next start --experimental-cpu-prof
```

生成された `.cpuprofile` ファイルは、Chrome DevTools（Performance タブ → Load profile）や、その他の V8 互換プロファイラーツールで開くことができます。

> **補足**: プロファイルファイルは、わかりやすいプレフィックスとタイムスタンプ付きの名前で保存されます。生成されるプロファイルは、実行するコマンドによって異なります:
>
> **`next dev`:**
>
> - `dev-main-*` - 親プロセス（開発サーバーのオーケストレーション）
> - `dev-server-*` - 子サーバープロセス（リクエスト処理とレンダリング）- 通常、解析対象となるのはこちらです
>
> **`next build` (Turbopack):**
>
> - `build-main-*` - ビルド全体のオーケストレーションプロセス
> - `build-turbopack-*` - Turbopack のコンパイルワーカー
>
> **`next build` (Webpack):**
>
> - `build-main-*` - ビルド全体のオーケストレーションプロセス
> - `build-webpack-client-*` - クライアントバンドルのコンパイルワーカー
> - `build-webpack-server-*` - サーバーバンドルのコンパイルワーカー
> - `build-webpack-edge-server-*` - Edge Runtime のコンパイルワーカー
>
> **`next start`:**
>
> - `start-main-*` - 本番サーバープロセス
