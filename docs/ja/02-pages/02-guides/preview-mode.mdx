[Pages のドキュメント](/docs/pages/building-your-application/routing/pages-and-layouts)と[データ取得のドキュメント](/docs/pages/building-your-application/data-fetching)では、`getStaticProps` と `getStaticPaths` を使ってビルド時にページを事前レンダリングする（**静的サイト生成**）方法について説明しました。

静的サイト生成は、ページがヘッドレス CMS からデータを取得する場合に便利です。ただし、ヘッドレス CMS 上で下書きを作成していて、その下書きをページ上で即座に**プレビュー**したい場合には最適ではありません。この場合、Next.js にはページをビルド時ではなく**リクエスト時**にレンダリングし、公開済みコンテンツではなく下書きコンテンツを取得してほしくなります。つまり、この特定のケースに限り、Next.js には静的サイト生成を無効化してほしいわけです。

Next.js には、この問題を解決する **Preview Mode** という機能があります。ここでは、その使い方について説明します。

## ステップ 1: プレビュー API ルートを作成してアクセスする

> Next.js の API Routes に慣れていない場合は、まず [API Routes のドキュメント](/docs/pages/building-your-application/routing/api-routes) をご覧ください。

まず、**プレビュー用の API ルート**を作成します。名前は任意で、例としては `pages/api/preview.js`（TypeScript を使用している場合は `.ts`）などとします。

この API ルート内で、レスポンスオブジェクトに対して `setPreviewData` を呼び出す必要があります。`setPreviewData` の引数はオブジェクトである必要があり、これは `getStaticProps` から利用できます（詳細は後述します）。ここでは、ひとまず `{}` を使用します。

```js
export default function handler(req, res) {
  // ...
  res.setPreviewData({})
  // ...
}
```

`res.setPreviewData` はブラウザにいくつかの **Cookie** をセットし、これによってプレビューモードが有効になります。これらの Cookie を含む Next.js へのリクエストは **プレビューモード** とみなされ、静的に生成されたページの挙動が変化します（詳しくは後述します）。

次のような API ルートを作成し、ブラウザから直接アクセスすることで手動でテストできます。

```js filename="pages/api/preview.js"
// ブラウザから手動でテストするためのシンプルな例
export default function handler(req, res) {
  res.setPreviewData({})
  res.end('Preview mode enabled')
}
```

ブラウザの開発者ツールを開いて `/api/preview` にアクセスすると、このリクエストには `__prerender_bypass` と `__next_preview_data` という Cookie が設定されていることを確認できます。

### Headless CMS から安全にアクセスする

実際には、この API ルートを Headless CMS から*安全に*呼び出す必要があります。具体的な手順は利用している Headless CMS によって異なりますが、一般的には次のような手順を取ることができます。

ここで説明する手順は、利用している Headless CMS が **カスタムプレビュー URL** の設定をサポートしていることを前提としています。サポートしていない場合でも、この方法を使ってプレビュー URL を保護することはできますが、プレビュー URL を手動で組み立ててアクセスする必要があります。

**まず**、任意のトークン生成ツールを使って **秘密のトークン文字列** を作成します。このシークレットは Next.js アプリと Headless CMS だけが知っているものになります。このシークレットによって、CMS へのアクセス権限を持たない人がプレビュー URL にアクセスすることを防ぎます。

**次に**、Headless CMS がカスタムプレビュー URL の設定をサポートしている場合は、プレビュー URL として次の値を指定します。ここでは、プレビュー用の API ルートが `pages/api/preview.js` に配置されていると仮定しています。

```bash filename="Terminal"
https://<your-site>/api/preview?secret=<token>&slug=<path>
```

- `<your-site>` には、デプロイ先のドメインを指定します。
- `<token>` には、生成したシークレットトークンを指定します。
- `<path>` には、プレビューしたいページのパスを指定します。たとえば `/posts/foo` をプレビューしたい場合は、`&slug=/posts/foo` を使用します。

利用しているヘッドレス CMS によっては、プレビュー用 URL に変数を含めることで、CMS のデータに基づいて `<path>` を動的に設定できる場合があります。たとえば次のように指定します: `&slug=/posts/{entry.fields.slug}`

**最後に**、プレビュー用の API ルートでは次の処理を行います:

- secret が一致していることと `slug` パラメータが存在することを確認します（存在しない場合はリクエストをエラーとして終了させます）。
-
- `res.setPreviewData` を呼び出します。
- その後、`slug` で指定されたパスへブラウザをリダイレクトします（以下の例では [307 redirect](https://developer.mozilla.org/docs/Web/HTTP/Status/307) を使用しています）。

```js
export default async (req, res) => {
  // シークレットとnextパラメータを検証する
  // このシークレットはこのAPIルートとCMSだけが知っている必要がある
  if (req.query.secret !== 'MY_SECRET_TOKEN' || !req.query.slug) {
    return res.status(401).json({ message: 'Invalid token' })
  }

  // 提供された `slug` が存在するかヘッドレスCMSに問い合わせる
  // getPostBySlugはヘッドレスCMSへの必要なフェッチロジックを実装する
  const post = await getPostBySlug(req.query.slug)

  // slugが存在しない場合、プレビューモードの有効化を防ぐ
  if (!post) {
    return res.status(401).json({ message: 'Invalid slug' })
  }

  // Cookieを設定してプレビューモードを有効にする
  res.setPreviewData({})

  // フェッチした投稿のパスへリダイレクトする
  // オープンリダイレクトの脆弱性を防ぐため、req.query.slugへは直接リダイレクトしない
  res.redirect(post.slug)
}
```

成功すると、プレビューモード用の Cookie が設定された状態で、ブラウザはプレビューしたいパスにリダイレクトされます。

## ステップ 2: `getStaticProps` を更新する

次のステップは、プレビューモードをサポートするように `getStaticProps` を更新することです。

`res.setPreviewData` によってプレビューモード用クッキーが設定された状態で、`getStaticProps` を持つページにリクエストすると、`getStaticProps` は（ビルド時ではなく）**リクエスト時** に呼び出されます。

さらに、その際には次のような `context` オブジェクトが渡されます。

- `context.preview` は `true` になります。
- `context.previewData` は `setPreviewData` に渡された引数と同じ値になります。

```js
export async function getStaticProps(context) {
  // プレビューモードのCookieが設定された状態でこのページにリクエストすると:
  //
  // - context.preview は true になります
  // - context.previewData は `setPreviewData` に
  //   渡された引数と同じ値になります
}
```

プレビュー API ルートでは `res.setPreviewData({})` を使用したため、`context.previewData` は `{}` になります。必要に応じて、これを使ってプレビュー API ルートから `getStaticProps` にセッション情報を渡すことができます。

`getStaticPaths` も使用している場合は、`context.params` も利用可能になります。

### プレビューデータを取得する

`getStaticProps` を更新して、`context.preview` および/または `context.previewData` に基づいて異なるデータを取得できます。

たとえば、ヘッドレス CMS で下書き投稿用に別の API エンドポイントが用意されている場合があります。その場合は、次のように `context.preview` を使って API エンドポイントの URL を変更できます。

```js
export async function getStaticProps(context) {
  // context.preview が true の場合、APIエンドポイントに "/preview" を追加して
  // 公開データの代わりに下書きデータをリクエストする。
  // これは使用しているヘッドレスCMSによって異なる。
  const res = await fetch(`https://.../${context.preview ? 'preview' : ''}`)
  // ...
}
```

以上です！ヘッドレス CMS から、または手動で `secret` と `slug` を付けてプレビュー用 API ルートにアクセスすれば、プレビューコンテンツが表示されるはずです。公開せずに下書きを更新した場合でも、その下書きをプレビューできるはずです。

この URL をヘッドレス CMS のプレビュー URL として設定するか、手動でアクセスすれば、プレビューを確認できるようになります。

```bash filename="Terminal"
https://<your-site>/api/preview?secret=<token>&slug=<path>
```

## 詳細

> **補足**: レンダリング中は、`next/router` が `isPreview` フラグを提供します。詳しくは [router オブジェクトのドキュメント](/docs/pages/api-reference/functions/use-router#router-object) を参照してください。

### プレビューモードの有効期間を指定する

`setPreviewData` は、オプションの第2引数としてオプションオブジェクトを受け取ります。指定できるキーは次のとおりです:

- `maxAge`: プレビューセッションを継続させる時間（秒）を指定します。
- `path`: Cookie を適用するパスを指定します。デフォルトは `/` で、すべてのパスに対してプレビューモードが有効になります。

```js
setPreviewData(data, {
  maxAge: 60 * 60, // プレビューモードのCookieは1時間で期限切れになる
  path: '/about', // プレビューモードのCookieは /about を含むパスに適用される
})
```

### プレビューモードの Cookie をクリアする

デフォルトでは、プレビューモードの Cookie には有効期限が設定されていないため、ブラウザを閉じるとプレビューセッションは終了します。

プレビューモードの Cookie を手動でクリアするには、`clearPreviewData()` を呼び出す API ルートを作成します：

```js filename="pages/api/clear-preview-mode-cookies.js"
export default function handler(req, res) {
  res.clearPreviewData({})
}
```

次に、`/api/clear-preview-mode-cookies` へのリクエストを送信して API Route を呼び出します。[`next/link`](/docs/pages/api-reference/components/link) を使ってこのルートを呼び出す場合、リンクのプリフェッチ時に `clearPreviewData` が実行されてしまうのを防ぐために、`prefetch={false}` を渡す必要があります。

`setPreviewData` の呼び出し時にパスが指定されていた場合は、同じパスを `clearPreviewData` に渡す必要があります。

```js filename="pages/api/clear-preview-mode-cookies.js"
export default function handler(req, res) {
  const { path } = req.query

  res.clearPreviewData({ path })
}
```

### `previewData` のサイズ制限

`setPreviewData` にオブジェクトを渡すと、`getStaticProps` 内で利用できるようになります。ただし、そのデータは Cookie に保存されるため、サイズに制限があります。現在、プレビューデータは 2 KB までに制限されています。

### `getServerSideProps` と併用可能

プレビューモードは `getServerSideProps` でも利用できます。`preview` と `previewData` を含む `context` オブジェクトからも参照できます。

> **補足**: プレビューモードを使用する場合、`Cache-Control` ヘッダーは設定しないでください。プレビューモードではこれを回避できないためです。代わりに、[ISR](/docs/pages/guides/incremental-static-regeneration) の利用を推奨します。

### API Routes でも動作する

API Routes では、リクエストオブジェクトから `preview` と `previewData` にアクセスできます。例：

```js
export default function myApiRoute(req, res) {
  const isPreview = req.preview
  const previewData = req.previewData
  // ...
}
```

### `next build` ごとにユニーク

バイパス Cookie の値と、`previewData` を暗号化するための秘密鍵は、`next build` が完了するたびに変更されます。
これにより、バイパス Cookie が推測されることを防ぎます。

> **補足**: HTTP 経由でローカル環境のプレビューモードをテストするには、ブラウザでサードパーティ Cookie とローカルストレージへのアクセスを許可する必要があります。
