## 12 から 13 へのアップグレード

Next.js をバージョン 13 にアップデートするには、お使いのパッケージマネージャーで次のコマンドを実行してください。

```bash filename="Terminal"
npm i next@13 react@latest react-dom@latest eslint-config-next@13
```

```bash filename="Terminal"
yarn add next@13 react@latest react-dom@latest eslint-config-next@13
```

```bash filename="Terminal"
pnpm i next@13 react@latest react-dom@latest eslint-config-next@13
```

```bash filename="Terminal"
bun add next@13 react@latest react-dom@latest eslint-config-next@13
```

> **補足:** TypeScript を使用している場合は、`@types/react` と `@types/react-dom` も忘れずに最新バージョンへアップグレードしてください。

### v13 の概要

- [Supported Browsers](/docs/architecture/supported-browsers) が更新され、Internet Explorer のサポートが終了し、モダンなブラウザのみを対象とするようになりました。
- 最小 Node.js バージョンが 12.22.0 から 16.14.0 に引き上げられました。これは 12.x および 14.x がサポート終了 (end-of-life) となったためです。
- 最小 React バージョンが 17.0.2 から 18.2.0 に引き上げられました。
- `swcMinify` 設定プロパティのデフォルト値が `false` から `true` に変更されました。詳細は [Next.js Compiler](/docs/architecture/nextjs-compiler) を参照してください。
- `next/image` インポートは `next/legacy/image` に名称変更されました。`next/future/image` インポートは `next/image` に名称変更されました。インポートを安全かつ自動的にリネームするための [codemod が利用可能](/docs/pages/guides/upgrading/codemods#next-image-to-legacy-image) です。
- `next/link` の子要素として `<a>` を使用できなくなりました。レガシーな挙動を利用するには `legacyBehavior` prop を追加するか、アップグレードするには `<a>` を削除してください。コードを自動的にアップグレードするための [codemod が利用可能](/docs/pages/guides/upgrading/codemods#new-link) です。
- `target` 設定プロパティは削除され、代わりに [Output File Tracing](/docs/pages/api-reference/config/next-config-js/output) に置き換えられました。

## 共有機能の移行

Next.js 13 では、新しい機能と規約を備えた [`app` ディレクトリ](/docs/app) が導入されました。ただし、Next.js 13 へアップグレードしても、新しい `app` ルーターを使用する必要は **ありません**。

更新された [Image コンポーネント](#image-component)、[Link コンポーネント](#link-component)、[Script コンポーネント](#script-component)、[フォント最適化](#font-optimization) など、`app` と `pages` の両方のディレクトリで動作する新機能は、引き続き `pages` で利用できます。

### `<Image/>` Component

Next.js 12 では、一時的なインポート先である `next/future/image` を通じて Image コンポーネントに多くの改善が導入されました。これらの改善には、クライアントサイド JavaScript の削減、画像の拡張やスタイリングを簡単に行えるようにする仕組みの提供、アクセシビリティの向上、そしてブラウザネイティブな遅延読み込みが含まれます。

Next.js 13 からは、この新しい挙動が `next/image` のデフォルトになりました。

新しい Image コンポーネントへの移行を支援するために、2 つの codemod が用意されています:

- [next-image-to-legacy-image](/docs/pages/guides/upgrading/codemods#next-image-to-legacy-image): この codemod は、`next/image` のインポートを安全かつ自動的に `next/legacy/image` にリネームし、Next.js 12 と同じ挙動を維持します。Next.js 13 へのアップグレードを自動で素早く行うために、この codemod を実行することを推奨します。
- [next-image-experimental](/docs/pages/guides/upgrading/codemods#next-image-experimental): 前の codemod を実行した後、任意でこの experimental な codemod を実行し、`next/legacy/image` を新しい `next/image` にアップグレードできます。これにより、未使用の props が削除され、インラインスタイルが追加されます。この codemod は experimental であり、静的な使用法 (例: `<Image src={img} layout="responsive" />`) のみを対象としており、動的な使用法 (例: `<Image {...props} />`) は対象外である点に注意してください。

または、[migration guide](/docs/pages/guides/upgrading/codemods#next-image-experimental) に従って手動でアップデートすることもできます。あわせて [legacy comparison](/docs/pages/api-reference/components/image-legacy#comparison) も参照してください。

### `<Link>` コンポーネント

[`<Link>` コンポーネント](/docs/pages/api-reference/components/link) では、子要素として手動で `<a>` タグを追加する必要がなくなりました。この動作は [バージョン 12.2](https://nextjs.org/blog/next-12-2) で実験的オプションとして追加され、現在はデフォルトになっています。Next.js 13 では、`<Link>` は常に `<a>` をレンダリングし、内部のタグに props を渡せるようになりました。

例:

```jsx
import Link from 'next/link'

// Next.js 12: `<a>` をネストする必要があり、そうしないと除外される
<Link href="/about">
  <a>About</a>
</Link>

// Next.js 13: `<Link>` は常に内部で `<a>` をレンダリングする
<Link href="/about">
  About
</Link>
```

リンクを Next.js 13 用に移行するには、[`new-link` codemod](/docs/pages/guides/upgrading/codemods#new-link) を使用できます。

### `<Script>` Component

[`next/script`](/docs/pages/api-reference/components/script) コンポーネントの動作は、`pages` と `app` の両方をサポートするように更新されました。`app` を段階的に導入する場合は、[アップグレードガイド](/docs/pages/guides/upgrading) を参照してください。

### フォント最適化

これまで Next.js は、フォント CSS をインライン化することでフォントの最適化をサポートしていました。バージョン 13 では新しい [`next/font`](/docs/pages/api-reference/components/font) モジュールが導入され、パフォーマンスとプライバシーを確保しつつ、フォントの読み込み方法をカスタマイズできるようになりました。

`next/font` の使い方については、[フォント最適化](/docs/pages/api-reference/components/font) を参照してください。
