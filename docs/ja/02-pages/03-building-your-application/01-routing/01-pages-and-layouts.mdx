title: ページとレイアウト
description: Pages Router を使って最初のページと共通レイアウトを作成します。
---

Pages Router は、ページという概念に基づいたファイルシステムベースのルーターを備えています。

`pages` ディレクトリにファイルを追加すると、そのファイルは自動的にルートとして利用できるようになります。

Next.js では、**ページ**は `pages` ディレクトリ内の `.js`、`.jsx`、`.ts`、または `.tsx` ファイルからエクスポートされる [React Component](https://react.dev/learn/your-first-component) を指します。各ページは、ファイル名に基づいてルートに関連付けられます。

**例**: 次のような React コンポーネントをエクスポートする `pages/about.js` を作成すると、そのページは `/about` でアクセスできるようになります。

```jsx
export default function About() {
  return <div>About</div>
}
```

## インデックスルート

ルーターは `index` という名前のファイルを、そのディレクトリのルートに自動的にルーティングします。

- `pages/index.js` → `/`
- `pages/blog/index.js` → `/blog`

## ネストされたルート

ルーターはネストされたファイル構造もサポートします。フォルダーをネストした構造で作成すると、その構造に対応したパスへ自動的にルーティングされます。

- `pages/blog/first-post.js` → `/blog/first-post`
- `pages/dashboard/settings/username.js` → `/dashboard/settings/username`

## 動的ルートを持つページ

Next.js は動的ルートを持つページをサポートしています。たとえば、`pages/posts/[id].js` というファイルを作成すると、`posts/1` や `posts/2` などのパスでアクセスできるようになります。

> 動的ルーティングの詳細については、[動的ルーティングに関するドキュメント](/docs/pages/building-your-application/routing/dynamic-routes)を参照してください。

## レイアウトパターン

React のモデルでは、[ページ](/docs/pages/building-your-application/routing/pages-and-layouts) を一連のコンポーネントに分割できます。これらのコンポーネントの多くは、ページ間でよく再利用されます。たとえば、すべてのページで同じナビゲーションバーとフッターを表示することがあるでしょう。

```jsx filename="components/layout.js"
import Navbar from './navbar'
import Footer from './footer'

export default function Layout({ children }) {
  return (
    <>
      <Navbar />
      <main>{children}</main>
      <Footer />
    </>
  )
}
```

## 例

### カスタム App を使った単一の共通レイアウト

アプリケーション全体でレイアウトが 1 つだけの場合は、[Custom App](/docs/pages/building-your-application/routing/custom-app) を作成し、そのレイアウトでアプリケーション全体をラップできます。ページを切り替えても `<Layout />` コンポーネントは再利用されるため、そのコンポーネントの状態は保持されます（例: 入力値）。

```jsx filename="pages/_app.js"
import Layout from '../components/layout'

export default function MyApp({ Component, pageProps }) {
  return (
    <Layout>
      <Component {...pageProps} />
    </Layout>
  )
}
```

### ページごとのレイアウト

複数のレイアウトが必要な場合は、ページに `getLayout` プロパティを追加して、レイアウト用の React コンポーネントを返せるようにします。これにより、*ページ単位*でレイアウトを定義できます。関数を返すようにしているので、必要に応じて複雑なネスト構造のレイアウトも実現できます。

```jsx filename="pages/index.js"

import Layout from '../components/layout'
import NestedLayout from '../components/nested-layout'

export default function Page() {
  return (
    /** コンテンツをここに記述 */
  )
}

Page.getLayout = function getLayout(page) {
  return (
    <Layout>
      <NestedLayout>{page}</NestedLayout>
    </Layout>
  )
}
```

```jsx filename="pages/_app.js"
export default function MyApp({ Component, pageProps }) {
  // ページレベルで定義されたレイアウトがあれば使用する
  const getLayout = Component.getLayout ?? ((page) => page)

  return getLayout(<Component {...pageProps} />)
}
```

ページ間をナビゲートするとき、Single-Page Application (SPA) のようなユーザー体験を実現するために、ページの状態（入力値、スクロール位置など）を*保持*しておきたいと考えます。

このレイアウトパターンでは、ページ遷移の間も React コンポーネントツリーが維持されるため、状態を保持できます。コンポーネントツリーが維持されることで、React はどの要素が変更されたかを理解し、状態を保持できます。

> **補足**: この処理は [reconciliation](https://react.dev/learn/preserving-and-resetting-state) と呼ばれ、React がどの要素が変更されたかを理解するしくみです。

### TypeScript を使用する場合

TypeScript を使用する場合は、まず `getLayout` 関数を含むページコンポーネント用の新しい型を作成する必要があります。次に、先ほど作成した型を使用するように `Component` プロパティを上書きする、新しい `AppProps` 型を作成する必要があります。

```tsx filename="pages/index.tsx" switcher
import type { ReactElement } from 'react'
import Layout from '../components/layout'
import NestedLayout from '../components/nested-layout'
import type { NextPageWithLayout } from './_app'

const Page: NextPageWithLayout = () => {
  return <p>hello world</p>
}

Page.getLayout = function getLayout(page: ReactElement) {
  return (
    <Layout>
      <NestedLayout>{page}</NestedLayout>
    </Layout>
  )
}

export default Page
```

```jsx filename="pages/index.js" switcher
import Layout from '../components/layout'
import NestedLayout from '../components/nested-layout'

const Page = () => {
  return <p>hello world</p>
}

Page.getLayout = function getLayout(page) {
  return (
    <Layout>
      <NestedLayout>{page}</NestedLayout>
    </Layout>
  )
}

export default Page
```

```tsx filename="pages/_app.tsx" switcher
import type { ReactElement, ReactNode } from 'react'
import type { NextPage } from 'next'
import type { AppProps } from 'next/app'

export type NextPageWithLayout<P = {}, IP = P> = NextPage<P, IP> & {
  getLayout?: (page: ReactElement) => ReactNode
}

type AppPropsWithLayout = AppProps & {
  Component: NextPageWithLayout
}

export default function MyApp({ Component, pageProps }: AppPropsWithLayout) {
  // ページレベルで定義されたレイアウトを使用する（存在する場合）
  const getLayout = Component.getLayout ?? ((page) => page)

  return getLayout(<Component {...pageProps} />)
}
```

```jsx filename="pages/_app.js" switcher
export default function MyApp({ Component, pageProps }) {
  // ページレベルで定義されたレイアウトがあれば使用する
  const getLayout = Component.getLayout ?? ((page) => page)

  return getLayout(<Component {...pageProps} />)
}
```

### データ取得

レイアウト内では、`useEffect` や [SWR](https://swr.vercel.app/) のようなライブラリを使ってクライアント側でデータを取得できます。このファイルは[ページ](/docs/pages/building-your-application/routing/pages-and-layouts)ではないため、現時点では `getStaticProps` や `getServerSideProps` を使用できません。

```jsx filename="components/layout.js"
import useSWR from 'swr'
import Navbar from './navbar'
import Footer from './footer'

export default function Layout({ children }) {
  const { data, error } = useSWR('/api/navigation', fetcher)

  if (error) return <div>Failed to load</div>
  if (!data) return <div>Loading...</div>

  return (
    <>
      <Navbar links={data.links} />
      <main>{children}</main>
      <Footer />
    </>
  )
}
```
