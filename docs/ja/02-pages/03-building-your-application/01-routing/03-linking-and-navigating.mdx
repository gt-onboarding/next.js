Next.js のルーターを使うと、シングルページアプリケーションのように、ページ間のクライアントサイドのルート遷移を行うことができます。

このクライアントサイドのルート遷移を行うための React コンポーネントとして、`Link` が提供されています。

```jsx
import Link from 'next/link'

function Home() {
  return (
    <ul>
      <li>
        <Link href="/">Home</Link>
      </li>
      <li>
        <Link href="/about">About Us</Link>
      </li>
      <li>
        <Link href="/blog/hello-world">Blog Post</Link>
      </li>
    </ul>
  )
}

export default Home
```

上記の例では複数のリンクを使用しています。それぞれはパス（`href`）を既知のページにマッピングします：

- `/` → `pages/index.js`
- `/about` → `pages/about.js`
- `/blog/hello-world` → `pages/blog/[slug].js`

ビューポート内に表示されている任意の `<Link />`（初期表示時のもの、およびスクロールによって表示されたもの）は、[静的サイト生成](/docs/pages/building-your-application/data-fetching/get-static-props)を使用しているページであれば、対応するデータも含めてデフォルトでプリフェッチされます。[サーバーサイドレンダリング](/docs/pages/building-your-application/data-fetching/get-server-side-props)ルートの対応するデータは、`<Link />` がクリック _されたときにのみ_ 取得されます。

## 動的なパスへのリンク

パスの生成に文字列補間を使用することもできます。これは [動的ルートセグメント](/docs/pages/building-your-application/routing/dynamic-routes) で便利です。たとえば、コンポーネントに `prop` として渡された投稿の一覧を表示する場合は、次のようにします。

```jsx
import Link from 'next/link'

function Posts({ posts }) {
  return (
    <ul>
      {posts.map((post) => (
        <li key={post.id}>
          <Link href={`/blog/${encodeURIComponent(post.slug)}`}>
            {post.title}
          </Link>
        </li>
      ))}
    </ul>
  )
}

export default Posts
```

> この例では、パスを UTF-8 と互換性のある形に保つために [`encodeURIComponent`](https://developer.mozilla.org/docs/Web/JavaScript/Reference/Global_Objects/encodeURIComponent) が使用されています。

別の方法として、URL オブジェクトを使用することもできます。

```jsx
import Link from 'next/link'

function Posts({ posts }) {
  return (
    <ul>
      {posts.map((post) => (
        <li key={post.id}>
          <Link
            href={{
              pathname: '/blog/[slug]',
              query: { slug: post.slug },
            }}
          >
            {post.title}
          </Link>
        </li>
      ))}
    </ul>
  )
}

export default Posts
```

ここでは、パスを生成するために文字列補間を使う代わりに、`href` に URL オブジェクトを渡しており、その各プロパティは次のようになります:

- `pathname` は `pages` ディレクトリ内のページ名です。この例では `/blog/[slug]` になります。
- `query` は動的セグメントを含むオブジェクトで、この例では `slug` プロパティを持つオブジェクトになります。

## router の注入

React コンポーネント内で [`router` オブジェクト](/docs/pages/api-reference/functions/use-router#router-object) にアクセスするには、[`useRouter`](/docs/pages/api-reference/functions/use-router) か [`withRouter`](/docs/pages/api-reference/functions/use-router#withrouter) を使用できます。

通常は [`useRouter`](/docs/pages/api-reference/functions/use-router) を使用することを推奨します。

## 命令的なルーティング

[`next/link`](/docs/pages/api-reference/components/link) はほとんどのルーティングのニーズを満たせますが、これを使わずにクライアントサイドでページ遷移を行うこともできます。その場合は、[`next/router`](/docs/pages/api-reference/functions/use-router) のドキュメントを参照してください。

次の例は、[`useRouter`](/docs/pages/api-reference/functions/use-router) を使って基本的なページ遷移を行う方法を示しています。

```jsx
import { useRouter } from 'next/router'

export default function ReadMore() {
  const router = useRouter()

  return (
    <button onClick={() => router.push('/about')}>
      Click here to read more
    </button>
  )
}
```

Shallow routing を使用すると、URL を変更してもデータ取得メソッドが再度実行されないようにできます。これには [`getServerSideProps`](/docs/pages/building-your-application/data-fetching/get-server-side-props)、[`getStaticProps`](/docs/pages/building-your-application/data-fetching/get-static-props)、[`getInitialProps`](/docs/pages/api-reference/functions/get-initial-props) などが含まれます。

Shallow routing を使うと、状態を失うことなく、更新された `pathname` と `query` を（[`useRouter`](/docs/pages/api-reference/functions/use-router) や [`withRouter`](/docs/pages/api-reference/functions/use-router#withrouter) によって提供される）[`router` オブジェクト](/docs/pages/api-reference/functions/use-router#router-object) 経由で受け取ることができます。

Shallow routing を有効にするには、`shallow` オプションを `true` に設定します。次の例を見てみましょう。

```jsx
import { useEffect } from 'react'
import { useRouter } from 'next/router'

// 現在のURLは '/' です
function Page() {
  const router = useRouter()

  useEffect(() => {
    // 最初のレンダリング後に必ずナビゲーションを実行する
    router.push('/?counter=10', undefined, { shallow: true })
  }, [])

  useEffect(() => {
    // カウンターが変更されました！
  }, [router.query.counter])
}

export default Page
```

URL は `/?counter=10` に更新されますが、ページ自体は置き換えられず、ルートの state だけが更新されます。

また、以下のように [`componentDidUpdate`](https://react.dev/reference/react/Component#componentdidupdate) を使って URL の変更を監視することもできます。

```jsx
componentDidUpdate(prevProps) {
  const { pathname, query } = this.props.router
  // 無限ループを避けるためにpropsが変更されたことを確認する
  if (query.counter !== prevProps.router.query.counter) {
    // 新しいクエリに基づいてデータを取得する
  }
}
```

### 注意事項

シャロー ルーティングは、**現在のページ内**での URL の変更に対してのみ動作します。たとえば、`pages/about.js` という別のページがあり、次のように実行したとします。

```js
router.push('/?counter=10', '/about?counter=10', { shallow: true })
```

それが新しいページである場合は、たとえ shallow routing を指定していても、現在のページはアンロードされ、新しいページがロードされ、データ取得の完了を待つことになります。

shallow routing を proxy と併用する場合、proxy を使わない場合のように、新しいページが現在のページと同一であることは保証されません。これは、proxy が動的に rewrite を行えるためであり、shallow ではスキップされるデータ取得を行わない限り、クライアントサイドで検証できないためです。したがって、shallow のルート変更は常に shallow として扱う必要があります。
