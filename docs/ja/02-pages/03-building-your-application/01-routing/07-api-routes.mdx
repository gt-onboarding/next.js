> **補足**: App Router を使用している場合は、API Routes の代わりに [サーバーコンポーネント](/docs/app/getting-started/server-and-client-components) や [Route Handlers](/docs/app/api-reference/file-conventions/route) を使用できます。

API Routes は、Next.js で **公開 API** を構築するためのソリューションを提供します。

`pages/api` フォルダ内の任意のファイルは `/api/*` にマッピングされ、`page` ではなく API エンドポイントとして扱われます。これらはサーバーサイド専用のバンドルであり、クライアントサイドのバンドルサイズを増やすことはありません。

たとえば、次の API Route は、ステータスコード `200` の JSON レスポンスを返します:

```ts filename="pages/api/hello.ts" switcher
import type { NextApiRequest, NextApiResponse } from 'next'

type ResponseData = {
  message: string
}

export default function handler(
  req: NextApiRequest,
  res: NextApiResponse<ResponseData>
) {
  res.status(200).json({ message: 'Hello from Next.js!' })
}
```

```js filename="pages/api/hello.js" switcher
export default function handler(req, res) {
  res.status(200).json({ message: 'Hello from Next.js!' })
}
```

> **補足**:
>
> - API Routes では[デフォルトで CORS ヘッダーが指定されていません](https://developer.mozilla.org/docs/Web/HTTP/CORS)。つまり、デフォルトでは **same-origin のみ** が許可されます。[CORS request helpers](https://github.com/vercel/next.js/tree/canary/examples/api-routes-cors) でリクエストハンドラーをラップすることで、この挙動をカスタマイズできます。
> - API Routes は [static exports](/docs/pages/guides/static-exports) と併用できません。ただし、App Router の [Route Handlers](/docs/app/api-reference/file-conventions/route) では使用できます。
> - API Routes は、`next.config.js` の [`pageExtensions` 設定](/docs/pages/api-reference/config/next-config-js/pageExtensions) の影響を受けます。

## パラメータ

```tsx
export default function handler(req: NextApiRequest, res: NextApiResponse) {
  // ...
}
```

- `req`: [http.IncomingMessage](https://nodejs.org/api/http.html#class-httpincomingmessage) のインスタンス
- `res`: [http.ServerResponse](https://nodejs.org/api/http.html#class-httpserverresponse) のインスタンス

## HTTP メソッド

API ルートで異なる HTTP メソッドを処理するには、次のようにリクエストハンドラー内で `req.method` を使用できます。

```ts filename="pages/api/hello.ts" switcher
import type { NextApiRequest, NextApiResponse } from 'next'

export default function handler(req: NextApiRequest, res: NextApiResponse) {
  if (req.method === 'POST') {
    // POSTリクエストを処理する
  } else {
    // その他のHTTPメソッドを処理する
  }
}
```

```js filename="pages/api/hello.js" switcher
export default function handler(req, res) {
  if (req.method === 'POST') {
    // POSTリクエストを処理する
  } else {
    // その他のHTTPメソッドを処理する
  }
}
```

## リクエストヘルパー

API Routes には、受信したリクエスト（`req`）を解析するための組み込みのリクエストヘルパーが用意されています:

- `req.cookies` - リクエストによって送信された Cookie を含むオブジェクト。デフォルトは `{}`
- `req.query` - [クエリ文字列](https://en.wikipedia.org/wiki/Query_string) を含むオブジェクト。デフォルトは `{}`
- `req.body` - `content-type` によってパースされたリクエストボディを含むオブジェクト。ボディが送信されていない場合は `null`

### カスタム設定

各 API Route は、以下のデフォルト設定を変更するために `config` オブジェクトをエクスポートできます。

```js
export const config = {
  api: {
    bodyParser: {
      sizeLimit: '1mb',
    },
  },
  // この関数の実行に許可される最大時間を指定する（秒単位）
  maxDuration: 5,
}
```

`bodyParser` はデフォルトで有効です。リクエストボディを `Stream` として処理したい場合や、[`raw-body`](https://www.npmjs.com/package/raw-body) を使って扱いたい場合は、これを `false` に設定できます。

`bodyParser` の自動処理を無効にする代表的なユースケースの 1 つは、**webhook** リクエストの生のリクエストボディを検証できるようにすることです。例えば [GitHub からの webhook](https://docs.github.com/en/developers/webhooks-and-events/webhooks/securing-your-webhooks#validating-payloads-from-github) などです。

```js
export const config = {
  api: {
    bodyParser: false,
  },
}
```

`bodyParser.sizeLimit` は、[bytes](https://github.com/visionmedia/bytes.js) がサポートする任意の形式で指定できる、パースされるボディの最大許容サイズです。例えば次のように指定します:

```js
export const config = {
  api: {
    bodyParser: {
      sizeLimit: '500kb',
    },
  },
}
```

`externalResolver` は、このルートが _express_ や _connect_ などの外部 resolver によって処理されていることをサーバーに明示的に伝えるフラグです。このオプションを有効にすると、解決されていないリクエストに対する警告が表示されなくなります。

```js
export const config = {
  api: {
    externalResolver: true,
  },
}
```

`responseLimit` は自動的に有効になっており、API Routes のレスポンスボディが 4MB を超えると警告が出ます。

サーバーレス環境で Next.js を使用しておらず、CDN や専用のメディアホストを使用しないことによるパフォーマンスへの影響を理解している場合は、この上限を `false` に設定できます。

```js
export const config = {
  api: {
    responseLimit: false,
  },
}
```

`responseLimit` には、バイト数や、`bytes` がサポートしている任意の文字列形式（例: `1000`、`'500kb'`、`'3mb'`）も指定できます。
この値は、警告が表示される前のレスポンスサイズの最大値になります。デフォルトは 4MB です（上記参照）。

```js
export const config = {
  api: {
    responseLimit: '8mb',
  },
}
```

## レスポンスヘルパー

[Server Response オブジェクト](https://nodejs.org/api/http.html#http_class_http_serverresponse)（一般的に `res` と省略されます）には、開発体験を向上させ、新しい API エンドポイントの作成を高速化するための、Express.js に似たヘルパーメソッドがいくつか用意されています。

利用できるヘルパーは次のとおりです。

- `res.status(code)` - ステータスコードを設定する関数です。`code` は有効な [HTTP ステータスコード](https://en.wikipedia.org/wiki/List_of_HTTP_status_codes) である必要があります。
- `res.json(body)` - JSON レスポンスを送信します。`body` は [シリアライズ可能なオブジェクト](https://developer.mozilla.org/docs/Glossary/Serialization) である必要があります。
- `res.send(body)` - HTTP レスポンスを送信します。`body` は `string`、`object`、または `Buffer` を指定できます。
- `res.redirect([status,] path)` - 指定されたパスまたは URL にリダイレクトします。`status` は有効な [HTTP ステータスコード](https://en.wikipedia.org/wiki/List_of_HTTP_status_codes) である必要があります。指定されない場合、`status` のデフォルトは 307（Temporary Redirect）です。
- `res.revalidate(urlPath)` - `getStaticProps` を使用して[オンデマンドでページを再検証します](/docs/pages/guides/incremental-static-regeneration#on-demand-revalidation-with-revalidatepath)。`urlPath` は `string` である必要があります。

### レスポンスのステータスコードを設定する

クライアントへレスポンスを送信する際に、レスポンスのステータスコードを設定できます。

次の例では、レスポンスのステータスコードを `200`（`OK`）に設定し、`message` プロパティに `Hello from Next.js!` という値を含む JSON レスポンスを返します。

```ts filename="pages/api/hello.ts" switcher
import type { NextApiRequest, NextApiResponse } from 'next'

type ResponseData = {
  message: string
}

export default function handler(
  req: NextApiRequest,
  res: NextApiResponse<ResponseData>
) {
  res.status(200).json({ message: 'Hello from Next.js!' })
}
```

```js filename="pages/api/hello.js" switcher
export default function handler(req, res) {
  res.status(200).json({ message: 'Hello from Next.js!' })
}
```

### JSON レスポンスの送信

クライアントへレスポンスを返す際には、JSON レスポンスを送信できます。このレスポンスの内容は[シリアライズ可能なオブジェクト](https://developer.mozilla.org/docs/Glossary/Serialization)である必要があります。
実際のアプリケーションでは、リクエストされたエンドポイントの結果に応じて、クライアントにリクエストのステータスを知らせたい場合があるでしょう。

次の例では、ステータスコード `200`（`OK`）と非同期処理の結果を含む JSON レスポンスを送信します。発生しうるエラーを処理するために try-catch ブロック内に記述されており、発生したエラーに応じた適切なステータスコードとエラーメッセージを捕捉してクライアントに返します。

```ts filename="pages/api/hello.ts" switcher
import type { NextApiRequest, NextApiResponse } from 'next'

export default async function handler(
  req: NextApiRequest,
  res: NextApiResponse
) {
  try {
    const result = await someAsyncOperation()
    res.status(200).json({ result })
  } catch (err) {
    res.status(500).json({ error: 'failed to load data' })
  }
}
```

```js filename="pages/api/hello.js" switcher
export default async function handler(req, res) {
  try {
    const result = await someAsyncOperation()
    res.status(200).json({ result })
  } catch (err) {
    res.status(500).json({ error: 'failed to load data' })
  }
}
```

### HTTP レスポンスの送信

HTTP レスポンスの送信は、JSON レスポンスを送信する場合と同じように動作します。唯一の違いは、レスポンスボディに `string`、`object`、または `Buffer` を指定できる点です。

次の例では、ステータスコード `200`（`OK`）と非同期処理の結果を含む HTTP レスポンスを送信します。

```ts filename="pages/api/hello.ts" switcher
import type { NextApiRequest, NextApiResponse } from 'next'

export default async function handler(
  req: NextApiRequest,
  res: NextApiResponse
) {
  try {
    const result = await someAsyncOperation()
    res.status(200).send({ result })
  } catch (err) {
    res.status(500).send({ error: 'failed to fetch data' })
  }
}
```

```js filename="pages/api/hello.js" switcher
export default async function handler(req, res) {
  try {
    const result = await someAsyncOperation()
    res.status(200).send({ result })
  } catch (err) {
    res.status(500).send({ error: 'failed to fetch data' })
  }
}
```

### 特定のパスまたは URL へのリダイレクト

フォームを例にすると、フォーム送信後にクライアントを特定のパスや URL にリダイレクトしたい場合があります。

次の例では、フォームが正常に送信された場合にクライアントを `/` パスにリダイレクトします。

```ts filename="pages/api/hello.ts" switcher
import type { NextApiRequest, NextApiResponse } from 'next'

export default async function handler(
  req: NextApiRequest,
  res: NextApiResponse
) {
  const { name, message } = req.body

  try {
    await handleFormInputAsync({ name, message })
    res.redirect(307, '/')
  } catch (err) {
    res.status(500).send({ error: 'Failed to fetch data' })
  }
}
```

### TypeScript 型の追加

`next` から `NextApiRequest` と `NextApiResponse` 型をインポートすることで、API Routes をより型安全にすることができます。これらに加えて、レスポンスデータ自体にも型を付けることができます。

```ts
import type { NextApiRequest, NextApiResponse } from 'next'

type ResponseData = {
  message: string
}

export default function handler(
  req: NextApiRequest,
  res: NextApiResponse<ResponseData>
) {
  res.status(200).json({ message: 'Hello from Next.js!' })
}
```

> **補足**: クライアントは任意のペイロードを含めることができるため、`NextApiRequest` の body は `any` 型です。利用する前に、実行時に body の型や構造を検証するようにしてください。

## 動的な API ルート

API Routes でも[動的ルート](/docs/pages/building-your-application/routing/dynamic-routes)が利用でき、`pages/` ディレクトリと同じファイル命名規則に従います。

```ts filename="pages/api/post/[pid].ts" switcher
import type { NextApiRequest, NextApiResponse } from 'next'

export default function handler(req: NextApiRequest, res: NextApiResponse) {
  const { pid } = req.query
  res.end(`Post: ${pid}`)
}
```

```js filename="pages/api/post/[pid].js" switcher
export default function handler(req, res) {
  const { pid } = req.query
  res.end(`Post: ${pid}`)
}
```

これで、`/api/post/abc` へのリクエストには、`Post: abc` というテキストで応答します。

### キャッチオール API ルート

API Routes は、角括弧内にドット 3 つ（`...`）を追加することで、すべてのパスをキャッチするように拡張できます。例えば:

- `pages/api/post/[...slug].js` は `/api/post/a` にマッチしますが、`/api/post/a/b`、`/api/post/a/b/c` などにもマッチします。

> **補足**: `slug` 以外の名前も使用できます（例: `[...param]`）。

マッチしたパラメータは、ページにクエリパラメータ（この例では `slug`）として渡され、常に配列になります。そのため、パス `/api/post/a` では、次のような `query` オブジェクトになります:

```json
{ "slug": ["a"] }
```

また、`/api/post/a/b` の場合や、その他のマッチするパスでは、次のように配列に新しいパラメータが追加されます。

```json
{ "slug": ["a", "b"] }
```

例えば、

```ts filename="pages/api/post/[...slug].ts" switcher
import type { NextApiRequest, NextApiResponse } from 'next'

export default function handler(req: NextApiRequest, res: NextApiResponse) {
  const { slug } = req.query
  res.end(`Post: ${slug.join(', ')}`)
}
```

```js filename="pages/api/post/[...slug].js" switcher
export default function handler(req, res) {
  const { slug } = req.query
  res.end(`Post: ${slug.join(', ')}`)
}
```

これで、`/api/post/a/b/c` へのリクエストには、`Post: a, b, c` というテキストが返されます。

### オプションのキャッチオール API ルート

キャッチオールルートは、パラメーターを二重角括弧で囲むことでオプションとして扱うことができます（`[[...slug]]`）。

たとえば、`pages/api/post/[[...slug]].js` は `/api/post`、`/api/post/a`、`/api/post/a/b` などにマッチします。

キャッチオールルートとオプションのキャッチオールルートの主な違いは、オプションの場合、パラメーターなしのルートもマッチする点です（上記の例では `/api/post`）。

`query` オブジェクトは次のようになります。

```json
{ } // GET `/api/post`（空のオブジェクト）
{ "slug": ["a"] } // `GET /api/post/a`（単一要素の配列）
{ "slug": ["a", "b"] } // `GET /api/post/a/b`（複数要素の配列）
```

### 注意点

- あらかじめ定義された API ルートが動的 API ルートよりも優先され、動的 API ルートがキャッチオール API ルートよりも優先されます。次の例を参照してください:
  - `pages/api/post/create.js` - `/api/post/create` にマッチします
  - `pages/api/post/[pid].js` - `/api/post/1`、`/api/post/abc` などにマッチします。ただし `/api/post/create` にはマッチしません
  - `pages/api/post/[...slug].js` - `/api/post/1/2`、`/api/post/a/b/c` などにマッチします。ただし `/api/post/create` や `/api/post/abc` にはマッチしません

## ストリーミングレスポンス

Pages Router でも API Routes を使ったストリーミングレスポンスはサポートされていますが、Next.js 14 以降を利用している場合は、App Router を段階的に導入し、[Route Handlers](/docs/app/api-reference/file-conventions/route) を使用することを推奨します。

ここでは、`writeHead` を使って API Route からレスポンスをストリーミングする方法を示します:

```ts filename="pages/api/hello.ts" switcher
import { NextApiRequest, NextApiResponse } from 'next'

export default async function handler(
  req: NextApiRequest,
  res: NextApiResponse
) {
  res.writeHead(200, {
    'Content-Type': 'text/event-stream',
    'Cache-Control': 'no-store',
  })
  let i = 0
  while (i < 10) {
    res.write(`data: ${i}\n\n`)
    i++
    await new Promise((resolve) => setTimeout(resolve, 1000))
  }
  res.end()
}
```
