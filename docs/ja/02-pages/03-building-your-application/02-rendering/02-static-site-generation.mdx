ページが**静的サイト生成**を使用する場合、そのページの HTML は**ビルド時**に生成されます。つまり、本番環境では `next build` を実行したときにページの HTML が生成されます。この HTML はその後、各リクエストで再利用されます。CDN にキャッシュすることもできます。

Next.js では、ページを**データの有無にかかわらず**静的生成できます。それぞれのケースを見ていきましょう。

### データなしの静的生成

デフォルトでは、Next.js はデータ取得を行わずに静的生成を使ってページを事前レンダリングします。次に例を示します。

```jsx
function About() {
  return <div>About</div>
}

export default About
```

このページは、事前レンダリングのために外部データを取得する必要がない点に注意してください。このような場合、Next.js はビルド時にページごとに 1 つの HTML ファイルを生成します。

### データを伴う静的生成

一部のページでは、プリレンダリングのために外部データのフェッチが必要になります。想定されるシナリオは 2 つあり、どちらか一方または両方が該当する可能性があります。いずれの場合でも、Next.js が提供する次の関数を使用できます：

1. ページの**コンテンツ**が外部データに依存している場合：`getStaticProps` を使用します。
2. ページの**パス**が外部データに依存している場合：`getStaticPaths` を使用します（通常は `getStaticProps` と併用します）。

#### シナリオ 1: ページのコンテンツが外部データに依存する場合

**例**: ブログページで、CMS（コンテンツ管理システム）からブログ記事の一覧を取得する必要がある場合があります。

```jsx
// TODO: このページがプリレンダリングされる前に、
//       （APIエンドポイントを呼び出して）`posts` をフェッチする必要がある
export default function Blog({ posts }) {
  return (
    <ul>
      {posts.map((post) => (
        <li>{post.title}</li>
      ))}
    </ul>
  )
}
```

このデータをプレレンダー時に取得するために、Next.js では同じファイル内で `getStaticProps` という名前の `async` 関数を `export` できます。この関数はビルド時に実行され、取得したデータをプレレンダー時にページの `props` として渡すことができます。

```jsx
export default function Blog({ posts }) {
  // 投稿をレンダリングする...
}

// この関数はビルド時に呼び出される
export async function getStaticProps() {
  // 外部APIエンドポイントを呼び出して投稿を取得する
  const res = await fetch('https://.../posts')
  const posts = await res.json()

  // { props: { posts } } を返すことで、Blog コンポーネントは
  // ビルド時に `posts` をプロップとして受け取る
  return {
    props: {
      posts,
    },
  }
}
```

`getStaticProps` の仕組みについてさらに詳しく知るには、[データ取得のドキュメント](/docs/pages/building-your-application/data-fetching/get-static-props)を参照してください。

#### シナリオ 2: ページパスが外部データに依存する場合

Next.js では、**動的ルート**を使ってページを作成できます。たとえば、`id` に基づいて単一のブログ投稿を表示するために、`pages/posts/[id].js` というファイルを作成できます。これにより、`posts/1` にアクセスしたときに `id: 1` のブログ投稿を表示できます。

> 動的ルーティングの詳細は、[動的ルーティングのドキュメント](/docs/pages/building-your-application/routing/dynamic-routes)を参照してください。

ただし、ビルド時にどの `id` のページをプリレンダリングするかは、外部データに依存する場合があります。

**例**: データベースにブログ投稿を 1 件（`id: 1`）だけ追加したとします。この場合、ビルド時にプリレンダリングしたいのは `posts/1` だけです。

その後、`id: 2` の 2 件目の投稿を追加するかもしれません。そのときには `posts/2` もプリレンダリングする必要があります。

このように、プリレンダリングされるページの **パス** は外部データに依存します。これに対応するために、Next.js では動的ページ（この例では `pages/posts/[id].js`）から `getStaticPaths` という `async` 関数を `export` できます。この関数はビルド時に呼び出され、どのパスをプリレンダリングするかを指定できます。

```jsx
// この関数はビルド時に呼び出される
export async function getStaticPaths() {
  // 外部APIエンドポイントを呼び出して投稿を取得する
  const res = await fetch('https://.../posts')
  const posts = await res.json()

  // 投稿に基づいてプリレンダリングしたいパスを取得する
  const paths = posts.map((post) => ({
    params: { id: post.id },
  }))

  // ビルド時にこれらのパスのみをプリレンダリングする。
  // { fallback: false } は、その他のルートが404になることを意味する。
  return { paths, fallback: false }
}
```

また、`pages/posts/[id].js` では、この `id` に対応する投稿データを取得し、それを使ってページを事前レンダリングできるようにするために、`getStaticProps` をエクスポートする必要があります。

```jsx
export default function Post({ post }) {
  // 投稿をレンダリングする...
}

export async function getStaticPaths() {
  // ...
}

// こちらもビルド時に呼び出される
export async function getStaticProps({ params }) {
  // params には投稿の `id` が含まれる。
  // ルートが /posts/1 の場合、params.id は 1 になる
  const res = await fetch(`https://.../posts/${params.id}`)
  const post = await res.json()

  // プロップを通じてページに投稿データを渡す
  return { props: { post } }
}
```

`getStaticPaths` の動作についてさらに詳しく知るには、[データ取得に関するドキュメント](/docs/pages/building-your-application/data-fetching/get-static-paths)を参照してください。

### いつ静的サイト生成を使うべきですか？

可能な限り**静的サイト生成**（データあり・なしの両方）を使用することを推奨します。ページを一度ビルドして CDN から配信できるため、リクエストごとにサーバーでレンダリングする場合よりもはるかに高速になるからです。

静的サイト生成は、次のような多くの種類のページに使用できます:

- マーケティングページ
- ブログ記事やポートフォリオ
- EC サイトの商品一覧
- ヘルプやドキュメント

次のように自問してみてください: 「ユーザーのリクエスト**前**にこのページをプリレンダリングできるか？」。もし答えが「はい」であれば、静的サイト生成を選ぶべきです。

一方で、ユーザーのリクエスト前にページをプリレンダリングできない場合、静的サイト生成は適して**いません**。たとえば、ページで頻繁に更新されるデータを表示していて、リクエストのたびにコンテンツが変わる場合などです。

このようなケースでは、次のいずれかの方法を使うことができます:

- **クライアントサイドのデータフェッチ**を伴う静的サイト生成を使う: ページの一部はプリレンダリングをスキップし、その部分はクライアントサイドの JavaScript を使って埋めることができます。このアプローチの詳細については、[データ取得のドキュメント](/docs/pages/building-your-application/data-fetching/client-side)を参照してください。
- **サーバーサイドレンダリング**を使う: Next.js はリクエストごとにページをプリレンダリングします。CDN によるキャッシュができないためより遅くなりますが、プリレンダリングされたページは常に最新の状態になります。このアプローチについては後ほど説明します。
