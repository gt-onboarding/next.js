Next.js はデフォルトで、すべてのページを**事前レンダリング**します。これは、クライアント側の JavaScript ですべてを処理するのではなく、各ページの HTML をあらかじめ生成するという意味です。事前レンダリングにより、パフォーマンスや SEO が向上する場合があります。

生成された各 HTML には、そのページに必要な最小限の JavaScript コードが関連付けられます。ブラウザでページが読み込まれると、その JavaScript コードが実行され、ページが完全にインタラクティブになります（この処理は React では [hydration](https://react.dev/reference/react-dom/client/hydrateRoot) と呼ばれます）。

### プレレンダリング

Next.js には 2 つの形式のプレレンダリングがあります: **静的サイト生成（Static Generation）** と **サーバーサイドレンダリング（Server-side Rendering）** です。違いは、ページの HTML を **いつ** 生成するかです。

- 静的サイト生成: HTML は **ビルド時** に生成され、各リクエストで再利用されます。
- サーバーサイドレンダリング: HTML は **各リクエストごと** に生成されます。

重要な点として、Next.js ではページごとにどのプレレンダリング形式を使うかを選択できます。多くのページには静的サイト生成を使い、一部のページにはサーバーサイドレンダリングを使うことで、「ハイブリッド」な Next.js アプリを構築できます。

パフォーマンス上の理由からは、サーバーサイドレンダリングよりも静的サイト生成を使うことを推奨します。静的に生成されたページは、追加の設定なしで CDN によってキャッシュできるため、パフォーマンスを向上させることができます。ただし、場合によってはサーバーサイドレンダリングが唯一の選択肢となることもあります。

静的サイト生成またはサーバーサイドレンダリングと併せて、クライアント側でのデータフェッチも使用できます。これは、ページの一部をクライアント側の JavaScript のみでレンダリングできることを意味します。詳細については、[データフェッチ](/docs/pages/building-your-application/data-fetching/client-side) のドキュメントを参照してください。
