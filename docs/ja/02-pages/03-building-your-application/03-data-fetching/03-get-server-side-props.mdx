title: getServerSideProps
description: '`getServerSideProps` を使用して、リクエストごとにデータを取得します。'
---

`getServerSideProps` は、リクエストごとにデータを取得し、ページの内容をレンダリングするために使用できる Next.js の関数です。

## 例

`getServerSideProps` は、ページコンポーネントからエクスポートすることで利用できます。次の例では、`getServerSideProps` 内でサードパーティー API からデータを取得し、そのデータを props としてページに渡す方法を示しています。

```tsx filename="pages/index.tsx" switcher
import type { InferGetServerSidePropsType, GetServerSideProps } from 'next'

type Repo = {
  name: string
  stargazers_count: number
}

export const getServerSideProps = (async () => {
  // 外部APIからデータを取得
  const res = await fetch('https://api.github.com/repos/vercel/next.js')
  const repo: Repo = await res.json()
  // propsを通じてページにデータを渡す
  return { props: { repo } }
}) satisfies GetServerSideProps<{ repo: Repo }>

export default function Page({
  repo,
}: InferGetServerSidePropsType<typeof getServerSideProps>) {
  return (
    <main>
      <p>{repo.stargazers_count}</p>
    </main>
  )
}
```

```jsx filename="pages/index.js" switcher
export async function getServerSideProps() {
  // 外部APIからデータを取得する
  const res = await fetch('https://api.github.com/repos/vercel/next.js')
  const repo = await res.json()
  // propsを通じてページにデータを渡す
  return { props: { repo } }
}

export default function Page({ repo }) {
  return (
    <main>
      <p>{repo.stargazers_count}</p>
    </main>
  )
}
```

## `getServerSideProps` はいつ使うべきですか？

パーソナライズされたユーザーデータや、リクエスト時にならないと分からない情報に依存するページをレンダリングする必要がある場合は、`getServerSideProps` を使用すべきです。たとえば、`authorization` ヘッダーや位置情報などです。

データをリクエスト時にフェッチする必要がない場合や、データと事前レンダリングされた HTML をキャッシュしたい場合は、[`getStaticProps`](/docs/pages/building-your-application/data-fetching/get-static-props) の使用を推奨します。

## 動作

- `getServerSideProps` はサーバー上で実行されます。
- `getServerSideProps` は **page** からのみエクスポートできます。
- `getServerSideProps` は JSON を返します。
- ユーザーがページにアクセスすると、`getServerSideProps` がリクエスト時にデータを取得し、そのデータを使ってページの初期 HTML がレンダリングされます。
- ページコンポーネントに渡される `props` は、初期 HTML の一部としてクライアント側で確認できます。これはページを正しく[ハイドレーション](https://react.dev/reference/react-dom/hydrate)するためです。クライアントで利用可能であるべきではない機密情報を `props` に渡さないように注意してください。
- ユーザーが [`next/link`](/docs/pages/api-reference/components/link) や [`next/router`](/docs/pages/api-reference/functions/use-router) を通じてページにアクセスすると、Next.js はサーバーに対して API リクエストを送信し、その中で `getServerSideProps` が実行されます。
- `getServerSideProps` を使用する場合、関数自体がサーバー上で実行されるため、データ取得のために Next.js の [API Route](/docs/pages/building-your-application/routing/api-routes) を呼び出す必要はありません。代わりに、`getServerSideProps` の内部から CMS やデータベース、その他のサードパーティ API を直接呼び出すことができます。

> **補足:**
>
> - `getServerSideProps` で使用できる引数や props については、[`getServerSideProps` API リファレンス](/docs/pages/api-reference/functions/get-server-side-props) を参照してください。
> - [next-code-elimination ツール](https://next-code-elimination.vercel.app/) を使用して、Next.js がクライアントサイドバンドルから何を削除するかを確認できます。

## エラー処理

`getServerSideProps` 内でエラーがスローされた場合、`pages/500.js` ファイルが表示されます。[500 ページ](/docs/pages/building-your-application/routing/custom-error#500-page) の作成方法の詳細については、ドキュメントを参照してください。開発モードではこのファイルは使用されず、代わりに開発用のエラーオーバーレイが表示されます。

## エッジケース

### サーバーサイドレンダリング (SSR) におけるキャッシング

`getServerSideProps` 内でキャッシュヘッダー（`Cache-Control`）を使用して、動的レスポンスをキャッシュできます。たとえば、[`stale-while-revalidate`](https://web.dev/stale-while-revalidate/) を利用できます。

```jsx
// この値は10秒間フレッシュとみなされます（s-maxage=10）。
// 次の10秒以内にリクエストが繰り返された場合、以前の
// キャッシュ値は引き続きフレッシュです。59秒以内にリクエストが繰り返された場合、
// キャッシュ値は古くなりますが、引き続きレンダリングされます（stale-while-revalidate=59）。
//
// バックグラウンドでは、キャッシュを新しい値で更新するための
// 再検証リクエストが行われます。ページを更新すると、新しい値が表示されます。
export async function getServerSideProps({ req, res }) {
  res.setHeader(
    'Cache-Control',
    'public, s-maxage=10, stale-while-revalidate=59'
  )

  return {
    props: {},
  }
}
```

しかし、`cache-control` を使う前に、ユースケースによっては [`getStaticProps`](/docs/pages/building-your-application/data-fetching/get-static-props) と [ISR](/docs/pages/guides/incremental-static-regeneration) の組み合わせのほうが適しているか検討することをおすすめします。
