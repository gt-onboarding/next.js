---

ページコンポーネントから `getServerSideProps`（サーバーサイドレンダリング）という関数をエクスポートすると、Next.js は `getServerSideProps` が返すデータを使って、各リクエストごとにこのページを事前レンダリングします。これは、頻繁に変化するデータを取得し、ページを常に最新の状態で表示したい場合に便利です。

```tsx filename="pages/index.tsx" switcher
import type { InferGetServerSidePropsType, GetServerSideProps } from 'next'

type Repo = {
  name: string
  stargazers_count: number
}

export const getServerSideProps = (async () => {
  // 外部APIからデータを取得する
  const res = await fetch('https://api.github.com/repos/vercel/next.js')
  const repo: Repo = await res.json()
  // propsを通じてページにデータを渡す
  return { props: { repo } }
}) satisfies GetServerSideProps<{ repo: Repo }>

export default function Page({
  repo,
}: InferGetServerSidePropsType<typeof getServerSideProps>) {
  return (
    <main>
      <p>{repo.stargazers_count}</p>
    </main>
  )
}
```

```jsx filename="pages/index.js" switcher
export async function getServerSideProps() {
  // 外部APIからデータを取得する
  const res = await fetch('https://api.github.com/repos/vercel/next.js')
  const repo = await res.json()
  // propsを通じてページにデータを渡す
  return { props: { repo } }
}

export default function Page({ repo }) {
  return (
    <main>
      <p>{repo.stargazers_count}</p>
    </main>
  )
}
```

`getServerSideProps` で使用するモジュールは、トップレベルスコープで import できます。これらの import は**クライアントサイド用のバンドルには含まれません**。つまり、データベースからのデータ取得を含めて、**サーバーサイドのコードを `getServerSideProps` 内に直接記述できる**ということです。

## Context パラメーター

`context` パラメーターは、次のキーを含むオブジェクトです:

| Name            | Description                                                                                                                                                                                                                      |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `params`        | このページが[動的ルート](/docs/pages/building-your-application/routing/dynamic-routes)を使用している場合、`params` にはルートパラメーターが含まれます。ページ名が `[id].js` の場合、`params` は `{ id: ... }` のようになります。 |
| `req`           | [`HTTP` IncomingMessage オブジェクト](https://nodejs.org/api/http.html#http_class_http_incomingmessage)。追加で `cookies` プロパティを持ち、これは文字列キーと、そのキーに対応するクッキーの文字列値からなるオブジェクトです。   |
| `res`           | [`HTTP` response オブジェクト](https://nodejs.org/api/http.html#http_class_http_serverresponse)。                                                                                                                                |
| `query`         | 動的ルートのパラメーターを含む、クエリ文字列を表すオブジェクトです。                                                                                                                                                             |
| `preview`       | (`draftMode` の導入に伴い非推奨) ページが[プレビューモード](/docs/pages/guides/preview-mode)の場合は `true`、それ以外は `false` です。                                                                                           |
| `previewData`   | (`draftMode` の導入に伴い非推奨) `setPreviewData` によって設定された[プレビュー](/docs/pages/guides/preview-mode)データです。                                                                                                    |
| `draftMode`     | ページが[Draft Mode](/docs/pages/guides/draft-mode) の場合は `true`、それ以外は `false` です。                                                                                                                                   |
| `resolvedUrl`   | クライアントトランジション時に `_next/data` プレフィックスを取り除き、元のクエリ値を含む、正規化されたリクエストの `URL` です。                                                                                                  |
| `locale`        | 有効化されている場合、アクティブなロケールが含まれます。                                                                                                                                                                         |
| `locales`       | 有効化されている場合、サポートされているすべてのロケールが含まれます。                                                                                                                                                           |
| `defaultLocale` | 有効化されている場合、設定されたデフォルトロケールが含まれます。                                                                                                                                                                 |

## getServerSideProps の戻り値

`getServerSideProps` 関数は、**以下のいずれか一つ**のプロパティを含むオブジェクトを返す必要があります。

### `props`

`props` オブジェクトはキーと値のペアから成り、各値はページコンポーネントで受け取られます。渡される props は [`JSON.stringify`](https://developer.mozilla.org/docs/Web/JavaScript/Reference/Global_Objects/JSON/stringify) でシリアライズできるように、[シリアライズ可能なオブジェクト](https://developer.mozilla.org/docs/Glossary/Serialization) である必要があります。

```jsx
export async function getServerSideProps(context) {
  return {
    props: { message: `Next.js is awesome` }, // ページコンポーネントにpropsとして渡されます
  }
}
```

### `notFound`

`notFound` ブール値を使用すると、ページが `404` ステータスと [404 Page](/docs/pages/building-your-application/routing/custom-error#404-page) を返すようにできます。`notFound: true` を指定すると、以前にページが正常に生成されていた場合でも `404` を返します。この挙動は、ユーザー生成コンテンツが作者によって削除されるといったユースケースを想定したものです。

```js
export async function getServerSideProps(context) {
  const res = await fetch(`https://.../data`)
  const data = await res.json()

  if (!data) {
    return {
      notFound: true,
    }
  }

  return {
    props: { data }, // ページコンポーネントにpropsとして渡される
  }
}
```

### `redirect`

`redirect` オブジェクトを使用すると、内部および外部リソースへのリダイレクトを行うことができます。これは `{ destination: string, permanent: boolean }` の形に従っている必要があります。まれに、古い `HTTP` クライアントを正しくリダイレクトするために、カスタムステータスコードを指定する必要があるかもしれません。そのような場合は、`permanent` プロパティの代わりに `statusCode` プロパティを使用できますが、両方を同時に使用することはできません。

```js
export async function getServerSideProps(context) {
  const res = await fetch(`https://.../data`)
  const data = await res.json()

  if (!data) {
    return {
      redirect: {
        destination: '/',
        permanent: false,
      },
    }
  }

  return {
    props: {}, // ページコンポーネントにpropsとして渡される
  }
}
```
