title: 高速リフレッシュ

---

Fast Refresh は Next.js に統合された React の機能で、ファイルを保存したときに、一時的なクライアントサイドの状態を維持したままブラウザーページをライブリロードできるようにします。これは **9.4 以降** のすべての Next.js アプリケーションでデフォルトで有効になっています。Fast Refresh が有効な場合、ほとんどの編集内容は 1 秒以内に反映されます。

## 仕組み

- **React コンポーネントだけを export している**ファイルを編集した場合、Fast Refresh はそのファイルのコードだけを更新し、コンポーネントを再レンダーします。そのファイル内のスタイル、レンダリングロジック、イベントハンドラー、エフェクトなど、何でも編集できます。
- React コンポーネントでは _ない_ export を含むファイルを編集した場合、Fast Refresh はそのファイルと、それを import している他のファイルの両方を再実行します。たとえば `Button.js` と `Modal.js` の両方が `theme.js` を import している場合、`theme.js` を編集すると両方のコンポーネントが更新されます。
- 最後に、**ファイルを編集**していて、そのファイルが **React ツリーの外側のファイルから import されている**場合、Fast Refresh は**フォールバックとして完全リロードを行います**。React コンポーネントをレンダーしつつ、同時に **非 React コンポーネント**から import される値も export しているファイルがあるかもしれません。たとえば、コンポーネントが定数も export しており、非 React のユーティリティファイルがそれを import しているケースです。その場合は、その定数を別ファイルに切り出し、両方のファイルからその新しいファイルを import することを検討してください。これにより Fast Refresh が再び動作するようになります。他のケースでも、たいていは同様の方法で解決できます。

## エラー耐性

### 構文エラー

開発中に構文エラーを発生させてしまっても、修正してファイルを再度保存すれば問題ありません。エラーは自動的に消えるため、アプリをリロードする必要はありません。**コンポーネントの状態は失われません**。

### 実行時エラー

コンポーネント内で実行時エラーにつながるミスをすると、
その文脈に応じたオーバーレイが表示されます。エラーを修正すると、
アプリをリロードすることなくオーバーレイは自動的に閉じられます。

エラーがレンダリング中に発生しなかった場合、コンポーネントの state は保持されます。
レンダリング中にエラーが発生した場合は、React が更新されたコードを使って
アプリケーションを再マウントします。

アプリ内に[エラーバウンダリ](https://react.dev/reference/react/Component#catching-rendering-errors-with-an-error-boundary)
がある場合（本番環境で障害を穏やかに処理するためにも推奨されます）、レンダリングエラーが発生した後の
次回の編集時に、再度レンダリングを試行します。これは、エラーバウンダリを持つことで、
常にルートのアプリ state にリセットされるのを防げることを意味します。ただし、
エラーバウンダリを _細かくしすぎるべきではない_ ことに注意してください。
エラーバウンダリは本番環境でも React によって使用される仕組みであり、常に意図を持って
設計する必要があります。

## 制限事項

Fast Refresh は、編集中のコンポーネントのローカルな React state を安全と判断できる場合に限り保持しようとします。ファイルを編集するたびにローカル state がリセットされる可能性がある理由として、次のようなものが考えられます。

- ローカル state はクラスコンポーネントでは保持されません（state が保持されるのは関数コンポーネントと Hooks のみです）。
- 編集しているファイルに、React コンポーネントに加えて _別の_ export が含まれている可能性があります。
- ときどき、ファイルが `HOC(WrappedComponent)` のような高階コンポーネント呼び出しの結果を export している場合があります。返されるコンポーネントがクラスの場合、その state はリセットされます。
- `export default () => <div />;` のような匿名アロー関数は、Fast Refresh がローカルコンポーネント state を保持しない原因になります。大規模なコードベースでは、[`name-default-component` codemod](/docs/pages/guides/upgrading/codemods#name-default-component) を利用できます。

コードベースのより多くの部分が関数コンポーネントと Hooks に移行されるにつれて、より多くのケースで state が保持されるようになることが期待できます。

## ヒント

- Fast Refresh は、デフォルトで関数コンポーネント（および Hooks）内の React のローカル state を保持します。
- state を強制的にリセットし、コンポーネントを再マウントさせたい場合もあります。たとえば、マウント時にのみ実行されるアニメーションを調整しているときに便利です。そのためには、編集中のファイル内の任意の場所に `// @refresh reset` を追加します。このディレクティブはそのファイルにのみ有効で、そのファイルで定義されたコンポーネントを編集のたびに再マウントするよう Fast Refresh に指示します。
- 開発中に編集しているコンポーネントの中に `console.log` や `debugger;` を書くことができます。
- import は大文字・小文字を区別することに注意してください。実際のファイル名と import が一致していない場合、Fast Refresh とフルリフレッシュの両方が失敗することがあります。
たとえば、`'./header'` と `'./Header'` などです
  。

## Fast Refresh と Hooks

可能な場合、Fast Refresh は編集の間でコンポーネントの state を保持しようとします。特に、`useState` と `useRef` は、その引数や Hook 呼び出しの順序を変更しない限り、これまでの値を保持します。

`useEffect`、`useMemo`、`useCallback` のような依存配列を持つ Hook は、Fast Refresh 中は _必ず_ 更新されます。Fast Refresh 中は、それらの依存配列は無視されます。

たとえば、`useMemo(() => x * 2, [x])` を
`useMemo(() => x * 10, [x])` に編集すると、`x`（依存値）が変わっていなくても再実行されます。もし React がこれを行わなければ、編集内容が画面に反映されません。

場合によっては、これが予期しない結果につながることがあります。たとえば、依存配列が空の `useEffect` であっても、Fast Refresh 中に一度は再実行されます。

しかし、Fast Refresh がなくても、ときどき `useEffect` が再実行されることに対して堅牢なコードを書くことは良いプラクティスです。そうしておくと、あとから新しい依存関係を追加しやすくなりますし、この方針は [React Strict Mode](/docs/pages/api-reference/config/next-config-js/reactStrictMode) によっても強制されます。Strict Mode の有効化を強く推奨します。
