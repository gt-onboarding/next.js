---
title: Next.js コンパイラ
description: Rust で書かれた Next.js コンパイラは、Next.js アプリケーションを変換および縮小（minify）します。
---

Rust 製で [SWC](https://swc.rs/) を利用した Next.js コンパイラにより、Next.js は本番環境向けに JavaScript コードを変換および縮小（minify）できます。これにより、各ファイルの変換に使用していた Babel と、出力バンドルの縮小に使用していた Terser が置き換えられます。

Next.js コンパイラによるコンパイルは Babel よりも 17 倍高速で、Next.js バージョン 12 以降ではデフォルトで有効になっています。既存の Babel 設定がある場合、または[未サポートの機能](#unsupported-features)を使用している場合、アプリケーションは Next.js コンパイラの利用からオプトアウトし、引き続き Babel を使用します。

## なぜ SWC なのか？

[SWC](https://swc.rs/) は、次世代の高速な開発者向けツールのための、拡張可能な Rust 製プラットフォームです。

SWC はコンパイル、minify（圧縮）、バンドルなどに利用でき、拡張を前提に設計されています。ビルトインまたはカスタムのコード変換を実行するために呼び出せるコンポーネントであり、それらの変換は Next.js のような、より高レベルなツールを通じて実行されます。

私たちが SWC を採用した理由はいくつかあります。

- **拡張性:** SWC は、ライブラリを fork したり設計上の制約を回避することなく、Next.js 内でクレートとして利用できます。
- **パフォーマンス:** SWC に切り替えることで、Next.js における Fast Refresh を約 3 倍、ビルドを約 5 倍高速化でき、さらに最適化の余地も残されています。
- **WebAssembly:** Rust の WASM サポートは、あらゆるプラットフォームをサポートし、Next.js の開発をどこでも可能にするために不可欠です。
- **コミュニティ:** Rust のコミュニティとエコシステムは素晴らしく、今も成長を続けています。

## サポートされている機能

### Styled Components

`babel-plugin-styled-components` を Next.js コンパイラへ移植する作業を進めています。

まず Next.js を最新バージョンに更新してください: `npm install next@latest`。その後、`next.config.js` ファイルを更新してください。

```js filename="next.config.js"
module.exports = {
  compiler: {
    styledComponents: true,
  },
}
```

高度なユースケースでは、`styled-components` のコンパイル用にプロパティを個別に設定できます。

> **注意:** Next.js で `styled-components` を使用するための主な要件は、`ssr` と `displayName` のトランスフォームです。

```js filename="next.config.js"
module.exports = {
  compiler: {
    // オプションの詳細については https://styled-components.com/docs/tooling#babel-plugin を参照してください。
    styledComponents: {
      // 開発環境ではデフォルトで有効、本番環境ではファイルサイズ削減のため無効。
      // この設定はすべての環境のデフォルトを上書きします。
      displayName?: boolean,
      // デフォルトで有効。
      ssr?: boolean,
      // デフォルトで有効。
      fileName?: boolean,
      // デフォルトは空。
      topLevelImportPaths?: string[],
      // デフォルトは ["index"]。
      meaninglessFileNames?: string[],
      // デフォルトで有効。
      minify?: boolean,
      // デフォルトで有効。
      transpileTemplateLiterals?: boolean,
      // デフォルトは空。
      namespace?: string,
      // デフォルトで無効。
      pure?: boolean,
      // デフォルトで有効。
      cssProp?: boolean,
    },
  },
}
```

### Jest

Next.js Compiler はテストコードをトランスパイルし、Next.js と Jest を併用する際の設定を簡略化します。具体的には次のようなものが含まれます。

- `.css`、`.module.css`（およびそれらの `.scss` の各種バリエーション）と画像インポートの自動モック
- SWC を使った `transform` の自動設定
- `.env`（およびその各種バリエーション）を `process.env` に読み込み
- テスト時のモジュール解決と変換処理の対象から `node_modules` を除外
- テスト時のモジュール解決の対象から `.next` を除外
- 実験的な SWC トランスフォームを有効にするフラグのために `next.config.js` を読み込み

まず、Next.js を最新バージョンにアップデートします（`npm install next@latest`）。次に、`jest.config.js` ファイルを更新します。

```js filename="jest.config.js"
const nextJest = require('next/jest')

// Next.jsアプリへのパスを指定することで、next.config.jsと.envファイルの読み込みが有効になります
const createJestConfig = nextJest({ dir: './' })

// Jestに渡すカスタム設定
const customJestConfig = {
  setupFilesAfterEnv: ['<rootDir>/jest.setup.js'],
}

// next/jestが非同期のNext.js設定を読み込めるよう、createJestConfigはこの形式でエクスポートされます
module.exports = createJestConfig(customJestConfig)
```

### Relay

[Relay](https://relay.dev/) のサポートを有効にするには、次のようにします。

```js filename="next.config.js"
module.exports = {
  compiler: {
    relay: {
      // relay.config.js の設定と一致させる必要があります
      src: './',
      artifactDirectory: './__generated__',
      language: 'typescript',
      eagerEsModules: false,
    },
  },
}
```

> **補足**: Next.js では、`pages` ディレクトリ内のすべての JavaScript ファイルがルートとして扱われます。したがって、`relay-compiler` を使用する場合は、`artifactDirectory` 設定で `pages` ディレクトリの外を指すようにする必要があります。そうしないと、`relay-compiler` はソースファイルと同じ場所にある `__generated__` ディレクトリにファイルを生成し、そのファイルもルートとして扱われてしまい、本番ビルドが失敗します。

### React のプロパティを削除する

JSX のプロパティを削除します。テスト時によく利用されます。`babel-plugin-react-remove-properties` と似ています。

デフォルトの正規表現 `^data-test` にマッチするプロパティを削除するには:

```js filename="next.config.js"
module.exports = {
  compiler: {
    reactRemoveProperties: true,
  },
}
```

カスタムプロパティを削除するには：

```js filename="next.config.js"
module.exports = {
  compiler: {
    // ここで定義された正規表現はRustで処理されるため、構文はJavaScriptの`RegExp`とは異なります。https://docs.rs/regex を参照してください。
    reactRemoveProperties: { properties: ['^data-custom$'] },
  },
}
```

### コンソールの削除

このトランスフォームは、アプリケーションコード内のすべての `console.*` 呼び出し（`node_modules` を除く）を削除します。`babel-plugin-transform-remove-console` と同様です。

すべての `console.*` 呼び出しを削除します:

```js filename="next.config.js"
module.exports = {
  compiler: {
    removeConsole: true,
  },
}
```

`console.error` を除き、`console.*` の出力を削除する:

```js filename="next.config.js"
module.exports = {
  compiler: {
    removeConsole: {
      exclude: ['error'],
    },
  },
}
```

### レガシーデコレーター

Next.js は `jsconfig.json` または `tsconfig.json` 内の `experimentalDecorators` を自動的に検出します。レガシーデコレーターは、`mobx` のようなライブラリの古いバージョンで一般的に使用されています。

このフラグは既存のアプリケーションとの互換性を保つためだけにサポートされています。新規のアプリケーションでレガシーデコレーターを使用することは推奨しません。

まず、Next.js を最新バージョンに更新します: `npm install next@latest`。次に、`jsconfig.json` または `tsconfig.json` ファイルを更新します:

```js
{
  "compilerOptions": {
    "experimentalDecorators": true
  }
}
```

### importSource

Next.js は `jsconfig.json` または `tsconfig.json` 内の `jsxImportSource` を自動的に検出して、その設定を適用します。これは一般的には [Theme UI](https://theme-ui.com) のようなライブラリと組み合わせて使用されます。

まず、Next.js を最新バージョンに更新します: `npm install next@latest`。次に、`jsconfig.json` または `tsconfig.json` ファイルを更新します:

```js
{
  "compilerOptions": {
    "jsxImportSource": "theme-ui"
  }
}
```

### Emotion

`@emotion/babel-plugin` を Next.js Compiler に移植する作業を進めています。

まず、Next.js を最新バージョンにアップデートします：`npm install next@latest`。次に、`next.config.js` ファイルを更新します。

```js filename="next.config.js"

module.exports = {
  compiler: {
    emotion: boolean | {
      // デフォルトはtrueです。ビルドタイプがproductionの場合は無効になります。
      sourceMap?: boolean,
      // デフォルトは'dev-only'です。
      autoLabel?: 'never' | 'dev-only' | 'always',
      // デフォルトは'[local]'です。
      // 使用可能な値: `[local]` `[filename]` `[dirname]`
      // このオプションはautoLabelが'dev-only'または'always'に設定されている場合にのみ機能します。
      // 生成されるラベルのフォーマットを定義できます。
      // フォーマットは文字列で定義し、可変部分は角括弧[]で囲みます。
      // 例: labelFormat: "my-classname--[local]" の場合、[local]は結果が代入される変数名に置き換えられます。
      labelFormat?: string,
      // デフォルトはundefinedです。
      // このオプションでは、コンパイラーが変換対象を判断する際に
      // 参照するインポートを指定できます。Emotionのエクスポートを
      // 再エクスポートしている場合でも、変換を引き続き利用できます。
      importMap?: {
        [packageName: string]: {
          [exportName: string]: {
            canonicalImport?: [string, string],
            styledBaseImport?: [string, string],
          }
        }
      },
    },
  },
}
```

### 圧縮（Minification）

Next.js では v13 以降、デフォルトの圧縮処理に `swc` コンパイラが使用されています。これは Terser と比べて 7 倍高速です。

> **補足:** v15 以降は、`next.config.js` で圧縮処理をカスタマイズすることはできません。`swcMinify` フラグのサポートは削除されました。

### モジュールのトランスパイル

Next.js は、ローカルパッケージ（モノレポなど）や外部パッケージ（`node_modules` 内）を自動的にトランスパイルしてバンドルできます。これは `next-transpile-modules` パッケージの代わりとして機能します。

```js filename="next.config.js"
module.exports = {
  transpilePackages: ['@acme/ui', 'lodash-es'],
}
```

### インポートのモジュール化

このオプションは、Next.js 13.5 で [`optimizePackageImports`](/docs/app/api-reference/config/next-config-js/optimizePackageImports) によって置き換えられました。インポートパスを手動で設定する必要のない新しいオプションを利用するようにアップグレードすることを推奨します。

### Define（ビルド時に変数を置き換える）

`define` オプションを使用すると、ビルド時にコード内の変数を静的に置き換えることができます。
このオプションにはキーと値のペアからなるオブジェクトを指定し、キーには置き換える対象となる変数名を、値には対応する置き換え後の値を指定します。

すべての環境（server、edge、client）で使用する変数を定義するには、`next.config.js` の `compiler.define` フィールドを使用します。また、サーバー側（server と edge）のコードでのみ使用する変数を定義するには、`compiler.defineServer` を使用します。

```js filename="next.config.js"
module.exports = {
  compiler: {
    define: {
      MY_VARIABLE: 'my-string',
      'process.env.MY_ENV_VAR': 'my-env-var',
    },
    defineServer: {
      MY_SERVER_VARIABLE: 'my-server-var',
    },
  },
}
```

### ビルドライフサイクルフック

Next.js Compiler は、ビルドプロセス中の特定のタイミングでカスタムコードを実行できるライフサイクルフックをサポートしています。現在サポートされているフックは次のとおりです。

#### runAfterProductionCompile

本番ビルドのコンパイルが完了した後、型チェックや静的ページ生成などのコンパイル後処理を実行する前に呼び出されるフック関数です。このフックでは、プロジェクトディレクトリやビルド出力ディレクトリなどのプロジェクトメタデータにアクセスできるため、サードパーティツールがソースマップなどのビルド成果物を収集する用途に便利です。

```js filename="next.config.js"
module.exports = {
  compiler: {
    runAfterProductionCompile: async ({ distDir, projectDir }) => {
      // カスタムコードをここに記述
    },
  },
}
```

このフックは次のプロパティを持つオブジェクトを受け取ります:

- `distDir`: ビルド出力ディレクトリ（デフォルトは `.next`）
- `projectDir`: プロジェクトのルートディレクトリ

## 実験的機能

### SWC トレースプロファイリング

SWC の内部変換処理のトレースを、Chromium の [trace event format](https://docs.google.com/document/d/1CvAClvFfyA5R-PhYUmn5OOQtYMH4h6I0nSsKchNAySU/preview?mode=html#%21=) 形式で出力できます。

```js filename="next.config.js"
module.exports = {
  experimental: {
    swcTraceProfiling: true,
  },
}
```

有効化すると、swc は `.next/` 配下に `swc-trace-profile-${timestamp}.json` という名前のトレースファイルを生成します。Chromium のトレースビューア（chrome://tracing/, https://ui.perfetto.dev/）や、互換性のあるフレームグラフビューア（https://www.speedscope.app/）で生成されたトレースを読み込んで可視化できます。

### SWC プラグイン（実験的）

`swc` の transform を設定して、wasm で実装された SWC の実験的なプラグインサポートを利用し、変換処理の挙動をカスタマイズできます。

```js filename="next.config.js"
module.exports = {
  experimental: {
    swcPlugins: [
      [
        'plugin',
        {
          ...pluginOptions,
        },
      ],
    ],
  },
}
```

`swcPlugins` は、プラグインを構成するためのタプルの配列を受け取ります。各プラグイン用のタプルには、プラグインへのパスと、プラグイン構成用のオブジェクトが含まれます。プラグインへのパスには、npm モジュールのパッケージ名、または `.wasm` バイナリ自体への絶対パスを指定できます。

## 未対応の機能

アプリケーションに `.babelrc` ファイルがある場合、Next.js は個々のファイルの変換には自動的に Babel を使用するようフォールバックします。これにより、カスタム Babel プラグインを利用している既存アプリケーションとの後方互換性が確保されます。

独自の Babel 設定を使用している場合は、[その設定を共有してください](https://github.com/vercel/next.js/discussions/30174)。よく使われている Babel の変換にできるだけ多く対応できるよう作業を進めており、将来的にはプラグインのサポートも行う予定です。
